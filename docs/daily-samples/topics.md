## 选题一：新模型发布后，你的旧评测还够用吗？

- 开场切入：新模型已经能调用了，你的迁移依据却可能还是旧榜单。
- 核心观点：模型换代值得重新比较，但发布方成绩不能代替自己工作流中的验证。
- 讲述提纲：发布了什么 → 哪些使用条件发生变化 → 挑选代表任务 → 记录质量、耗时和成本 → 决定是否迁移。
- 证据入口：对应新闻、官方模型文档、独立评测；正式选题必须补真实链接。
- 边界：不预设新模型一定更好，不把“可用”说成“适合所有任务”。

## 选题二：Agent 的上下文满了，为什么不能只删日志？

- 开场切入：日志删掉后，Agent 可能连自己失败在哪里都找不到。
- 核心观点：减少输入量的同时，要保留恢复原始证据的能力。
- 讲述提纲：大输出如何进入上下文 → 截断的风险 → 外部保存与按需读取 → 新增的检索成本 → 哪些任务值得用。
- 证据入口：对应工具深挖、关键实现；正式选题补真实链接。
- 边界：不声称节省特定比例的 token；没有实验就不说效果已验证。

## 选题三：测试全绿，为什么还不能说明 Agent 做对了？

- 开场切入：如果测试也来自对需求的错误理解，全部通过可能只说明它们彼此一致。
- 核心观点：验收约定要从用户目标出发，并尽量独立于实现。
- 讲述提纲：错误理解怎样传给测试 → 先定义真实操作 → 加入失败场景 → 保留可复查证据 → 说明覆盖边界。
- 证据入口：对应方法篇、原始博客及案例；正式选题补真实链接。
- 边界：独立验收减少盲区，但不是可靠性的无限保证。
