本期深挖一个虚构的上下文管理项目。它面向反复读取长日志、检索结果和构建输出的编程 Agent，核心思路是把原始结果留在外部存储，让模型先看到索引或摘要。

## 它解决的问题

Agent 执行一次搜索可能返回大量内容，但下一步真正需要的只是少数片段。如果全部进入对话，会占用后续推理所需的上下文。ContextShelf 将“保存原始结果”和“把哪些内容交给模型”拆开处理。

## 怎么工作

假设其实现分三步：工具结果先写入文件；返回带位置的简短索引；模型根据索引调用读取接口取回片段。正式深挖必须检查这三个步骤对应的关键实现，并解释摘要失败、文件清理或会话重启时会怎样，不能只复述 README。

## 与常见做法的差异

| 方式 | 主要收益 | 主要代价 |
|---|---|---|
| 直接截断工具输出 | 简单、快速 | 被截掉的关键内容可能无法找回 |
| 只保留摘要 | 降低后续输入量 | 摘要遗漏会影响后续判断 |
| 保存原文、按需读取 | 可以回到原始证据 | 增加文件管理、检索和额外调用 |

这里比较的是方法差异，不代表虚构项目已证明更快或更省钱。

## 适合谁，怎么开始

适合经常处理大输出且需要追溯原文的 Agent 工作流。只有短问答、上下文本就很小的任务，未必值得增加这层复杂度。
