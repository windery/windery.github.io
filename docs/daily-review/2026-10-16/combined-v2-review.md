## 本轮范围

用户要求整合「梳理日报现状供 Review」与「AI 日报文案风格研究与三个改写版本」两个会话的意见，生成包含新闻、工具、方法、口播四篇的新文章。本轮只新增 combined-v2.md 与本记录，不覆盖恢复版，不改 skill、发布器、定时任务或已讲记录，不发布、不发消息。

合订用于一次审阅，不改变此前四篇各自独立分发的决定。沿用恢复版的选题及证据；第二个会话提供写作意见，不将其六条素材直接拼入本期。

## 采用的意见

- 第一个会话：四篇用途不同；主体明确；新闻要点可扫读；工具解释具体实现；方法围绕真实作者案例；口播保留选题卡。日期来源简写，采集、核查及试写说明移出正文。
- 第二个会话：用户选择阮一峰参考方向，优先把事情讲清楚。标题写出主体与事件，导语先交代事实；费用与对象放在相关位置。删去重复劝告、通用金句及未经支持的行业拔高；区分正式开放与首次新增能力。
- 不恢复被撤回轮次的固定三点结构；新闻三条源于现有三个事件，其他篇依内容组织。没有把参考方向写成对某位作者措辞的模仿。

## 自审与修正

| 检查 | 处理 |
|---|---|
| 标题和开头 | 新闻分别写明 GitHub、功能及正式开放事件；工具首段说明是自部署推理引擎；方法首段说明作者、功能和完整两阶段过程 |
| 新闻层次 | 用短要点提供入口，正文拆成三个事件；压缩完整语言清单和页面位置，保留付费对象与关键限制 |
| 新旧变化 | 只写正式开放及公告描述的流程，没有声称复扫或验证记录首次出现 |

| 工具具体性 | 保留状态、缓存引用、执行计划三个代码依据；去掉 API 星标快照和详细 CUDA 版本清单，安装细节链接到文档 |
| 方法具体性 | 保留日期归档改口、两类搜索规则、Git 子进程改 API、私有数据配置；四步归纳明确来自案例 |
| 口播可用性 | 每张卡有明确开场、观点、提纲及画面证据；去掉“成稿不能”等编辑任务 |
| 边界 | AI Scan 不能阻止合并、自动修复默认分支范围、METR 访问和发表边界、工具未测性能均保留；未重复通用免责声明 |
| 热榜 | 沿用恢复版同一份十项快照及计数，不混入 API 数字，不声称实时更新或首次上榜 |
