代码阅读考核

不看运行结果也能解释为什么，才算形成自己的阅读能力。

五步阅读法

  1. 用一句话翻译函数签名。
  2. 圈出 return、?、panic 与不匹配分支。
  3. 画出拥有者到借用者的对应关系。
  4. 为每个链式调用写出输入、Item 与输出类型。
  5. 用正常、空、无效三类输入解释行为。

闭卷小考

每题 2 分：结论 1 分，能用规则解释 1 分。先在纸上写答案，再展开。这里的 10 分只衡量这些题，不是对全部 Rust 能力的认证。

01 · 借用冲突

let mut s = String::from("x");
let r = &s;
s.push('!');
println!("{r}");

能否编译？如何保持“先读后改”的需求？

核对解释

不能，共享引用 r 在 push 后仍要使用；把读取放到修改之前。若需求是保留旧文本副本，则应显式 clone，并说明成本。

02 · 返回关系

fn prefix<'a>(text: &'a str, limit: usize) -> &'a str {
    text.get(..limit).unwrap_or(text)
}

输入“你好”，limit=1 和 limit=3 各返回什么？是否新建 String？

核对解释

limit=1 不在 UTF-8 边界，get 为 None，返回完整原文；limit=3 返回“你”。两者都是借用。这个 API 的边界策略是“失败退回原文”，不一定符合每个业务。

03 · 嵌套错误

let parsed: Result<Vec<u32>, _> = ["2", "x", "4"]
    .into_iter().map(str::parse::<u32>).collect();

得到部分成功还是整体失败？如何故意只保留可解析项？

核对解释

得到 Err，失败后停止收集。可用 filter_map(|s| s.parse::<u32>().ok()).collect::<Vec<_>>() 得到 [2, 4]，但会丢弃错误原因，必须是有意策略。

04 · trait 对象

fn build(flag: bool) -> impl std::fmt::Display {
    if flag { 7_u32 } else { String::from("seven") }
}

能否编译？给出保持两种表示的方案。

核对解释

不能：返回 impl Trait 仍需统一具体类型。可返回统一的 String，或一个实现 Display 的枚举，或 Box<dyn Display>；选择应符合接口需求。

05 · 异步执行

async fn fetch() -> Result<u32, &'static str> { Ok(3) }
async fn run() -> Result<u32, &'static str> {
    let n = fetch().await?;
    Ok(n * 2)
}

调用 run() 就得到 6 吗？驱动完成时的 Output 是什么？

核对解释

调用仅得到 future。驱动它完成得到 Ok(6)，类型是 Result<u32, &'static str>。await 与 ? 分别处理异步完成和错误传播。

根据表现安排下一步

表现回补路径
0–4 分重读所有权、借用、Option/Result 与表达式课，再换一组数据解释。
5–8 分找出说不出理由的题，对应复习生命周期、迭代器或 trait 对象。
9–10 分隔一天换题复述，再阅读 examples/rust-reading/src/lib.rs，解释每项测试覆盖的行为。

记录答案与理由，依据解释是否准确选择下一阶段；阅读标记不等于已经掌握。
