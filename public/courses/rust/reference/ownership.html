所有权与签名速查

用三问替代猜测：谁拥有？这次调用取得什么权限？返回值借自哪里？

签名或类型读取结论需要注意
fn f(x: String)按值取得 String 的所有权。调用方不能再用原绑定。
fn f(x: &str)共享借用文本。可接受 String 借用或字面量。
fn f(x: &mut String)独占借用，可能修改原值。借用有效时避免冲突访问。
fn f(&self) / fn f(self)共享借用 / 按值接收自己。self 为 Copy 类型时按值可复制。
fn f<'a>(x: &'a str) -> &'a str输出借自输入，不能比来源更久。标注不会分配或复制文本。
impl Iterator<Item = &T>产生借用，来源须仍有效。看返回类型生命周期与捕获。
iter / iter_mut / into_iter常见为借用 / 独占借用 / 消费。into_iter 用在引用上时仍可能产出引用，要看接收者类型。
Box<T>独占拥有。移动句柄不等于克隆 T。
Rc<T> / Arc<T>单线程 / 原子计数共享拥有。Arc 不自动使内部 T 可任意并发修改。
RefCell<T>运行时借用检查。冲突可 panic，try_borrow 可返回错误。
Mutex<T>锁控制互斥访问。guard 销毁解锁；仍可能死锁。
Weak<T>不维持 T 存活。upgrade 必须处理 None。
Pin<Box<T>>拥有指针，约束所指值移动。Unpin 与投影规则需单独核对。

做一次调用前，按顺序检查

  1. 参数是值还是引用？值是否 Copy？
  2. 调用后原绑定是否还能使用？方法有没有消耗 self？
  3. 返回的是拥有值还是借用？借用来自哪个输入？
  4. 闭包捕获了什么？捕获与每次调用时的移动是否不同？
  5. 内部可变性、线程与 async 有没有增加运行时义务？

遇到编译错误先标记引用最后使用点；需要复制时明确说明为何必须有独立副本。参见第 06–08、17、22–25 节。
