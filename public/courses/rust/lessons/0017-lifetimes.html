生命周期：返回的引用借自哪里

把生命周期签名读成引用之间的约束。

理解类型之间的约束建议 8–15 分钟

先建立一个判断方法

生命周期标注不延长对象寿命，也不安排释放动作。它说明输入输出引用之间的关系，让编译器验证实际调用是否安全。阅读时优先问“返回引用来自哪份仍然存在的数据”。

fn head(text: &str) -> &str 中只有一个输入引用，省略规则通常能把输出关联到它。多个输入引用时可能需要显式标注。相同的 'a 表示共同满足某个有效区间，不表示两个原始对象必须同时创建或同时销毁。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l17.rs / Rust 2024
fn longer<'a>(left: &'a str, right: &'a str) -> &'a str {
    if left.len() >= right.len() {
        left
    } else {
        right
    }
}
fn main() {
    let left = String::from("rust");
    let right = String::from("go");
    let result = longer(&left, &right);
    println!("{result}");
}

  1. 结果可能来自任意输入，因此使用它时必须满足签名给出的共同借用约束。
  2. 本例按 UTF-8 字节数比较长度；这是业务选择，不是生命周期规则的一部分。

常见误读加上 'static 不能修复返回局部字符串引用的问题。&'static str 常见于字符串字面量，但 T: 'static 的含义不同，后面专讲。

检查你的判断

生命周期标注会延长局部变量的实际寿命吗？

查看完整判断依据

不会延长。它是编译期关系描述，不是延长存活时间的指令。

合上解释，自己说一遍

若 right 在一个更小的块内创建，而 result 在块外打印，为什么即使 left 更长也可能被拒绝？

完成后查看参考解析

调用者依据函数签名检查：输出可能借自 right。不能用“这次数据恰好选 left”替代签名保证。应调整作用域、返回拥有的 String，或重新设计只关联一个输入的签名。
