先建立一个判断方法

模式不仅出现在 match，也出现在 let、函数参数和 for 中。{ field, .. } 忽略其他字段；a | b 是多个候选模式；n @ 1..=9 同时检查范围并把匹配到的值绑定为 n。

分支的 if 是守卫，模式匹配成功后才判断它。对引用匹配时，匹配人体工学可能自动按引用绑定字段；不要见到普通变量名就断定发生移动。在 Rust 2024 下，一些显式 ref/mut 与隐式借用混写受到更严格限制。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l28.rs / Rust 2024
struct User {
    name: String,
    score: u32,
}
fn main() {
    let user = User {
        name: String::from("Lin"),
        score: 7,
    };
    match &user {
        User {
            name,
            score: n @ 1..=9,
        } if name.len() > 2 => {
            println!("{name} {n}");
        }
        _ => println!("other"),
    }
    println!("{}", user.name);
}
展开预期输出与阅读解析
Lin 7
Lin
  1. match &user 借用结构体；name 与 n 在该模式下是字段的引用。
  2. n @ 1..=9 同时检查分数并绑定；守卫进一步检查名字字节数。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l28。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读模式中的 Some(x) 创建或绑定 x，不是“和外围变量 x 的旧值比较”。要比较旧值，可使用不同名字和守卫。

检查你的判断

本例匹配后 user.name 还能使用吗？

查看完整判断依据

还能使用。匹配对象是 &user，字段通过引用访问，String 没有移走。

合上解释，自己说一遍

如果改为 match user 并按值绑定 name，随后再打印 user.name 会怎样？

完成后查看参考解析

name 是非 Copy 的 String，按值模式会移动字段，随后再用该字段会编译失败。其他未移走且可独立访问的字段可能仍可用，这叫部分移动。
