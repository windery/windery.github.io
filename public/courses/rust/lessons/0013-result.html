Result 与 ?：找出隐藏的提前返回

逐条展开成功路径和失败路径。

描述数据与失败建议 8–15 分钟

先建立一个判断方法

Result<T, E> 的两个变体是 Ok(T) 与 Err(E)，表达可恢复的成功或失败。它不是异常自动跳转机制：错误作为值流动，调用者必须决定如何处理。

在返回 Result 的函数中，expr? 在 Ok 时取出里面的值，在 Err 时提前返回，并在必要时通过相应转换把错误变成函数的错误类型。Option 函数中也可对 Option 使用 ?，遇到 None 提前返回 None；两者不能任意混用。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l13.rs / Rust 2024
fn parse_port(text: &str) -> Result<u16, std::num::ParseIntError> {
    let value = text.parse::<u16>()?;
    Ok(value)
}
fn main() {
    println!("{:?}", parse_port("8080"));
    println!("{}", parse_port("oops").is_err());
}
展开预期输出与阅读解析
Ok(8080)
true
  1. ::<u16> 显式指定泛型类型；parse 返回 Result。
  2. ? 使 value 成功时为 u16；失败时根本不会执行 Ok(value)。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l13。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读不能在返回 () 的普通 main 中随便使用 ?。可以让 main 返回合适的 Result，或显式处理错误。unwrap/expect 遇到 Err 会 panic。

完成后查看参考解析

let value = match text.parse::<u16>() { Ok(v) => v, Err(e) => return Err(e) };。Option 可用 ok_or(error) 或 ok_or_else(|| error) 提供缺失时的错误。
