闭包：捕获什么，能调用几次

分开判断捕获方式与 Fn 系列约束。

识别日常代码习惯建议 8–15 分钟

先建立一个判断方法

|x| x + 1 是闭包，能捕获外部环境。编译器按使用方式选择共享借用、独占借用或移动捕获；move 强制按值捕获所需变量，但不代表每次调用都把捕获值移出。

FnOnce 表示可按值调用，FnMut 进一步允许重复调用并修改捕获状态，Fn 进一步允许通过共享引用调用。Fn 实现也满足 FnMut 和 FnOnce；只实现 FnOnce 的闭包可能把捕获的非 Copy 值移出。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l19.rs / Rust 2024
fn main() {
    let prefix = String::from("Hi");
    let greet = move |name: &str| format!("{prefix}, {name}");
    println!("{}", greet("Lin"));
    println!("{}", greet("Mei"));
}
展开预期输出与阅读解析
Hi, Lin
Hi, Mei
  1. prefix 被移入闭包，调用方不能再用原绑定。
  2. format! 在每次调用中只读取 prefix，没有把它移出，因此闭包可重复调用。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l19。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读不要把 move 闭包一律理解成“只能调用一次”。看闭包体是否消费捕获值，才知道它满足哪些 Fn trait。

检查你的判断

这个 move 闭包能调用两次吗？

查看完整判断依据

可以两次。捕获时移动和调用时移出是不同动作；此处没有移出 prefix。

合上解释，自己说一遍

对比 move || prefix 与 move || prefix.len()：哪个会把 String 移出闭包？

完成后查看参考解析

前者返回 String，消费捕获值，因此只能按 FnOnce 调用；后者只是读取长度，即使 move 捕获，仍可满足 Fn。
