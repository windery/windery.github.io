examples/l35.rs / Rust 2024
#[derive(Debug, PartialEq)]
struct Rule<'a> {
    name: &'a str,
    limit: u32,
}
fn parse_rule(line: &str) -> Result<Rule<'_>, &'static str> {
    let (name, raw) = line.split_once('=').ok_or("missing =")?;
    let name = name.trim();
    if name.is_empty() {
        return Err("empty name");
    }
    let limit = raw.trim().parse::<u32>().map_err(|_| "bad limit")?;
    Ok(Rule { name, limit })
}
fn main() {
    let input = String::from(
        "alpha=2
beta=5",
    );
    let rules: Result<Vec<_>, _> = input.lines().map(parse_rule).collect();
    match rules {
        Ok(items) => println!(
            "{} {}",
            items[0].name,
            items.iter().map(|r| r.limit).sum::<u32>()
        ),
        Err(error) => println!("{error}"),
    }
}
展开预期输出与阅读解析
alpha 7
  1. split_once 返回 Option<(&str, &str)>；ok_or 把“没有等号”转成 Err。
  2. trim 返回借用，Rule 中的 name 没有复制文本，借用关系由 Rule<'_> 表达。
  3. map_err 改错误类型；collect 把多个 Result 汇总为一个 Result<Vec<Rule>, _>。
  4. sum 是整数求和；本例数值很小，不承诺任意输入都不溢出。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l35。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读不要把错误消息的 &'static str 与 name 的借用寿命混淆：消息是字面量，name 指向动态输入。删掉输入后继续使用 name 不合法。

查看完整判断依据

整体失败。collect 成 Result 会在错误处整体返回 Err，不会返回部分成功列表。

合上解释，自己说一遍

独立解释六项：空名称；无等号；负数；多余等号；输入销毁；中间有空行。完成后打开阅读考核速查页，再运行项目测试验证。

完成后查看参考解析

空名称报 empty name；无等号报 missing =；负数不能解析为 u32；多余等号保留在 raw 中导致 bad limit；借用存续期间不能销毁 input；中间空行没有等号，整体失败。结尾单个换行不额外产生空行。
