切片：借用一段连续数据

理解 String、&str、Vec<T> 与 &[T] 的对应关系。

追踪拥有与借用建议 8–15 分钟

先建立一个判断方法

切片 [T] 是一段连续元素的视图，常通过 &[T] 使用；引用携带数据位置和长度。Vec<T> 拥有可增长的元素序列，&[T] 借用其中一段。类似地，String 拥有 UTF-8 文本，&str 借用文本。

借用参数尽量读作“需要怎样的数据视图”。接收 &str 的函数通常既能读字符串字面量，也能读 String 的借用；接收 &[i32] 的函数通常既能读数组也能读 Vec。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l08.rs / Rust 2024
fn first_two(values: &[i32]) -> &[i32] {
    &values[..values.len().min(2)]
}
fn main() {
    let values = vec![10, 20, 30];
    let part = first_two(&values);
    println!("{:?}", part);
}
展开预期输出与阅读解析
[10, 20]
  1. ..end 范围不包含 end；len().min(2) 让空集合和短集合也安全。
  2. 返回的切片借自输入，没有新建 Vec；values 必须在 part 使用期间有效。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l08。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读&values[..] 不是深拷贝。如果需要独立拥有数据，可对切片使用 to_vec；这要求元素能够 Clone。

检查你的判断

first_two 返回值拥有独立的元素缓冲区吗？

查看完整判断依据

借用原值。返回的是 &[i32]，只是对原数据一段的借用。

合上解释，自己说一遍

为什么 fn wrong() -> &str { let s = String::from("x"); &s } 不成立？

完成后查看参考解析

s 在函数返回时销毁，返回的引用会悬垂。可以返回 String，把所有权交给调用者；添加生命周期标注不能使局部字符串活得更久。
