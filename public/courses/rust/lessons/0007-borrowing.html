借用：&T 与 &mut T

读出一个函数是在读取、修改还是接管数据。

追踪拥有与借用建议 8–15 分钟

先建立一个判断方法

&T 是共享引用，&mut T 是独占引用。普通借用规则是：同一数据的相关借用有效期间，允许多个共享引用，或一个独占引用。引用必须始终指向有效数据。

借用的有效区间常由最后一次使用决定，并不总要等到右花括号才结束。读取编译器错误时，把“引用在哪里创建”和“最后在哪里使用”连起来看。内部可变性是受控的另一套机制，后面单独讲。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l07.rs / Rust 2024
fn append_mark(text: &mut String) {
    text.push('!');
}
fn main() {
    let mut name = String::from("Rust");
    let view = &name;
    println!("{view}");
    append_mark(&mut name);
    println!("{name}");
}

  1. view 最后一次使用在第一条 println!，之后可以独占借用 name。
  2. append_mark 持有 &mut String，能修改原字符串，但没有接管它的所有权。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l07。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读如果把 println!("{view}") 移到 append_mark 之后，共享借用和独占借用的需求会冲突。mut name 与 &mut name 分别是绑定声明和借用表达式。

合上解释，自己说一遍

比较 fn a(s: String)、fn b(s: &str)、fn c(s: &mut String)：谁接管，谁只读，谁能原地修改？

完成后查看参考解析

a 按值接管 String；b 共享借用文本；c 独占借用并可修改 String。&str 并不限定只能来自 String，也可以来自字符串字面量。
