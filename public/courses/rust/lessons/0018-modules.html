mod、use、pub 与路径

从导入路径追到真正的定义。

理解类型之间的约束建议 8–15 分钟

先建立一个判断方法

mod 建立模块，use 为路径引入作用域内的名字；use 本身不下载包，也不是执行别的文件。crate:: 从当前 crate 根开始，self:: 从当前模块开始，super:: 指向父模块。

项默认私有；pub 暴露项，但路径上的父模块可见性也要考虑。pub(crate) 只在当前 crate 可见。公开 struct 不代表字段全部公开，而公开 enum 的变体按枚举可见性使用。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l18.rs / Rust 2024
mod model {
    pub struct User {
        name: String,
    }
    impl User {
        pub fn new(name: &str) -> Self {
            Self {
                name: name.to_owned(),
            }
        }
        pub fn name(&self) -> &str {
            &self.name
        }
    }
}
use crate::model::User;
fn main() {
    println!("{}", User::new("Lin").name());
}
展开预期输出与阅读解析
Lin
  1. main 可使用 User 的公开方法，但不能直接读取其私有字段 name。
  2. mod model { ... } 可以拆为 mod model; 和对应模块文件；模块树才是理解路径的关键。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l18。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读文件夹层次不自动等于所有可用模块。阅读 mod 声明和重导出 pub use，才能找到库提供的实际公开接口。

检查你的判断

本例 main 能直接读取 user.name 字段吗？

查看完整判断依据

无法读取。User 公开，但 name 字段没有 pub，主模块不能直接访问它。

合上解释，自己说一遍

看到 use library::Client 与 pub use internal::Client 时，分别如何追踪？

完成后查看参考解析

前者把外部 crate 的 Client 引入当前作用域；后者把内部路径的 Client 重新公开。先查看 Cargo.toml 依赖，再沿库的 lib.rs 与 pub use 找实现。
