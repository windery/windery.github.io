Box、Deref 与 Drop：读资源的拥有关系

分清堆分配、借用转换和资源清理。

识别日常代码习惯建议 8–15 分钟

先建立一个判断方法

Box<T> 通常独占拥有堆上的 T；移动 Box 转移拥有权，而不是克隆 T。递归类型常用 Box 把无限展开的结构变成已知大小的指针。

Deref 让一些指针类型可通过 * 访问目标，并参与解引用强制转换，例如 &String 到 &str。Drop 定义资源释放时的逻辑；离开作用域通常会自动清理，也可以用 std::mem::drop 提前消耗一个值。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l22.rs / Rust 2024
struct Notice;
impl Drop for Notice {
    fn drop(&mut self) {
        println!("released");
    }
}
fn main() {
    let boxed = Box::new(7);
    println!("{}", *boxed);
    let notice = Notice;
    drop(notice);
    println!("after");
}
展开预期输出与阅读解析
7
released
after
  1. *boxed 读到 i32 值；Box 的拥有关系和内部数值是两层。
  2. drop(notice) 移动并销毁 notice，因此 released 出现在 after 前。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l22。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读不能直接调用对象的 Drop::drop 方法来手动重复释放；使用 std::mem::drop。Rust 也允许某些内存泄漏，内存安全不等于绝不泄漏。

为什么 enum List { Node(i32, List), End } 大小无法确定，而 Box<List> 可以解决？

完成后查看参考解析

直接嵌入 List 会要求类型大小包含自身，无法得到有限布局。Box<List> 作为间接指针大小可确定，下一节点放在单独分配中。
