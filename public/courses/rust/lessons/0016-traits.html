trait 与 where：读能力约束

读懂定义行为、实现行为和要求行为的三个位置。

理解类型之间的约束建议 8–15 分钟

先建立一个判断方法

trait 定义某种行为契约；impl Trait for Type 为具体类型实现契约。impl Type 则定义类型自身的关联项，二者不要混淆。trait 可以有默认方法，实现者可以复用或覆盖。

T: Trait 是类型约束，where T: A + B 可以把多个要求移到签名后。+ 表示同时满足。泛型函数的实现只能依赖约束中保证的能力。需要某个 trait 的方法时，有时要 use 该 trait 让方法参与查找。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l16.rs / Rust 2024
trait Named {
    fn name(&self) -> &str;
}
struct User {
    name: String,
}
impl Named for User {
    fn name(&self) -> &str {
        &self.name
    }
}
fn show<T>(value: &T)
where
    T: Named,
{
    println!("{}", value.name());
}
fn main() {
    show(&User {
        name: String::from("Lin"),
    });
}
展开预期输出与阅读解析
Lin
  1. Named 是契约，User 是具体实现，show 是只依赖契约的使用方。
  2. &self 到 &str 的返回引用借自对象；没有克隆 name。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l16。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读Rust trait 不是类继承。通常不能给外部类型实现外部 trait；孤儿规则及其细节限制这种实现，常用本地 newtype 解决。

检查你的判断

where T: Named + Clone 的 + 表示什么？

查看完整判断依据

同时满足。T 必须同时实现 Named 与 Clone。

合上解释，自己说一遍

比较 impl User 与 impl Named for User。为什么调用者看 show 的签名就能知道它要求 name 能力？

完成后查看参考解析

前者定义 User 自身的关联项，后者实现 Named 契约。show 的 where 明确要求 T: Named，因此实现中可以使用 name 方法。
