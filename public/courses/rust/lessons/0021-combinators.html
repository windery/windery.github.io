map、and_then、collect：看清容器层数

区分变换内部值与串接可能失败的步骤。

识别日常代码习惯建议 8–15 分钟

先建立一个判断方法

Option::map 把 Some 内的值变换后重新包成 Some；and_then 要求闭包直接返回 Option，用来串接可能缺失的步骤，避免嵌套 Option<Option<T>>。Result 有对应组合器，map_err 用于转换错误。

迭代器中的 Result 可以 collect 成 Result<Vec<T>, E>：成功时收集所有 T，遇到第一个 Err 就返回失败。filter_map(|x| x.parse().ok()) 则会静默跳过无效项，两者是不同业务策略。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l21.rs / Rust 2024
fn main() {
    let nested = Some("12").map(|s| s.parse::<u32>().ok());
    let flat = Some("12").and_then(|s| s.parse::<u32>().ok());
    let values: Result<Vec<u32>, _> = ["1", "bad", "3"]
        .into_iter()
        .map(str::parse::<u32>)
        .collect();
    println!("{:?} {:?} {}", nested, flat, values.is_err());
}
展开预期输出与阅读解析
Some(Some(12)) Some(12) true
  1. nested 有两层 Option，因为 map 的闭包本身返回 Option。
  2. flat 只有一层 Option；Result 收集因 bad 解析失败而整体失败。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l21。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读.ok() 把 Err 变成 None，会丢掉错误原因。读业务代码时要确认这是有意忽略，还是错误被不小心吞掉。
