字符串：字节、字符与切片边界

避免把 Rust 的字符串索引当成字符索引。

追踪拥有与借用建议 8–15 分钟

先建立一个判断方法

String 与 str 都保证有效 UTF-8。len() 返回字节数，chars() 遍历 Unicode 标量值，bytes() 遍历字节。这三个视角不能混用；组合字符或 emoji 还可能由多个标量值组成。

Rust 不支持 s[0] 这种字符串整数索引。范围切片必须落在合法 UTF-8 边界；不确定边界时可使用 get(range)，它返回 Option，避免越界或截断编码带来的 panic。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l09.rs / Rust 2024
fn main() {
    let text = String::from("你好");
    println!("{} {}", text.len(), text.chars().count());
    println!("{:?}", text.get(0..3));
    println!("{:?}", text.get(0..1));
}
展开预期输出与阅读解析
6 2
Some("你")
None
  1. 每个汉字在此占 3 个 UTF-8 字节，所以 len 为 6。
  2. 0..3 正好包含“你”；0..1 落在编码内部，get 返回 None。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l09。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读chars().count() 也不保证等于屏幕上看到的“字符个数”；字形簇需要额外的 Unicode 分词规则。

查看完整判断依据

六个字节。len 按字节计数，不按汉字数量计数。

合上解释，自己说一遍

比较 text.get(0..1) 与 &text[0..1] 在这个例子中的表现。

完成后查看参考解析

前者返回 None；后者在运行时 panic，因为 1 不是 UTF-8 字符边界。注意这并不是编译失败。
