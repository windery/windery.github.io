先建立一个判断方法

测试不仅验证实现，也帮助读者找输入输出示例。#[test] 的函数由 cargo test 执行；assert_eq! 检查相等。单元测试常放在 #[cfg(test)] mod tests，集成测试通常位于 tests/，以外部使用者方式调用库。

/// 是文档注释，代码块可成为文档测试。#[cfg(feature = "x")] 在构建时选择代码；Cargo feature 常被合并启用，并非天然互斥的运行时选项。阅读条件分支要同时看 Cargo.toml、目标平台与构建命令。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l31.rs / Rust 2024
fn clamp_small(n: i32) -> i32 {
    n.clamp(0, 10)
}
#[cfg(test)]
mod tests {
    use super::*;
    #[test]
    fn clamps_both_ends() {
        assert_eq!(clamp_small(-1), 0);
        assert_eq!(clamp_small(11), 10);
        assert_eq!(clamp_small(4), 4);
    }
}
fn main() {
    println!("{}", clamp_small(11));
}

  1. 普通 cargo run 不编译 tests 模块；本例测试使用 cargo test --example l31。
  2. 读测试要检查边界与失败路径，不能只看到“有测试”就认为行为已全覆盖。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l31。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。
