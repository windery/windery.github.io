enum 与 Option：把情况写进类型

识别“某种情况携带某份数据”的模型。

描述数据与失败建议 8–15 分钟

先建立一个判断方法

枚举值一次只能属于一个变体，每个变体可以携带不同数据。它不是只有几个整数常量的枚举；例如连接状态可以是 Offline 或 Online { users: usize }。

Option<T> 是标准库枚举，有 Some(T) 和 None。Option<String> 是“可能拥有字符串”，Option<&str> 是“可能借用字符串”。T 与 Option<T> 不是同一个类型，不能直接混着用。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l11.rs / Rust 2024
enum Status {
    Offline,
    Online { users: usize },
}
fn user_count(status: Status) -> Option<usize> {
    match status {
        Status::Offline => None,
        Status::Online { users } => Some(users),
    }
}
fn main() {
    println!("{:?}", user_count(Status::Online { users: 3 }));
    println!("{:?}", user_count(Status::Offline));
}
展开预期输出与阅读解析
Some(3)
None
  1. match 拆出 Online 变体中的 users。
  2. None 表示此模型下没有计数；Some(0) 则表示在线但用户数为零，含义不同。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l11。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读对 None 调用 unwrap 会 panic。默认值必须符合业务含义，不能为了少写 match 就把“未知”混同于 0。
