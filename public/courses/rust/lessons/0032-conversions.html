转换、newtype 与类型别名

区分无损转换、可能失败转换和新类型边界。

回到真实代码建议 8–15 分钟

先建立一个判断方法

From/Into 表达无失败转换；TryFrom/TryInto 返回 Result，适合可能超界的转换。as 是语言转换操作，不等于“总能安全保留原值”；例如大整数窄化可能截断。

struct UserId(u64) 创建新类型，能阻止与普通 u64 或其他 ID 混用。type UserId = u64 只是别名，不创建新边界。AsRef<T> 提供借用视图，不能与消费值的 Into<T> 混为一谈。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l32.rs / Rust 2024
struct UserId(u64);
fn show(id: UserId) {
    println!("{}", id.0);
}
fn main() {
    let large = 300_u16;
    println!("{} {}", large as u8, u8::try_from(large).is_err());
    show(UserId(7));
}
展开预期输出与阅读解析
44 true
7
  1. 300 as u8 只保留低 8 位，得到 44；try_from 明确报告失败。
  2. show 接受 UserId，不能直接传裸整数 7，需要显式构造。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l32。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读Clone、Copy、From、AsRef 都涉及“得到另一个东西”，但拥有关系和成本不同；阅读时先分类，不要统称为复制。

检查你的判断

type UserId = u64 能阻止把普通 u64 当作 UserId 吗？

查看完整判断依据

不能阻止。类型别名仍是同一个类型；newtype 才创建独立类型。

合上解释，自己说一遍

为什么 fn read(path: impl AsRef<std::path::Path>) 常比直接要求 String 更适合文件路径 API？

完成后查看参考解析

调用者可以提供多种能借出 Path 的类型，函数不必接管 String。路径也不保证能完整表示为 UTF-8 文本，应尊重 Path/OsStr 抽象。
