宏与属性：识别生成出来的代码

读懂感叹号、derive 和条件编译的边界。

拆解进阶语言结构建议 8–15 分钟

先建立一个判断方法

name!(...) 通常是宏调用；宏处理 token 并展开成 Rust 代码，随后仍要经过类型检查。macro_rules! 是声明宏，其 $x:expr 匹配表达式，$(...),* 表示逗号分隔的重复。

#[derive(Debug, Clone)] 请求生成 trait 实现；#[cfg(...)] 控制代码是否编译；#[test] 把函数标记为测试。属性不一定都是宏：既有内建属性，也有过程宏属性。看到陌生属性先查定义和依赖。

依据：Rust 官方文档 · 对应章节

先预测，再运行

先说出输出、关键值的类型，以及它们是否仍可使用，再展开结果。

examples/l29.rs / Rust 2024
macro_rules! list {
    ($($value:expr),* $(,)?) => { vec![$($value),*] };
}
#[derive(Debug, Clone)]
struct Item {
    count: u32,
}
fn main() {
    let values = list![2, 4, 6];
    let item = Item {
        count: values.len() as u32,
    };
    println!("{:?} {}", item.clone(), item.count);
}
展开预期输出与阅读解析
Item { count: 3 } 3
  1. list! 把参数转成 vec! 调用；重复参数仍必须满足 Vec 元素类型要求。
  2. Debug 支持 {:?}，Clone 提供 .clone()；derive 不表示会在所有赋值处自动克隆。

运行：在 examples/rust-reading 中执行 cargo run --offline --example l29。所有主示例均为完整程序；练习里的失败片段会明确说明。参见 下载与运行说明。

常见误读宏展开不等于“绕过类型系统”。序列化宏、异步入口宏的行为来自对应库，不能只凭属性名称猜完整语义。
