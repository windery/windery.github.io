类加载：双亲委派与类的身份

同名的两个类为什么可以不相等，框架为什么需要自己的加载器。

JVM 运行时：从源码到运行建议 15–20 分钟

先建立一个判断方法

从 JDK 9 起，一个普通应用至少有三层类加载器。bootstrap 加载器由 JVM 用 C++ 实现，负责 java.base 等核心模块，在 Java 代码里表现为 null；platform 加载器负责 java.sql 等平台模块，它取代了 JDK 8 的 extension 加载器；app 加载器（也叫 system 加载器）负责 classpath 和 module path 上的应用类。

ClassLoader.loadClass 的默认流程是双亲委派：先看自己是否已经加载过这个名字，没有就交给父加载器，父加载器找不到时才调用自己的 findClass 去读字节码。这样核心类只会有一份，应用也无法用自己写的 java.lang.String 冒充核心类。

判断两个类是否相同，要同时看两样东西：全限定名，以及定义它的加载器（defining loader）。同一份 .class 文件被两个加载器各自定义，就是两个互不兼容的运行时类型：静态字段各有一份，实例之间不能互相强转。

很多框架会有意改变默认委派。Tomcat 为每个 web 应用创建独立加载器，优先加载应用自己 WEB-INF 下的类，以便隔离不同应用的依赖；ServiceLoader 和 JDBC 通过线程上下文加载器（TCCL），让核心库找到应用提供的实现；热部署则是丢弃整棵旧加载器，换一个新加载器重新加载类。

依据：JVM 规范 §5.3 · 创建与加载 · JDK 21 API · ClassLoader

先预测，再运行

先预测最后三行：两个加载器读的是同一个文件，“同一个类”会是 true 吗？新建的对象是 Payload 的实例吗？

java-depth/src/L02.java / JDK 21
import java.net.URL;
import java.net.URLClassLoader;

public class L02 {
    public static class Payload {
        public Payload() {}
    }

    public static void main(String[] args) throws Exception {
        System.out.println("String 的加载器: " + String.class.getClassLoader());
        ClassLoader app = L02.class.getClassLoader();
        System.out.println("L02 的加载器: " + app.getName());
        System.out.println("它的父加载器: " + app.getParent().getName());

        URL[] path = { L02.class.getProtectionDomain().getCodeSource().getLocation() };
        ClassLoader platform = ClassLoader.getPlatformClassLoader();
        try (var a = new URLClassLoader(path, platform);
             var b = new URLClassLoader(path, platform)) {
            Class<?> ca = a.loadClass("L02$Payload");
            Class<?> cb = b.loadClass("L02$Payload");
            System.out.println("名字相同: " + ca.getName().equals(cb.getName()));
            System.out.println("同一个类: " + (ca == cb));
            Object o = ca.getDeclaredConstructor().newInstance();
            System.out.println("instanceof Payload: " + (o instanceof Payload));
        }
    }
}
展开实际输出与阅读解析
String 的加载器: null
L02 的加载器: app
它的父加载器: platform
名字相同: true
同一个类: false
instanceof Payload: false
  1. String 由 bootstrap 加载器定义，所以 getClassLoader() 返回 null。这不代表“没有加载器”。
  2. a 和 b 的父加载器都是 platform。platform 在平台模块里找不到 L02$Payload，于是 a、b 各自从同一个目录读取同一个 .class 并定义它，得到两个不同的 Class 对象。
  3. 源码里写的 Payload 解析为 app 加载器定义的那个类，和 a 定义的不是同一个，所以 instanceof 为 false。如果此时写 (Payload) o，会抛出 ClassCastException: class L02$Payload cannot be cast to class L02$Payload，异常消息会分别注明两边的加载器。

运行：在解压后的 java-depth 目录执行 ./run.sh l02，课程名之后可以追加 JVM 参数。参见 下载与运行说明。

常见误读“全限定名相同就是同一个类”只在只有一个加载器的世界里成立。看到“X cannot be cast to X”时，不要怀疑编译器，先读异常消息里两个类各自属于哪个加载器。

变成 true。双亲委派会先问父加载器。app 加载器能在 classpath 上找到 L02$Payload，于是 a、b 都返回 app 定义的同一个类，instanceof Payload 也变成 true。

完成后查看参考解析

DevTools 把项目自己的类放进一个可丢弃的 restart 加载器，依赖 jar 留在 base 加载器。重启后，如果有对象被 base 一侧的组件持有（例如进程内缓存或反序列化时用了错误的加载器），它的类属于旧的或另一个加载器，与新加载器里的同名类不相等。先读异常消息中两个 Order 各自的 loader，再找出是谁创建或缓存了这个对象。
