JDK 诊断工具速查

课程中用到的命令都在这里。先用 jcmd 列出进程号，下文的 <pid> 都指它。

jcmd：对运行中的 JVM 提问

命令回答的问题课程
jcmd本机有哪些 Java 进程01
jcmd <pid> help这个 JVM 支持哪些诊断命令01
jcmd <pid> VM.flags最终生效的 JVM 参数，包括 ergonomics 推导出的值01
jcmd <pid> VM.command_line进程启动时的完整命令行01
jcmd <pid> Thread.print所有线程的栈，包括 GC、编译等 JVM 内部线程01
jcmd <pid> GC.heap_info堆的分区和占用01
jcmd <pid> GC.class_histogram堆中每个类的实例数和字节数09
jcmd <pid> GC.heap_dump <file>生成堆转储，交给 MAT 等工具分析09
jcmd <pid> Compiler.codecacheJIT 编译后代码占用的 code cache05
jcmd <pid> JFR.start duration=60s filename=rec.jfr录制 60 秒 Java Flight Recorder 数据25

javap：看编译器生成了什么

命令作用
javap -c -p Foo反汇编所有方法（含 private）的字节码
javap -v Foo额外显示常量池、版本号、局部变量表等全部信息
javap -s Foo显示方法的内部类型签名，如 (I)Ljava/lang/String;

启动参数：打开观察窗口

参数作用
-Xlog:gc每次 GC 打印一行；-Xlog:gc* 打印全部 GC 细节
-XX:+PrintCompilation每编译一个方法打印一行，含层级和 OSR 标记
-XX:ActiveProcessorCount=1让 JVM 以为只有 1 个 CPU，用来复现容器里的 ergonomics
-XX:-UseCompressedOops关闭压缩指针，引用变成 8 字节
-XX:-DoEscapeAnalysis关闭逃逸分析，用于对照实验
-XX:+HeapDumpOnOutOfMemoryError发生 OOM 时自动生成堆转储，线上建议常开
-XX:NativeMemoryTracking=summary开启后可用 jcmd <pid> VM.native_memory summary 查看堆外内存

JOL：测量对象布局

调用作用
ClassLayout.parseClass(Foo.class).toPrintable()某个类的实例字段偏移、对齐与大小
ClassLayout.parseInstance(obj).toPrintable()同上，并显示对象头当前的值
GraphLayout.parseInstance(obj).toFootprint()沿引用统计整张对象图，按类汇总数量和字节数
VM.current().details()当前 JVM 的指针大小、对齐等基本参数

更多用法见 openjdk/jol 使用指南。
