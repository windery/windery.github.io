学习路线

这门课写给正在从 Java 后端转向 AI 应用开发的工程师。不必从头读到尾，按目标选路线。

三条路线，共用一份课程

你的目标建议路线
尽快转向 AI 应用开发01–05 打好运行时基础，13–15 掌握线程池与虚拟线程（大模型调用是高延迟 I/O），然后读 27–34 的架构与 AI 应用阶段。
补齐深度，准备架构设计或面试按顺序读完 01–23，再读 27–32。每个阶段结束时做一遍下表的检查。
解决眼前的线上问题先读 01 学会用 jcmd 取证，再按症状跳转：内存问题读 06–09，卡顿与线程问题读 10–16，性能问题读 24–26。

为什么转 AI 还要学这些

AI 应用里的问题对应的课程
一次模型调用要几秒，成百上千个并发请求怎么撑住13 线程池、14 CompletableFuture、15 虚拟线程
向量、embedding 缓存放在进程内会占多少内存04 对象布局、06 内存区域、09 内存泄漏排查
模型 API 限流、超时、偶发失败31 限流、熔断与降级
一次 Agent 请求调了五个工具，哪一步慢了32 可观测性
把检索、生成、评估组织成能演进的服务27 边界设计、33 Java 调用大模型、34 RAG 服务实战

每阶段怎样知道可以继续

阶段可以继续的标志
01 JVM 运行时拿到一个陌生 Java 进程，能用 jcmd 说出它的 GC、堆上限和最忙的线程；能用 javap 解释一处“反直觉”的输出。
02 内存与 GC看到一条 OutOfMemoryError 消息，能说出是哪个区域、先采集什么证据。
03 并发能说明一段代码为什么需要 volatile 或锁，并为一个 I/O 密集服务选出线程模型。
04 语言与类库能解释泛型擦除、动态代理在一段框架代码里的作用。
05 框架原理能说出一个 @Transactional 不生效的原因，并在源码里找到对应的位置。
06 性能与诊断能写出一个结论可信的 JMH 基准，读懂一张火焰图。
07 架构能为一个跨服务的下单流程设计幂等和最终一致方案，并说出取舍。
08 AI 应用能用 Java 搭出一个带检索、工具调用和超时保护的最小 RAG 服务。
