## 重点解读

### GitHub 把修漏洞做成了闭环，但闭环只到草稿 PR

10 月 15 日，GitHub 同时开放了两项代码安全能力：agentic autofix 和 AI Scan。前者从默认分支的安全告警出发，让 Copilot 找到相关代码、生成修改、重新运行 CodeQL；告警还在就继续调整，最后提交一份写明修复和验证过程的草稿 PR。一份 PR 最多处理 25 条告警。

后者补的是检查范围。AI Scan 在 PR 里检查 PHP、Shell、Terraform、Dockerfile，以及部分 Java、C# 框架的变更，弥补 CodeQL 没覆盖的语言和配置。两项功能都不要求 Copilot 许可证，但都会消耗 Code Security 的 AI Credits；autofix 还消耗 Actions 分钟，并且只面向 GitHub Enterprise Cloud 上购买 Code Security 或 Advanced Security 的客户。

最需要记住的是边界。autofix 只接收默认分支上的告警，PR 或其他分支独有的告警不能直接指派；重新扫 CodeQL 证明的是原告警是否消除，不证明业务功能没被改坏。AI Scan 的结果目前只作建议，不会让检查失败，也不能阻止合并；来自 fork 和 Dependabot 的 PR 不运行这项检查。两项功能的入口也不同，公告没有承诺 AI Scan 的发现会自动交给 Copilot 修复。

对已经在用 GitHub 安全服务的团队，值得先拿一批低风险的默认分支告警做试点：看修复 diff、CodeQL 结果和业务回归，再决定是否扩大。对只用托管模型 API 的开发者，这项更新暂时不需要动作。

## 工具与实践

### TokenSpeed：C++ 调度请求与缓存，Python 执行模型

如果你自己部署模型服务，一次 Agent 任务会带来一串请求：长输入、正在生成的请求和缓存资源都要排队。LightSeek Foundation 开源的 TokenSpeed 把请求状态与缓存调度放进 C++，把模型执行留在 Python，并提供兼容 OpenAI 的 HTTP 接口。

沿着代码读，有三处值得看。`fsm/states.h` 用 `std::variant` 列出 Submitted、Prefilling、Decoding、Finishing 等状态，`Request::Apply` 把事件作用到当前状态；`CacheBlockRef` 用引用计数管理共享缓存块，最后一个引用释放时才销毁；Python 事件循环从 C++ 调度器取 `next_execution_plan()`，再交给设备执行入口。三处连起来，就是“这一轮算谁、缓存归谁、在哪执行”。

它适合已经有 GPU、想研究推理调度或针对特定负载调优的团队；只调用托管 API 的应用不需要自己接管这一层。和 vLLM 相比，两者都提供兼容 OpenAI 的服务入口，是否更合适仍取决于模型、硬件、并发和输入输出长度。本文没有跑性能测试，README 里的加速数字不能当实测结论。

上手先按官方文档选 GPU 路线，用 `tokenspeed env` 检查环境，再试 `tokenspeed serve --help`；官方最小示例是 `openai/gpt-oss-20b`，实际能否装入取决于硬件。要比较现有引擎，固定模型、精度、输入长度和并发，记录首 token 延迟、持续生成速度和错误情况，比只看榜单星标更有用。

### Copilot 的 11 月 16 日迁移清单

GitHub 宣布 2026 年 11 月 16 日在 Copilot 的 Chat、inline edits、ask/agent 和补全等体验中停用 Claude Opus 5、GPT-5.6 Terra，以及多数 Opus 4.8 使用场景。官方建议 Opus 转 Opus 5.5，Terra 转 GPT-6.1 Sol 或 GPT-6 Luna。个人年付订阅的 Opus 4.8 不在停用范围；Business/Enterprise 的替代模型还取决于管理员策略。现在就该列出仍指定旧模型的入口，用同一组真实任务回归替代模型，而不是等到截止日才发现不可用。

### Opus 5.5 的 fast mode 开始单独计费

Anthropic 把 Opus 5.5 的 API fast mode 移出 research preview：不再需要申请，也不再必需旧 beta header，请求使用 `speed:"fast"`。官方说最高 2.5 倍输出速度，不是整个任务快 2.5 倍；API 输入/输出价格是每百万 token 8/40 美元，Claude Code 订阅里的 fast mode 另扣 usage credits，不消耗套餐额度。想开之前先设预算，比较一次任务的总费用和端到端耗时；后台批处理继续用标准速度。

2026-10-15 · Claude Platform：[release notes](https://platform.claude.com/docs/en/release-notes/overview)

### Anthropic 向六名 METR 人员开放内部访问

Anthropic 向非营利评估机构 METR 的六名员工提供公司设备、办公空间，以及接近内部风险评估团队的工具和系统访问权限。METR 可以发表对 Anthropic 风险水平、事件和实践的分析，Anthropic 不能否决；客户数据、律师保密信息、模型架构等类别被排除，双方可以就删减是否合理公开讨论。这次公布的是外部机构如何获得信息、如何发表结果，不是 METR 已经给出安全结论，也不代表其他机构自动获得同样权限。

## 深读推荐

### Simon Willison 用语音写功能，再用键盘收尾

Simon 在 10 月 9 日的博客里记录了一次开发：一边做饭，一边用 Codex 的语音对话，给自己的 Django 博客加 newsletter 归档。他先让 Codex 启动本地服务器并打开预览，再开始说；做饭时瞥一眼页面，直接指出哪里不对。原文保留了带改口的语音转录：newsletter 不要进标签页和首页，但要进发送当天的日期归档；Substack 周报不进搜索，月度 newsletter 有独立内容，公开后应该能被搜到。

语音阶段结束后，他让 Codex 创建分支和 PR，再去 GitHub 审查。他发现一个导入脚本用 Git 子进程，涉及私有仓库时更希望走 API，于是切回键盘要求修改，也调整了页面展示；私有数据导入还需要新的 API key，这部分同样回到键盘。按他的记录，语音约半小时，之后键盘审查和修改又约半小时。

这个案例的价值不是“语音能替代打字”，而是分工：语音适合在预览已经出现时讨论业务规则，键盘适合粘贴报错、参数、代码位置和配置。先在自己熟悉的小功能上试，保留预览、分支和 PR 这些可检查的中间物，比一次性改变整个开发方式更接近这个案例的条件。
