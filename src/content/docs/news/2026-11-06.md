## Agent

### [23 分钟教程：用 Claude 从零搭 4 个 Agent](https://x.com/i/status/2118316821996798100)

### [没有测试集时，从 100 条 trace 起步做 evals](https://x.com/kritinv07/status/2118382835530690852)

给出七步做法：取 100 条近期生产 trace，用大白话记下问题，归类并计数，为前三类写 pass/fail 检查，与人工标注对比，新失败持续加入数据集。 （来源：X List）

### [别只信公开基准，做自己的私有 evals](https://x.com/HamelHusain/status/2118357661750288570)

Hamel Husain 提醒要做自己的私有评测：不少基准有实质缺陷，部分模型已记住标准答案。他补充说，关键是针对真实系统、持续维护的高质量测试。 （来源：X List）

### [Deep Agents 的异步 subagent：长任务不阻塞主 Agent](https://www.langchain.com/blog/agents-are-going-async)

LangChain 介绍异步 subagent：后台 worker 跑长任务时，Agent 仍能保持响应。文中讲了 Deep Agents 里编排器、通知和审批的工作方式。 （来源：LangChain Blog）

### [LangChain 比较七种浏览器工具集，选定 Stagehand](https://www.langchain.com/blog/how-we-optimized-browser-use-for-deep-agents)

LangChain 为 Deep Agents 对比了七套浏览器工具集，选出 Browserbase 的 Stagehand，并借助 LangSmith 的 trace 和 evals 做了调优。 （来源：LangChain Blog）

### [Agent 记忆的上下文工程要从检索做起](https://www.langchain.com/blog/context-engineering-starts-with-retrieval)

Agent 常因笨拙的搜索、过大的结果和过期数据浪费时间与上下文。文章介绍了 LangChain 的 Deep Agents 用来取到正确上下文的检索技巧。 （来源：LangChain Blog）

### [为什么异步 subagent 是长任务 Agent 的关键原语](https://x.com/sydneyrunkle/status/2118435802338427095)

Sydney Runkle 指出，Agent 干活越久，异步 subagent 越重要：主编排器不被阻塞，可持续与人交互，工作也能高效分给后台 worker。 （来源：X List）

### [Executor v2 发布：让 Agent 像写代码一样驱动 Zapier/Retool](https://x.com/RhysSullivan/status/2118440383353172022)

Executor v2 是对产品的大改版，可以理解为 Zapier / Retool 完全能用代码驱动，所有功能都暴露给你的 Agent。 （来源：X List）

### [Raindrop 推出：每个 PR 用真实场景一键测试 Agent](https://x.com/benhylak/status/2118407746076950882)

Raindrop 的新产品能在每个 PR 上用真实场景测试 Agent、一键完成，并负责搭好沙箱、fixtures、真实与合成数据、evals 等环境。 （来源：X List）

### [逆向分析 Agent 产品：让它看上下文再问它自己](https://x.com/dotey/status/2118431419424714878)

宝玉分享逆向技巧：让 Agent 看到相关上下文，再问相关信息。比如让 Claude Duet 安装一个 Skill，再问它如何实现，它会说明自己的 skill_propose 工具。 （来源：X List）
