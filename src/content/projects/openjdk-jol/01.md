TL;DR：JOL（Java Object Layout）是 OpenJDK 下的小工具箱，能读出对象在当前 JVM 里的真实布局与占用：对象头、字段偏移、对齐损失和整张对象图的大小。本文讲清它能看到什么，并用 jol-core 0.17 在 JDK 21 上跑一个完整例子。

## 它解决什么问题

Java 语言规范不规定对象在内存里长什么样。字段顺序、对象头大小、引用是 4 字节还是 8 字节，都由具体 JVM 和启动参数决定。凭经验估算在下面这些场景就不够了：

- 本地缓存放 100 万个条目，堆要预留多少？
- 给类加一个 `boolean` 字段，实例为什么没变大，又为什么有时突然多出 8 字节？
- 两个高频写的 `volatile long` 会不会落在同一条 cache line 上（false sharing）？
- 堆超过 32 GB、compressed oops 失效后，内存到底涨多少？

JOL 借助 Unsafe、Instrumentation 和 HotSpot Serviceability Agent（SA）解码**当前这个 JVM 进程**里的实际布局，而不是按规范或经验推算。它只支持 HotSpot / OpenJDK：`VM.current()` 发现 `java.vm.name` 不含 `HotSpot` 或 `OpenJDK` 时直接抛出 `IllegalStateException`。

## 它能看到什么

| 概念 | 含义 | JOL 里怎么看 |
| --- | --- | --- |
| 对象头 mark word | 锁状态、GC 年龄、identity hash 等，64 位 JVM 上 8 字节 | `(object header: mark)` 行，带解码说明，如 `non-biasable; age: 0` |
| 对象头 class word | 指向类元数据；开启 compressed class pointers 时 4 字节 | `(object header: class)` 行 |
| 数组长度 | 数组额外的 4 字节长度槽 | `(array length)` 行 |
| 字段偏移 | JVM 会重排字段以减少空洞，并按字段大小对齐 | 每个字段的 `OFF`（偏移）和 `SZ`（大小） |
| 对齐损失 | 字段间空洞、对象尾部按 `ObjectAlignmentInBytes`（默认 8）补齐 | `(alignment/padding gap)`、`(object alignment gap)`，汇总为 internal / external 损失 |
| Compressed oops / class pointers | 64 位 JVM 上用 32 位编码引用和类指针 | `VM.current().details()` 的对应行与 `Field sizes` 中的 `ref` 列 |
| 对象图占用 | 从根对象出发所有可达对象的数量与大小 | `GraphLayout.parseInstance(root).totalSize()` / `toFootprint()` |

另外，JOL 除了读取真实布局（`CurrentLayouter`），还能用 `HotSpotLayouter` 在纯 Java 里**模拟**其他数据模型和 JDK 版本下的布局，回答“换 JDK、关掉 compressed oops 会怎样”。原理见[工作原理](/projects/openjdk-jol/02/)。

## 仓库结构

| 模块 | 内容 |
| --- | --- |
| `jol-core` | 核心库：`info`（`ClassLayout`、`GraphLayout` 等对外 API）、`vm`（与 JVM 打交道）、`layouters`（真实与模拟布局）、`datamodel`、`heap`（heap dump 读取） |
| `jol-cli` | 命令行工具，打包成可 `java -jar` 运行的 jar |
| `jol-samples` | 28 个编号示例 `JOLSample_01_Basic` 到 `JOLSample_28_Difference`，每个都有注释说明要演示什么，是最好的教材 |
| `jol-benchmarks` | JMH 基准，测 JOL 自身遍历对象图的开销 |

日常只需要 `jol-core`（写代码）和 `jol-cli`（不写代码）。

## 引入依赖

Maven Central 上最新正式版是 `0.17`（2023-02 发布），主分支是尚未发布的 `0.18-SNAPSHOT`。核心 API 两者一致。

```xml
<dependency>
    <groupId>org.openjdk.jol</groupId>
    <artifactId>jol-core</artifactId>
    <version>0.17</version>
</dependency>
```

Gradle：`implementation("org.openjdk.jol:jol-core:0.17")`。

## 核心 API

| API | 作用 |
| --- | --- |
| `VM.current().details()` | 打印 VM 模式：位数、compressed oops / class pointers、对象对齐、各类型字段大小 |
| `ClassLayout.parseClass(Foo.class).toPrintable()` | 只看类的布局，不需要实例 |
| `ClassLayout.parseInstance(obj).toPrintable()` | 看具体实例，额外显示 mark word 和字段当前值 |
| `instanceSize()` / `getLossesInternal()` / `getLossesExternal()` | 以数字拿到实例大小和对齐损失，适合写进测试断言 |
| `GraphLayout.parseInstance(roots...)` | 从一个或多个根遍历所有可达对象 |
| `totalSize()` / `totalCount()` / `toFootprint()` | 总字节数、总个数、按类汇总的 COUNT / AVG / SUM 表 |
| `GraphLayout#subtract()` / `add()` | 两次快照做差或求和，看一次操作新分配了什么 |

## 一个完整例子

`Demo.java` 依次看：一个业务类的布局、`Object` 在 `hashCode()` 前后的 mark word、`long[3]`，以及装了 1000 个条目的 `HashMap<String, Integer>`。

```java
import org.openjdk.jol.info.ClassLayout;
import org.openjdk.jol.info.GraphLayout;
import org.openjdk.jol.vm.VM;
import java.util.HashMap;
import java.util.Map;

public class Demo {
    static class Order {
        boolean paid;
        long id;
        int amount;
        String sku;
    }

    public static void main(String[] args) {
        System.out.println(VM.current().details());
        System.out.println(ClassLayout.parseClass(Order.class).toPrintable());

        Object lock = new Object();
        System.out.println(ClassLayout.parseInstance(lock).toPrintable());
        System.out.println("hashCode: " + Integer.toHexString(lock.hashCode()));
        System.out.println(ClassLayout.parseInstance(lock).toPrintable());

        System.out.println(ClassLayout.parseInstance(new long[3]).toPrintable());

        Map<String, Integer> cache = new HashMap<>();
        for (int i = 0; i < 1000; i++) cache.put("key-" + i, i);
        GraphLayout g = GraphLayout.parseInstance(cache);
        System.out.println("totalCount = " + g.totalCount());
        System.out.println("totalSize  = " + g.totalSize());
        System.out.println(g.toFootprint());
    }
}
```

把从 Maven Central 下载的 `jol-core-0.17.jar` 放在同一目录，用单文件源码模式运行（环境：OpenJDK 21.0.11，Linux x86_64，默认参数）：

```bash
java -cp jol-core-0.17.jar Demo.java
```

VM 信息（第一行警告见“注意事项”）：

```text
# WARNING: Unable to get Instrumentation. Dynamic Attach failed. You may add this JAR as -javaagent manually, or supply -Djdk.attach.allowAttachSelf
# VM mode: 64 bits
# Compressed references (oops): 3-bit shift
# Compressed class pointers: 0-bit shift and 0x7FD577000000 base
# Object alignment: 8 bytes
#                       ref, bool, byte, char, shrt,  int,  flt,  lng,  dbl
# Field sizes:            4,    1,    1,    2,    2,    4,    4,    8,    8
```

`Order` 的布局：

```text
Demo$Order object internals:
OFF  SZ               TYPE DESCRIPTION               VALUE
  0   8                    (object header: mark)     N/A
  8   4                    (object header: class)    N/A
 12   4                int Order.amount              N/A
 16   8               long Order.id                  N/A
 24   1            boolean Order.paid                N/A
 25   3                    (alignment/padding gap)
 28   4   java.lang.String Order.sku                 N/A
Instance size: 32 bytes
Space losses: 3 bytes internal + 0 bytes external = 3 bytes total
```

对象头 8 + 4 = 12 字节；JVM 重排了字段，`int amount` 填进头后的 4 字节空位，`long id` 落在 8 字节对齐的偏移 16；`boolean` 后有 3 字节空洞，因为引用要按 4 对齐。

`Object` 在 `hashCode()` 前后：

```text
  0   8        (object header: mark)     0x0000000000000001 (non-biasable; age: 0)
  8   4        (object header: class)    0x00000e90
 12   4        (object alignment gap)
Instance size: 16 bytes

hashCode: 43c1b556
  0   8        (object header: mark)     0x00000043c1b55601 (hash: 0x43c1b556; age: 0)
```

identity hash 一旦计算就写进 mark word；一个空 `Object` 也要 16 字节，其中 4 字节是尾部对齐。`long[3]` 则多一个 `(array length)` 槽，元素从偏移 16 开始，总计 40 字节。

`HashMap` 对象图：

```text
totalCount = 4002
totalSize  = 104256
     COUNT       AVG       SUM   DESCRIPTION
      1000        24     24000   [B
         1      8208      8208   [Ljava.util.HashMap$Node;
      1000        16     16000   java.lang.Integer
      1000        24     24000   java.lang.String
         1        48        48   java.util.HashMap
      1000        32     32000   java.util.HashMap$Node
      4002              104256   (total)
```

平均每个条目约 104 字节，而有效数据只是一个短字符串和一个 4 字节整数。加上 `-XX:-UseCompressedOops` 重跑，引用变成 8 字节，`Order` 涨到 40 字节，这张图涨到 128,464 字节（约 +23%）——这就是“堆别轻易超过 32 GB”的量化依据。

## 常用 JVM 参数

| 参数 | 作用 |
| --- | --- |
| `-Djdk.attach.allowAttachSelf` | 允许 JOL 自我 attach 拿到 Instrumentation；JDK 21 上会再警告动态加载 agent，可加 `-XX:+EnableDynamicAgentLoading` 消除 |
| `-XX:-UseCompressedOops` | 关闭压缩引用，模拟大堆 |
| `-XX:ObjectAlignmentInBytes=16` | 修改对象对齐，观察尾部损失变化 |
| `-XX:-RestrictContended` | 让应用代码里的 `@Contended` 生效，用来验证 false sharing 填充（见 `JOLSample_09_Contended`） |
| `-Djol.skipHotspotSAAttach=true` | 跳过 SA，启动更快；字段偏移不受影响，但对象地址变为推测值 |

例如：

```bash
java -Djdk.attach.allowAttachSelf -XX:+EnableDynamicAgentLoading -XX:-UseCompressedOops \
     -cp jol-core-0.17.jar Demo.java
```

## 命令行工具 jol-cli

不想写代码时，从 Maven Central 的 `org/openjdk/jol/jol-cli/0.17/` 下载 `jol-cli-0.17-full.jar`。它自带 `Launcher-Agent-Class`，`java -jar` 启动即可获得 Instrumentation，没有 attach 警告。

```bash
java -jar jol-cli-0.17-full.jar internals -cp target/classes com.example.Order
java -jar jol-cli-0.17-full.jar footprint java.util.concurrent.ConcurrentHashMap
java -jar jol-cli-0.17-full.jar heapdump-estimates app.hprof
```

不带参数运行可查看命令列表。**注意命令名随版本不同**：0.17 发布版是 `internals`、`externals`、`footprint`、`estimates`、`heapdump-estimates`、`heapdumpstats`、`shapes`、`string-compress`；主分支重做了 CLI，改为 `internals`、`internals-estimates`、`externals`、`footprint`、`heapdump-stats`、`heapdump-estimates`、`heapdump-duplicates`、`heapdump-strings`、`heapdump-boxes`。要用主分支命令，需从源码 `mvn clean verify` 构建，或使用 README 提到的 builds.shipilev.net 构建。

## 注意事项

- **结果属于当前 VM**：JDK 版本、位数、堆大小、`UseCompressedOops`、对齐参数都会改变结果。写进文档或评审的数字要注明运行环境。
- **attach 警告**：例子开头的 `Unable to get Instrumentation` 表示 JOL 没能自我 attach，`Instance size` 退回到自己计算。加 `-Djdk.attach.allowAttachSelf`，或改用 jol-cli 的 full jar（`jol-core` 的 jar 没有 `Premain-Class`，不能当 `-javaagent` 用）。
- **单文件源码模式的限制**：`java Demo.java` 运行时，对自定义类调用 `parseInstance(...).toPrintable()` 会抛出 `Class is not found`，因为 JOL 按类名重新加载类，看不到源码启动器在内存里编译的类。上面的例子因此对 `Order` 只用了 `parseClass`；需要看自定义类的实例时，先 `javac -cp jol-core-0.17.jar Demo.java` 再 `java -cp jol-core-0.17.jar:. Demo`。
- **可达不等于独占**：`GraphLayout` 统计所有**可达**对象，不是 MAT 里基于支配树的 retained size。被共享的对象（`Integer` 缓存里的小整数、驻留字符串）也会计入。量缓存时，关注代表性数据下单条目的边际成本。
- **数值是快照**：mark word 和字段值是调用那一刻的状态；GC 可能在遍历中搬移对象，地址每次运行都不同。
