TL;DR：Paperclip 的核心是“唤醒请求 → 心跳运行 → 适配器执行 → 结果入账”这条链路。所有触发源都汇入 `heartbeat.ts` 的 `enqueueWakeup()`，经过暂停、预算、策略检查后写入数据库队列，并与已在排队的运行合并；执行器取出运行、准备工作区与凭证，调用适配器的 `execute()`；Agent 再通过 REST API 原子领取任务、回写进度。预算、审批和活动日志都挂在这条链路的关口上。

本文按模块分层、一次心跳的控制流、关键实现、扩展点的顺序展开。概念和术语见第 01 篇，启动与配置见第 02 篇。

## 模块分层

这是一个 pnpm monorepo，`AGENTS.md` 给出了各目录的职责：

| 层次 | 目录 | 职责 |
| --- | --- | --- |
| 界面 | `ui/` | React 19 + Vite + TanStack Query 的看板；开发模式下由 API 服务以中间件方式提供 |
| 接口 | `server/src/routes/` | Express 5 的 REST 路由，统一挂在 `/api` 下；鉴权、公司边界检查 |
| 编排服务 | `server/src/services/` | 业务逻辑：`heartbeat.ts`（唤醒与运行）、`issues.ts`（任务与领取）、`budgets.ts`、`approvals.ts`、`routines.ts`、`activity-log.ts`、插件宿主等 |
| 适配器注册 | `server/src/adapters/` | 适配器类型到实现的映射，内置 `process`、`http`，并加载外部适配器包 |
| 适配器实现 | `packages/adapters/*`、`packages/adapter-utils/` | Claude、Codex、Gemini、OpenCode 等 CLI 的启动、输出解析、会话编解码；公共的进程与环境变量工具 |
| 数据 | `packages/db/` | Drizzle ORM 的 schema 与迁移，默认连嵌入式 PostgreSQL |
| 共享契约 | `packages/shared/` | 常量、类型、校验器、API 路径；服务端、UI、CLI 共用 |
| 扩展 | `packages/plugins/` | 插件 SDK、示例插件、沙箱提供方 |
| 原生 Runner | `packages/paperclip-runner/` | 独立进程（Rust）执行 Agent 会话，通过 Paperclip Runner Protocol 与服务端通信 |
| CLI | `cli/` | `paperclipai` 命令：安装、配置、诊断，以及面向 Agent 的控制平面操作 |
| Agent 技能 | `skills/paperclip/` | 注入给 Agent 的工作协议，规定每次心跳该调用哪些 API |

`AGENTS.md` 要求改动保持“契约同步”：改了数据模型，就要同时更新 `packages/db`、`packages/shared`、服务端路由与服务、UI 客户端。

## 一次心跳的控制流

`doc/spec/agent-runs.md` 把这套子系统拆成适配器注册表、唤醒协调器、运行执行器、运行时状态、运行日志、实时事件六个部件。结合 `server/src/services/heartbeat.ts`，一次心跳大致经过以下阶段：

| 序号 | 阶段 | 发生了什么 | 落到哪里 |
| --- | --- | --- | --- |
| 1 | 触发 | 指派任务、负责人收到评论、手动唤醒、定时器、例行任务、审批结果等 | 调用 `enqueueWakeup(agentId, opts)`；来源取值 `timer` / `assignment` / `on_demand` / `automation` |
| 2 | 准入 | 丢弃不应触发运行的唤醒（例如评论中的 @ 提及）；检查预算阻断、Agent 的心跳策略、公司与项目暂停、执行保持（hold）等 | 被拦下的请求写成 `skipped` 记录并注明原因，不消耗执行次数 |
| 3 | 入队与合并 | 写入 `agent_wakeup_requests`；如果同一 Agent 已有排队或运行中的运行，新请求合并进去（记为 `coalesced`），否则新建一条 `queued` 状态的 `heartbeat_runs` | PostgreSQL，重启后仍在 |
| 4 | 领取运行 | `startNextQueuedRunForAgent()` 按 Agent 的 `maxConcurrentRuns`（默认 20）计算可启动数量，`claimQueuedRun()` 认领 | 运行状态转为 `running` |
| 5 | 准备执行 | 用适配器的会话编解码器恢复上次会话；解析或创建工作区（可以是 git worktree）；校验并注入密钥；同步技能与指令文件；为支持的适配器签发本次运行的短期 JWT | 运行事件写入 `heartbeat_run_events` |
| 6 | 执行 | `getServerAdapter(agent.adapterType).execute(ctx)`，通过 `onLog`、`onEvent`、`onUsage` 等回调实时回传日志、事件和用量 | 日志流经 WebSocket 推给 UI |
| 7 | Agent 回调 | Agent 进程读取注入的 `PAPERCLIP_*` 环境变量，调用 REST API：查收件箱、领取任务、评论、改状态、建子任务 | `issues`、评论、文档等表；所有变更写活动日志 |
| 8 | 收尾 | 根据退出码、超时、错误类别决定运行状态；保存会话参数供下次续接；记录用量和花费；释放任务锁；必要时安排有界重试 | `heartbeat_runs`、`agent_task_sessions`、`cost_events` |

几点值得注意：

- 定时心跳由服务进程内的调度循环驱动。`server/src/index.ts` 每隔 `HEARTBEAT_SCHEDULER_INTERVAL_MS`（默认 30 秒）调用 `heartbeat.tickTimers()`，为到期的 Agent 认领一次定时心跳；同一循环还负责外部对象刷新、GitHub 事件轮询、工作区清理等后台任务。另一个独立的定时器做执行控制的对账与恢复。
- 只有被指派、被评审请求、负责人收到顶层评论等明确路径会唤醒 Agent。@ 提及在 `enqueueWakeup()` 开头就被忽略，文档评论默认也不唤醒。
- Agent 侧的流程写在 `skills/paperclip/SKILL.md`：确认身份 → 处理审批结果 → 取收件箱 → 选任务 → 领取 → 读上下文 → 干活 → 更新状态。所有修改任务的请求都要带 `X-Paperclip-Run-Id` 头，把操作关联到本次运行。

依据：[doc/spec/agent-runs.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/doc/spec/agent-runs.md)、[server/src/services/heartbeat.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/services/heartbeat.ts)、[server/src/index.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/index.ts)、[doc/execution-semantics.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/doc/execution-semantics.md)、[skills/paperclip/SKILL.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/skills/paperclip/SKILL.md)。

## 关键实现

### 原子领取：一条带条件的 UPDATE

“同一任务只能有一个运行在做”是控制平面最核心的不变量。`issues.ts` 中的 `checkout()` 没有用应用层锁，而是把所有前置条件写进一条 `UPDATE ... WHERE`：

- 任务状态在调用方给出的 `expectedStatuses` 之内；
- 任务无人负责，或负责人就是这个 Agent 且 `checkoutRunId` 为空或等于本次运行；
- `executionRunId` 为空或等于本次运行。

条件满足时，同一条语句把负责人、`checkoutRunId`、`executionRunId`、状态 `in_progress` 一起写入。两个运行并发领取时，数据库保证只有一条更新命中，另一方拿到 `409 Conflict`。在执行这条 UPDATE 之前，函数会先清理指向已结束运行的残留锁，检查子树暂停和未解决的阻塞项；UPDATE 落空后，还会尝试接管确认已失效的旧锁（旧运行已终止或不存在），最后才返回冲突。`doc/execution-semantics.md` 明确：清理残留锁属于崩溃恢复，不是重试；不得清除或接管仍在进行中的运行持有的锁。

两个字段的分工是：`checkoutRunId` 表示谁拥有这个任务的执行权，`executionRunId` 表示当前实际在跑的是哪个运行。

依据：[server/src/services/issues.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/services/issues.ts)、[doc/execution-semantics.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/doc/execution-semantics.md)。

### 适配器契约

适配器是 `ServerAdapterModule` 接口的实现，必需的只有三项：`type`、`execute(ctx)`、`testEnvironment(ctx)`。其余都是可选能力：

| 能力 | 字段 | 用途 |
| --- | --- | --- |
| 会话续接 | `sessionCodec`、`sessionManagement` | 把上次运行的会话参数序列化存库，下次恢复 |
| 技能同步 | `listSkills`、`syncSkills` | 把公司技能装进 Agent 的运行环境 |
| 模型列表 | `models`、`listModels`、`refreshModels`、`detectModel` | 供 UI 选择模型 |
| 配置表单 | `getConfigSchema` | 返回声明式表单结构，UI 无需为每个适配器写组件 |
| 运行令牌 | `supportsLocalAgentJwt` | 允许服务端为每次运行签发短期 JWT |
| 额度查询 | `getQuotaWindows` | 查询提供方的限额窗口 |
| 招聘回调 | `onHireApproved` | Agent 被批准招聘时通知外部系统 |

`execute()` 的输入 `AdapterExecutionContext` 包含运行 ID、Agent、运行时状态、配置、唤醒上下文、可选的取消信号，以及 `onLog`、`onMeta`、`onEvent`、`onUsage` 等回调；返回的 `AdapterExecutionResult` 包含退出码、信号、是否超时、错误码与错误类别、用量、按模型拆分的用量、花费、会话参数等。源码注释特别规定了用量口径：`usageBasis` 为 `session_cumulative` 时由服务端对相邻运行做差，缺省按单次运行计，服务端不能因为会话 ID 相同就推断为累计值。

两个最简单的内置实现可以作为阅读入口：

- `process`：用配置中的 `command`、`args`、`cwd` 启动子进程，注入 `PAPERCLIP_AGENT_ID`、`PAPERCLIP_COMPANY_ID`、`PAPERCLIP_API_URL`、`PAPERCLIP_RUN_ID` 和运行令牌 `PAPERCLIP_API_KEY`。配置里写的 `PAPERCLIP_API_KEY` 会被丢弃，运行时的 `PAPERCLIP_*` 值总是优先于配置。退出码非 0 记为失败，超过 `timeoutSec` 记为超时。
- `http`：把 `payloadTemplate` 与 `agentId`、`runId`、唤醒上下文合并后 POST 到配置的 URL，收到 2xx 即视为成功。它只负责“叫醒”外部 Agent，后续由对方回调 API。

复杂的适配器（如 `claude_local`）在此基础上处理更多细节：以 `--print --output-format stream-json` 启动 Claude CLI，用 `--resume` 续接会话，按配置加入模型、推理强度、最大轮数等参数，并解析流式输出得到用量与花费。

依据：[packages/adapter-utils/src/types.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/adapter-utils/src/types.ts)、[server/src/adapters/process/execute.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/adapters/process/execute.ts)、[server/src/adapters/http/execute.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/adapters/http/execute.ts)、[packages/adapter-utils/src/server-utils.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/adapter-utils/src/server-utils.ts)、[packages/adapters/claude-local/src/server/execute.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/adapters/claude-local/src/server/execute.ts)。

### 适配器注册表

`registry.ts` 在模块加载时把 16 个内置适配器放进一个 `Map<type, ServerAdapterModule>`，随后异步加载外部适配器。外部适配器是安装在适配器插件目录 `node_modules` 下的 npm 包，必须导出 `createServerAdapter()`。如果外部适配器的 `type` 与内置类型重名，它会覆盖内置实现，原实现保存在 `builtinFallbacks` 中；暂停或卸载外部适配器时恢复内置版本。`process` 和 `http` 不能被卸载。启动时需要先等 `waitForExternalAdapters()` 完成，否则校验适配器类型时会误判外部类型不存在。

依据：[server/src/adapters/registry.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/adapters/registry.ts)、[server/src/adapters/plugin-loader.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/adapters/plugin-loader.ts)。

### 预算硬停

预算策略按范围（公司、项目、Agent）和时间窗（UTC 自然月或累计）统计已记录的花费，指标为 `billed_cents`。`budgets.ts` 的对账逻辑如下：

1. 对每条策略计算已观测花费；达到 `warnPercent` 时产生软告警事件。
2. 达到硬上限且启用了 `hardStopEnabled` 时，产生硬事件，把对应范围置为 `paused`（`pauseReason = "budget"`），并取消该范围内待执行的唤醒和工作。
3. 有已完成但尚未入账的运行，或存在无可靠定价的用量（且策略不允许）时，同样拒绝新工作。
4. 时间窗滚动、策略停用或调高预算后，只解除由预算造成的暂停；人工暂停保持不变。

`enqueueWakeup()` 在入队前调用 `budgets.getInvocationBlock()`，被阻断的唤醒写成 `budget.blocked` 记录并返回冲突。也就是说，预算拦截发生在“开始新运行”这个关口，已经在跑的运行要靠取消流程停下，这也是 README 说停止可能有延迟的原因。

依据：[server/src/services/budgets.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/services/budgets.ts)、[packages/shared/src/constants.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/shared/src/constants.ts)。

### 原生 Paperclip Runner

除了“服务端直接调适配器”，仓库还有一条独立的执行路径：`paperclip_runner` 适配器把会话交给单独的 Runner 进程。架构决策记录说明了动机：需要持久投递、重启恢复，以及受治理的动作调用，同时不能让 Runner 变成第二个控制平面；现有适配器的调用路径保持不变。在服务端注册表中，`paperclip_runner` 的 `execute()` 被直接调用时只会报错，必须由 Runner 协调器接手。实例设置 `enableNativeRunner` 在当前校验器中默认为 `true`，与这份 ADR 中“默认关闭”的描述不同，以源码为准。

依据：[doc/architecture/paperclip-runner.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/doc/architecture/paperclip-runner.md)、[server/src/adapters/registry.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/server/src/adapters/registry.ts)、[packages/shared/src/validators/instance.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/shared/src/validators/instance.ts)。

## 数据与状态

| 表 | 内容 |
| --- | --- |
| `companies`、`agents`、`projects`、`goals` | 组织结构、目标与设置 |
| `issues` | 任务；含负责人、父任务、状态以及 `checkoutRunId`、`executionRunId` 两把锁 |
| `agent_wakeup_requests` | 每次唤醒的原始请求，状态为排队、合并、跳过等 |
| `heartbeat_runs` | 心跳运行记录：状态、上下文快照、结果、错误、用量 |
| `heartbeat_run_events` | 运行日志事件，只保存在实例数据库内 |
| `agent_task_sessions`、`agent_runtime_state` | 按 Agent、按任务保存的可续接会话与运行时状态 |
| `cost_events`、`budget_policies` | 花费流水与预算策略 |
| `approvals`、`activity_log` | 审批与审计记录 |
| `routines` 及其触发器 | 例行任务；并发策略 `coalesce_if_active` / `always_enqueue` / `skip_if_active`，补跑策略 `skip_missed` / `enqueue_missed_with_cap` |

所有业务实体都带 `companyId`，路由和服务层负责校验公司边界。`AGENTS.md` 还区分了三条数据路径：首方遥测（默认开启，发往 Paperclip）、OpenTelemetry 可观测性（需运维者设置端点才生效）、运行日志（只留在本地数据库），改动时按路径决定审查级别。

依据：[packages/db/src/schema/issues.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/db/src/schema/issues.ts)、[packages/db/src/schema/heartbeat_runs.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/db/src/schema/heartbeat_runs.ts)、[packages/db/src/schema/agent_wakeup_requests.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/db/src/schema/agent_wakeup_requests.ts)、[packages/db/src/schema/routines.ts](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/packages/db/src/schema/routines.ts)、[AGENTS.md](https://github.com/paperclipai/paperclip/blob/317ed367d4e7ef3221cccab2079018534b5be560/AGENTS.md)。

## 扩展点

| 想做的事 | 方式 | 说明 |
| --- | --- | --- |
| 接入一个自己的 Agent，最快 | `process` 或 `http` 适配器 | 无需写代码；进程读 `PAPERCLIP_*` 环境变量回调 API，或由 HTTP 端点接收唤醒 |
| 接入新的 Agent 运行时 | 写一个 npm 包，导出 `createServerAdapter()` 返回 `ServerAdapterModule` | 可提供配置表单、模型列表、会话编解码。`packages/adapters/AUTHORING.md` 要求跨运行的状态只能保存在本地工作区，不能依赖 git remote |
| 给 Paperclip 加功能 | 插件：`@paperclipai/plugin-sdk` 的 `definePlugin()` + `runWorker()` | 插件以独立 worker 进程运行，通过 JSON-RPC 与宿主通信；可订阅事件、注册定时任务、数据、动作、Agent 工具、Webhook，以及仪表盘、侧栏、任务详情等 UI 插槽；宿主 API 按清单中声明的能力授权 |
| 调整 Agent 的工作方式 | 技能（skills）与指令文件 | 公司技能可从 GitHub 仓库导入并版本化；`skills/paperclip/SKILL.md` 定义了心跳协议 |
| 定期产生工作 | 例行任务 | cron、Webhook（支持 bearer、HMAC 等签名方式）、API 三种触发 |
| 换数据库 | 设置 `DATABASE_URL` | 使用外部 PostgreSQL，迁移由 `packages/db` 管理 |

插件 SDK 的 README 提醒：目前插件的 worker 和 UI 都应视为可信代码，UI 包与主应用同源运行，清单里声明的能力并不构成前端沙箱；动态安装插件更适合单节点持久化部署。
