TL;DR：Impeccable 为 AI 编程助手提供一套前端设计工作方法，并配套可执行的检测和浏览器迭代工具。当前快照包含一个主技能、24 个命令表入口和 61 条确定性检测规则。适合把“帮我美化一下”拆成可执行、可检查的设计任务。

本文解释它解决什么问题、各项能力如何配合，以及应该从哪里开始使用。

## 它解决什么问题

AI 可以写出能运行的界面，但仍可能反复采用相似的字体、卡片、渐变和布局。Impeccable 把设计判断拆成明确的观察对象和操作：检查信息层级、调整排版、降低视觉噪声、补齐空状态，或者在浏览器中比较同一个元素的多个版本。

它包含两种互补的能力。技能指导 AI 理解产品与页面目标，做有语境的设计判断；检测引擎根据程序规则识别具体问题，例如某些重复视觉套路、过小的触控目标和标题层级跳跃。规则命中是供处理的证据，不能独自判定整个产品的设计质量。

依据：[README.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/README.md)、[skill/SKILL.src.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/SKILL.src.md)。

## 项目由哪些部分组成

| 部分 | 用户得到什么 | 主要实现位置 |
| --- | --- | --- |
| 设计技能与命令 | 从分析需求到修改界面的工作步骤 | `skill/SKILL.src.md`、`skill/reference/` |
| 独立检测器 | 在终端扫描目录、HTML 或网页 URL，无需 LLM API key | `crates/detect/`、`crates/html/`、`crates/browser/` |
| 自动检测 Hook | 在支持的编程工具事件中反馈设计问题 | `crates/hook/` |
| Live 模式 | 在本地运行的页面中选择元素、生成方案、接受或丢弃方案 | `crates/live/`、`skill/scripts/live-browser*.js` |
| 浏览器扩展 | 在浏览器中使用共享的检测规则 | `extension/`、`crates/wasm/` |
| 安装与分发 | 把同一技能适配到不同编程助手 | `crates/skills/`、`scripts/lib/transformers/` |

仓库本身是技能、引擎和分发工具的源码。项目官网与服务已经位于另一个私有仓库，不能把当前仓库当成完整官网源码。

依据：[docs/ENGINE.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/docs/ENGINE.md)、[AGENTS.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/AGENTS.md)。

## 命令如何选择

不必先记住全部入口，按当前任务选择即可。

| 当前任务 | 对应命令 | 关注点 |
| --- | --- | --- |
| 第一次让 AI 理解项目 | `init` | 用户、用途、约束、产品事实 |
| 记录已有视觉体系 | `document` | 已存在的样式、组件与设计规范 |
| 实现前梳理方案 | `shape` | 任务与界面方案 |
| 看页面为什么不好用 | `critique` | 层级、清晰度、体验判断 |
| 检查技术质量 | `audit` | 可访问性、性能、响应式等 |
| 收尾打磨 | `polish` | 一致性与细节 |
| 调整视觉表达 | `bolder`、`quieter`、`distill` | 增强、降低或精简表达 |
| 改善具体维度 | `typeset`、`layout`、`colorize`、`clarify` | 字体、布局、颜色、文案 |
| 补齐交付细节 | `harden`、`adapt`、`optimize`、`onboard` | 边界状态、多设备、性能、初次使用 |
| 交互与视觉增强 | `animate`、`delight`、`overdrive` | 动效、趣味与高强度视觉效果 |
| 提炼可复用资产 | `extract` | 设计 token 和组件 |
| 对比多个版本 | `live`、`generate` | 浏览器内方案选择 |

命令表仍包含 `craft`，但技能源码已明确将其标记为普通新设计请求的弃用别名。因此，24 是该快照的命令表入口数，不表示 24 种互不重叠的工作流。开始新页面也可以直接描述需要实现的内容。

依据：[skill/SKILL.src.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/SKILL.src.md)。

## 一次典型使用过程

1. 在目标项目安装技能，再在编程助手中调用 `init`。AI 读取现有信息，补问影响决策的产品事实，写入 `PRODUCT.md`。
2. 对已有页面选择具体任务，例如 `critique landing` 分析落地页，或 `polish settings` 打磨设置页。
3. AI 读取对应工作指南，结合产品信息、已有视觉体系和页面目标完成工作。
4. 使用检测结果与实际页面观察检查修改。需要比较多个方向时，进入 Live 模式，由用户选择保留方案。

产品事实、视觉体系和单页策略分别保存，后续任务就不必把所有背景重新解释一遍。具体文件职责见《工作原理》。

## 适用范围与边界

- 适用于 AI 辅助的前端设计、新页面构建、已有界面改进和设计检查。
- 技能包含 iOS、Android 和跨平台设计指导；DOM 检测、浏览器扩展和网页 Live 功能有各自的 Web 使用边界。
- 独立检测器不需要大模型；设计分析和代码修改仍由用户所使用的编程助手完成。
- Live 需要本地源码及开发服务器或本地静态 HTML。生产站点可用 URL 检测，但不支持直接将 Live 的本地辅助服务注入线上站点来回写源码。
- 61 条规则是当前快照中的规则目录数量。本次读取并计数了 `crates/live/assets/antipatterns.json`，未把它当成 61 项运行测试都已通过。
