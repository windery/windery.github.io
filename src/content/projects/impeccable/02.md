TL;DR：在目标项目中运行 `npx impeccable install`，重载编程助手，然后调用 `impeccable init` 技能流程。先让它理解产品，再选择具体页面执行评审或修改；只想扫描文件时可以独立使用 `detect`。

本文面向使用者，覆盖最小上手流程、命令选择、检测结果和 Live 模式。下列命令依据该 commit 的 README 与源码整理，未在用户项目中执行。

## 最小上手流程

前置条件：准备一个你要改进的本地项目，并使用该仓库支持的 AI 编程助手。使用 npm 安装路径时，仓库 `package.json` 要求 Node.js 22.18.0 或更新版本；设计任务还需要编程助手自身可用。

1. 在终端进入目标项目根目录，执行：

   ```bash
   npx impeccable install
   ```

   按安装器提示选择编程助手和安装范围。预期结果是对应技能被安装；支持的助手还会获得相应 Hook 配置。首次使用可能下载固定版本的引擎。

2. 重载编程助手，使其识别新技能。按目标助手的命令形式运行初始化，例如 README 使用：

   ```text
   /impeccable init
   ```

   该仓库对 Codex 的生成配置采用 `$` 前缀，对应形式为：

   ```text
   $impeccable init
   ```

   这是编程助手中的技能调用，不是终端命令。不要把它替换成 `npx impeccable init`：当前 CLI 路由对 `init` 返回提示和非零状态。

3. 回答产品背景中的关键缺口。完成后检查项目中产生或更新的 `PRODUCT.md`，确认用户、用途、约束等事实正确。`init` 本身不创建视觉体系，也不负责生成 `DESIGN.md`。

4. 在确有设置页的项目中，用仓库示例执行一次范围明确的任务：

   ```text
   /impeccable polish settings
   ```

   在 Codex 中使用相应的 `$impeccable polish settings`。若目标页面不同，将 `settings` 换成实际页面名称。预期结果是围绕该目标进行收尾改进，并报告修改内容；具体视觉效果仍需查看页面确认。

仓库 README 还要求 Codex 用户在安装或更新后打开 `/hooks`，按工具提示批准项目 Hook；这属于该仓库记载的安装步骤，本次未验证当前客户端的实际界面。

## 三种常用场景

### 已有页面，但不知道问题在哪里

先调用 `critique`，让 AI 从信息层级和使用体验分析；需要技术质量检查时用 `audit`。例如：

```text
/impeccable critique landing
/impeccable audit blog
```

评审后再选要修改的范围。`critique`、`audit` 是 AI 工作流程，`detect` 是确定性扫描，两者覆盖的判断不同。

### 页面方向正确，只需要改一处

用目标加具体维度缩小工作范围。仓库的命令设计支持 `typeset` 处理排版、`layout` 处理布局、`clarify` 处理文案、`harden` 处理错误与边界状态。已有视觉身份应作为约束；只有明确提出重设计时才切换视觉方向。

### 从零构建页面

先完成产品初始化，然后直接描述要构建的页面，或使用 `shape` 先规划。在有图像生成能力时，项目可采用两种构建路径：先制作视觉设计稿再实现的 `comp`，或直接写代码并用方向约定检查成品的 `code`。

该偏好保存在 `.impeccable/config.json` 的 `buildPath` 字段，本机可用 `.impeccable/config.local.json` 覆盖。它是工作流设置，不应复制进 `PRODUCT.md` 充当产品事实。

依据：[skill/SKILL.src.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/SKILL.src.md)、[skill/reference/init.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/reference/init.md)。

## 独立运行检测器

在终端中，以下命令可以脱离 AI 技能使用：

```bash
npx impeccable detect src/
npx impeccable detect index.html
npx impeccable detect https://example.com
npx impeccable detect --json .
```

目录和文件应替换为项目中的真实目标；URL 示例来自 README。网页扫描需要已安装的 Chrome、Chromium 或 Edge。扫描文本文件与扫描渲染后网页可获得的信息不同，结果不能当成完全等价。

| 退出码 | 含义 | 如何理解 |
| --- | --- | --- |
| `0` | 扫描完成，没有主要问题 | 不等于界面质量或无障碍全部合格 |
| `2` | 扫描完成，存在主要问题 | 可以在 CI 中作为需要处理的结果 |
| `1` | 至少一个目标未能扫描 | 多目标扫描中，运行失败优先于问题发现 |

面向人的诊断输出到 stderr；`--json` 将机器可读结果输出到 stdout。保存报告可使用：

```bash
npx impeccable detect src/ 2> findings.txt
npx impeccable detect --json . > findings.json
```

默认检测会读取共享配置和本地配置中的忽略项。需要排除明确的品牌例外时，可以按 README 示例记录理由：

```bash
npx impeccable ignores add-value overused-font Inter --reason "Brand font"
npx impeccable ignores list
```

这表示声明已知例外，不能替代对命中项的判断。需要忽略项目配置进行原始扫描时，使用 `npx impeccable detect --no-config src/`。

依据：[README.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/README.md)、[crates/detect/src/cli.rs](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/crates/detect/src/cli.rs)。

## 用 Live 比较多个设计版本

1. 准备可在本地运行的 Web 项目。由初始化或 Live 设置流程确定开发命令、入口与配置。
2. 在编程助手中调用 `/impeccable live`，按当前助手前缀调整。引擎启动辅助服务，页面显示实时操作界面。
3. 在页面选中元素，给出调整方向并触发生成。AI 根据元素与项目上下文写出候选版本，浏览器加载预览。
4. 比较结果后接受或丢弃。接受时将选中的方案合入源码；丢弃时按对应路径清理临时方案。

也可以用 `generate` 描述要比较的元素，省去手动点选。Live 具体的源码定位和回写行为取决于框架适配路径，原理见《工作原理》。

Live 的辅助服务不是项目的开发服务器。生产 URL 检测也不是 Live 编辑：线上检查不会自动给你一个可回写的本地项目。

依据：[skill/reference/live.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/reference/live.md)、[skill/reference/generate.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/reference/generate.md)、[README.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/README.md)。

## 更新与已有项目接入

更新已安装的版本使用：

```bash
npx impeccable update
```

如果项目已有视觉体系，调用 `document` 可以从现有实现整理 `DESIGN.md`。不要因为缺少这个文件，就让 AI 将成熟界面当成全新项目重做。产品事实过期时才更新 `PRODUCT.md` 中对应内容；视觉变更在视觉体系与页面 brief 中维护。

依据：[README.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/README.md)、[skill/SKILL.src.md](https://github.com/pbakaus/impeccable/blob/114ea1d3838fca73b253af45f873b9c4f5f213c8/skill/SKILL.src.md)。
