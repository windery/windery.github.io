TL;DR：普通用户直接装 Release 里的桌面安装包，打开 Voice cloning、按提示下载默认模型，就能生成第一段语音。开发者从源码运行需要 Bun 和 uv，依次执行 `bun install`、`bun run setup:api`、`bun run dev`。后端默认监听 `127.0.0.1:3900`，可以用 OpenAI 兼容的 `/v1/audio/speech` 或 MCP 调用；Docker 部署必须先设置 `OMNIVOICE_API_KEY`。

本文的命令都依据 README、`docs/` 和源码整理，未在本机实际执行。各工作区能做什么见《项目概览》，后端内部流程见《工作原理》。

## 前置依赖

| 用途 | 需要什么 | 依据 |
| --- | --- | --- |
| 运行硬件 | 推荐 6 GB 以上显存的 NVIDIA GPU，或 macOS 13.3 及以上的 Apple Silicon；没有 GPU 也能用 CPU 运行，但较慢 | [docs/engines/omnivoice.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/engines/omnivoice.md)、[docs/install/macos.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/install/macos.md) |

FFmpeg 不需要预先安装：首次运行向导会在用户确认后下载固定版本；已有 FFmpeg 时可以用 `FFMPEG_PATH` / `FFPROBE_PATH` 指定路径。

## 安装与启动

### 桌面安装包（推荐）

1. 从 [Releases](https://github.com/debpalash/VoiceStudio/releases/latest) 下载对应平台的安装包：macOS `.dmg`、Windows `.exe`、Linux `.AppImage` 或 `.deb`。
2. 或者使用官方安装脚本（macOS / Linux）：

   ```sh
   curl -fsSL https://voicestudio.sh/install | sh
   # 指定版本
   curl -fsSL https://voicestudio.sh/install | sh -s -- --version X.Y.Z
   # 卸载应用，保留数据
   curl -fsSL https://voicestudio.sh/install | sh -s -- --uninstall
   ```

   Windows 在 PowerShell 中运行 `irm https://voicestudio.sh/install | iex`。脚本源码就是仓库里的 `scripts/install.sh` 和 `scripts/install.ps1`，介意管道直接执行的话可以先读一遍再运行。
3. 打开应用，按首次运行向导准备 Python 运行时和模型。

升级时安装器会保留设置、项目和模型。旧的 Tauri 版本不会自动迁移到 Electron，需要按 [docs/electron-migration.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/electron-migration.md) 单独安装。

### 从源码运行

```bash
git clone https://github.com/debpalash/VoiceStudio.git
cd VoiceStudio
bun install
bun run setup:api   # uv sync --locked 安装 Python 依赖，再运行 scripts/setup.py
bun run dev         # 启动 Electron（主进程 + preload + 渲染层热更新）
```

`setup:api` 会自动选择 PyTorch 变体：没有 NVIDIA 驱动的 Linux / Windows 装 CPU 版，macOS 用原生 wheel。也可以手动指定：

```sh
OMNIVOICE_TORCH_VARIANT=cpu bun run setup:api   # 可选 cpu / cuda / rocm（rocm 仅 Linux）
```

Electron 启动时会先探测 `http://127.0.0.1:3900`：已有后端就直接连上，没有就用准备好的 `.venv` 启动 Python 后端并持续守护（崩溃后重启，退出码 78 表示端口被占用）。第一次启动 Electron 时还要联网下载 Electron 二进制。

依据：[electron/README.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/electron/README.md)。

### 只跑后端

不需要桌面界面时（例如只给脚本或 Agent 用），可以单独启动后端：

```bash
bun run dev:api                     # scripts/dev-backend.mjs，经 uv 启动 uvicorn
# 或
uv run python backend/main.py       # 默认 127.0.0.1:3900
```

后端启动约 1 秒就会绑定端口，但 torch 导入、路由注册、数据库初始化在后台进行。这段时间里 `/health` 返回 503 和当前步骤，就绪后返回 `{"status":"ok", ...}`。脚本在 `/health` 返回 200 之前不要发业务请求。

`bun run dev:web` 会同时启动后端和浏览器版 UI（前端开发服务器端口 3901）。

### Docker

Docker 模式下无法确认浏览器是否来自本机，所以必须先生成管理员密钥：

```bash
export OMNIVOICE_API_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"

docker run -d --name omnivoice \
  -p 127.0.0.1:3900:3900 \
  -e OMNIVOICE_API_KEY="$OMNIVOICE_API_KEY" \
  -v omnivoice-data:/app/omnivoice_data \
  ghcr.io/debpalash/voicestudio:stable
```

NVIDIA GPU 加 `--gpus all`；AMD 改用 `:stable-rocm` 镜像，并加 `--device /dev/kfd --device /dev/dri`。也可以用 compose：`docker compose -f deploy/docker-compose.yml --profile cpu up`（profile 还有 `gpu`、`rocm`、`worker-gpu`、`worker-rocm`）。启动后访问 `http://localhost:3900`，网页会要求输入这个密钥，并换成短期会话。

镜像标签：`:stable` 是最新正式版，`:latest` 是 main 分支的滚动预览版，生产环境应固定 `:stable` 或具体版本号。

## 配置要点

设置有三个来源，优先级从高到低是：真实环境变量、桌面端 Settings 写入的 `prefs.json`、代码默认值。Settings 面板还会把需要持久化的环境变量写进 `~/.config/omnivoice/env`。

**数据目录**（声音、生成结果、配音任务、数据库都在这里）：

| 平台 | 默认位置 |
| --- | --- |
| macOS | `~/Library/Application Support/OmniVoice` |
| Windows | `%APPDATA%\OmniVoice` |
| Linux | `~/.omnivoice` |
| 任意平台 | 设置 `OMNIVOICE_DATA_DIR` 后以它为准 |

**常用环境变量**：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `OMNIVOICE_PORT` | 后端端口 | `3900` |
| `OMNIVOICE_BIND_HOST` | 监听地址 | `127.0.0.1`（后端不带鉴权，所以默认只监听本机） |
| `OMNIVOICE_API_KEY` | 非本机 HTTP / WebSocket 请求要带的 Bearer 密钥；Docker 必填 | 未设置 |
| `OMNIVOICE_TTS_BACKEND` | 固定使用某个 TTS 引擎 id，优先于 Settings 中的选择 | `omnivoice` |
| `HF_TOKEN` | 下载受限模型（如 pyannote、PocketTTS）用 | 未设置 |
| `OMNIVOICE_TORCH_VARIANT` | 源码安装时选择 PyTorch 变体 | 自动检测 |
| `OMNIVOICE_GPU_WORKERS` | GPU 并发数（1–16） | CUDA/ROCm 按“空闲显存 ÷ 5 GB”计算，最多 4；MPS/CPU 为 1 |
| `OMNIVOICE_GENERATE_TIMEOUT_S` / `OMNIVOICE_CPU_GENERATE_TIMEOUT_S` | 单次生成的时间预算 | 300 s / 600 s |
| `OMNIVOICE_MCP_DISABLE` | 设为 `1` 不挂载 `/mcp` | 挂载 |
| `OMNIVOICE_ANALYTICS_DISABLED` | 设为 `1` 彻底关闭产品分析 | 未设置（仍需用户在首次运行时同意才会上报） |

可选引擎多数通过“指向上游仓库目录”的变量启用，例如 `OMNIVOICE_INDEXTTS_DIR`、`OMNIVOICE_MOSS_TTS_V15_DIR`、`OMNIVOICE_DOTS_TTS_DIR`、`OMNIVOICE_CONFUCIUS4_TTS_DIR`。完整的安装提示在 [backend/services/tts_backend.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/services/tts_backend.py) 的 `_INSTALL_HINTS` 和 `_SETUP_SNIPPETS` 里，应用的 Model Catalogue 中也会显示。

依据：[backend/core/config.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/core/config.py)、[backend/core/prefs.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/core/prefs.py)、[backend/services/model_manager.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/services/model_manager.py)、[docs/api-auth.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/api-auth.md)。

## 生成第一段语音

### 在桌面端

1. 打开 **Voice cloning**。
2. 选择一个已有声音（应用自带演示声音），或者添加一段干净的参考录音。
3. 输入文本，点击生成。
4. 如果默认模型还没安装，按提示下载；之后同一模型不再下载。

生成结果出现在编辑区下方，可以播放和导出；最近的生成记录在左侧边栏。

### 用 OpenAI 兼容接口

后端运行后，在本机可以直接调用（本机请求不需要密钥）：

```bash
curl http://127.0.0.1:3900/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{"model":"omnivoice","voice":"default","input":"你好，这是本地生成的语音。","response_format":"wav"}' \
  --output speech.wav
```

字段含义见 [backend/api/routers/openai_compat.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/api/routers/openai_compat.py) 中的 `SpeechRequest`：

- `model` 填引擎 id；`tts-1`、`gpt-4o-mini-tts` 等 OpenAI 模型名会被当成当前激活引擎的别名。
- `voice` 可以填声音档案的 ID 或名称；`alloy` 等 OpenAI 声音名会映射到引擎默认声音。
- `response_format` 支持 `mp3`、`opus`、`aac`、`flac`、`wav`、`pcm`，默认 `mp3`。
- `input` 最长 4096 字符。

预期结果：当前目录得到 `speech.wav`。如果默认模型还没下载，第一次调用会在后端的时间预算内先下载约 2.3 GB 权重，耗时较长；文档建议先在首次运行向导或 Model Catalogue 里装好模型。

用 OpenAI Python SDK 时，把 `base_url` 指向 `http://127.0.0.1:3900/v1`，没设密钥时 `api_key` 填任意字符串即可。后端设置了 `OMNIVOICE_API_KEY` 时，远程请求要带 `Authorization: Bearer <key>`，并且应走 HTTPS 或 Tailscale 等加密通道。

桌面端自己调用的是原生接口 `POST /generate`（multipart 表单，字段有 `text`、`language`、`ref_audio`、`profile_id`、`engine`、`stream` 等），响应体是 WAV，`X-Audio-Id`、`X-Audio-Duration` 等响应头携带元数据。

### 转写与 MCP

转写同样走 OpenAI 兼容接口 `POST /v1/audio/transcriptions`。仓库还带了一个无依赖的命令行客户端：

```bash
python -m backend.speech_client capabilities
python -m backend.speech_client transcribe recording.wav
```

让 Agent 使用时，把 MCP 客户端指向 `http://127.0.0.1:3900/mcp/`（保留结尾斜杠）。Codex CLI 的配置示例：

```toml
[mcp_servers.voicestudio]
url = "http://127.0.0.1:3900/mcp/"
http_headers = { "X-OmniVoice-Client-Id" = "codex-cli" }
```

`X-OmniVoice-Client-Id` 用来给不同 Agent 绑定不同的声音。工具包括 `generate_speech`、`clone_voice`、`design_voice`、`transcribe`、`list_voices`、`check_health` 等。默认情况下音频以 base64 内联返回，比较占 Agent 上下文；设置 `OMNIVOICE_MCP_OUTPUT_MODE=files` 和 `OMNIVOICE_MCP_BASE_PATH` 后改为写文件、返回路径。只支持 stdio 的客户端用 `python -m backend.mcp_shim`。

依据：[docs/speech-platform.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/speech-platform.md)、[docs/mcp.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/mcp.md)、[backend/api/routers/generation.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/api/routers/generation.py)。

## 常见问题

出问题时先跑一遍自检。应用里是 **Settings → About → Run self-check**，命令行如下：

```bash
uv run python backend/main.py --diagnose          # 检查设备、ffmpeg、HF Token、磁盘、内存、引擎等，失败时退出码为 1
uv run python backend/main.py --diagnose --deep   # 额外加载当前引擎并合成一段测试语音
```

| 现象 | 处理 |
| --- | --- |
| 配音时报 HF 401，或说话人分离退化成单人 | `pyannote/speaker-diarization-3.1` 是受限模型：在 Settings → API Keys 填 HF Token，再到模型页点击同意协议 |
| 4 GB 显卡生成极慢，最后超时 | 低于默认引擎的 6 GB 建议下限，显存被换页到内存。改用 `omnivoice-gguf` 量化引擎或 CPU |
| 端口 3900 被占用 | 桌面端会自动换一个回环端口；手动启动时设置 `OMNIVOICE_PORT` |
| 8 GB 显卡并发克隆导致后端崩溃 | 源码按每个任务 5 GB 显存计算并发数，这类显卡默认只开 1 个 worker；不要手动把 `OMNIVOICE_GPU_WORKERS` 调大 |
| 首次安装在受限网络下失败 | 后端会探测 huggingface.co 和 hf-mirror.com 哪个可达；GitHub / PyPI 被墙时参见排障文档对应章节 |
| RTX 50 系（sm_120）启动时崩溃 | 排障文档有专门章节，涉及 torch / torchaudio 版本 |
| Docker 中改不了设置、跑不了诊断 | 容器的 NAT 让后端无法确认请求来自本机，设置、诊断等管理操作必须带 `OMNIVOICE_API_KEY`。compose 文件在这个变量缺失时直接拒绝启动；变量设为空白字符串时，server 模式的后端也会拒绝启动 |
| Apple Silicon 想用 Docker | 容器访问不到 Mac 的 GPU；用原生 macOS 应用 |
| 提交 issue | Settings → About → Save diagnostic bundle 生成 zip，其中家目录路径和 Token 形式的字符串已脱敏 |

依据：[docs/install/troubleshooting.md](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/docs/install/troubleshooting.md)、[backend/services/model_manager.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/services/model_manager.py)、[backend/main.py](https://github.com/debpalash/VoiceStudio/blob/06c6e077f0fc35149efefc3561e9be5ae835d916/backend/main.py)。
