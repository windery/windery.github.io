TL;DR：开源的终端编程 agent，支持几十家模型服务商。客户端与服务端分离，会话存在 SQLite 里；agent、命令、工具、插件、MCP 和 skills 都可以用文件扩展，并兼容 Claude Code 的 CLAUDE.md 和 skills 目录。本文基于 2026-10-02 的提交 `108b988`（包版本 1.18.34），MIT 许可证。

## 它解决什么问题

Claude Code 好用，但它是闭源的，只能接 Claude 模型。opencode 做的是同一类工具：在终端里和 agent 对话，让它读代码、改代码、跑命令。不同之处在于：

- **不绑定模型。** 通过 Vercel 的 AI SDK 和 models.dev 的模型目录，可以接 Anthropic、OpenAI、Google、各家云平台、本地模型以及任何兼容 OpenAI 接口的服务。
- **源码公开。** agent 怎么拼系统提示、怎么压缩上下文、怎么检查权限，都能直接读到。这也是“Vibe Coding 与 Agent 原理”课程第五部分选它来通读的原因。
- **可以用文件扩展。** 自定义 agent、命令、工具、插件都是放在 `.opencode/` 下的文件，不用改源码。

它在课程的 [第 24 课](/courses/ai-dev/24/) 到 [第 27 课](/courses/ai-dev/27/) 中逐模块精读，[第 23 课](/courses/ai-dev/23/) 是为读它准备的 TypeScript 速成。

## 仓库结构

仓库是一个 Bun 管理的 TypeScript monorepo，大量使用 [Effect](https://effect.website/) 库。`packages/` 下有三十多个包，最重要的几个：

| 包 | 作用 |
| --- | --- |
| `packages/opencode` | 命令行入口、HTTP 服务端、会话与主循环、工具、权限、配置。发布到 npm 的 `opencode-ai` |
| `packages/tui` | 终端界面，是服务端的一个客户端 |
| `packages/app`、`packages/desktop` | 网页版和桌面版界面 |
| `packages/sdk` | 根据服务端 OpenAPI 生成的 JavaScript SDK（`@opencode-ai/sdk`） |
| `packages/plugin` | 插件接口和自定义工具的辅助函数（`@opencode-ai/plugin`） |
| `packages/core`、`packages/schema` | 共享的数据结构、数据库表；`core` 里还有一套正在重写中的 V2 会话实现 |
| `packages/web` | 官网和文档，`src/content/docs/` 下是全部文档 |

读源码时要注意新旧两套实现并存：命令行和终端界面实际运行的是 `packages/opencode/src/session/` 下的 V1；`packages/core/src/session/` 是 V2，替换条件写在 `specs/v2/session.md` 里。

## 核心设计

**客户端与服务端分离。** 会话、主循环、工具执行都在服务端。直接运行 `opencode` 时，服务端跑在一个 Bun Worker 线程里，终端界面通过一个内部的 fetch 和它通信；`opencode serve` 单独启动服务端，网页版、桌面版、IDE 插件和 SDK 都走同一套 HTTP 接口。

**一个主循环，多个 agent。** `session/prompt.ts` 的 `runLoop` 是 agent 循环：每一步从数据库重新加载历史，拼系统提示，调用模型，执行工具，直到模型不再调用工具。agent 只是一份配置（提示词、模型、权限、步数上限），内置的 build、plan、general、explore，以及内部使用的 compaction、title、summary 都跑在同一个循环上。

**会话是持久化的事件流。** 消息拆成 part（文本、推理、工具调用、步骤开始和结束、快照、补丁、压缩等）存进 SQLite。压缩不删除历史，只改变发给模型的部分；子 agent 是一个带 `parent_id` 的子会话。

**权限是规则列表。** 每条规则是“权限名 + 模式 + 动作”，最后一条匹配的规则生效。默认几乎全部允许，只有读 `.env`、访问项目外的目录、疑似死循环时会询问。没有沙箱。

**文件改动用 git 快照记录。** 每一步前后对工作目录拍快照（一个独立的 git 目录，不影响项目自己的仓库），所以 `/undo` 能撤销包括 bash 命令在内的所有文件改动。

## 扩展点

| 扩展点 | 位置 | 说明 |
| --- | --- | --- |
| 项目说明 | `AGENTS.md`（没有时读 `CLAUDE.md`） | 每一步都放进系统提示；子目录里的在读到相关文件时附加 |
| 自定义 agent | `.opencode/agent/*.md` 或配置 `agent` | frontmatter 是配置，正文是提示词 |
| 自定义命令 | `.opencode/command/*.md` 或配置 `command` | 提示词模板，支持 `$ARGUMENTS`、`$1` 和 `` !`命令` `` |
| 自定义工具 | `.opencode/tool/*.ts` | 用 `@opencode-ai/plugin` 的 `tool()` 定义 |
| 插件 | `.opencode/plugin/*.ts` 或配置 `plugin`（npm 包） | 一组钩子函数，在同一进程里运行 |
| MCP | 配置 `mcp` | 本地（stdio）和远程（Streamable HTTP，回退 SSE），支持 OAuth |
| Skills | `.opencode/skills/`、`.claude/skills/`、`.agents/skills/` 等 | 系统提示里只列名字和描述，需要时用 skill 工具加载 |

全局的同名目录在 `~/.config/opencode/` 下。

## 适用范围与边界

- 它是**通用的**编程 agent，系统提示按模型挑选（`session/prompt/` 下有 anthropic、gpt、gemini 等多份），但不会针对某一家模型做 Claude Code 那样深的优化。
- 默认权限很宽松，又没有沙箱。在重要的仓库里使用前，应该先在 `opencode.json` 里收紧 `edit` 和 `bash` 的规则。
- 项目迭代很快，版本号更新频繁，内部实现（尤其是 V1 到 V2 的迁移）还在变化。读源码时以具体的提交为准，文档和类型声明也偶尔和代码不一致。
