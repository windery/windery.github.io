TL;DR：安装后先用 `providers login` 配好模型；在 `opencode.json` 里收紧 edit 和 bash 的权限，注意最后一条匹配的规则生效；项目说明写在 `AGENTS.md`；常用的审查、提交流程写成自定义 agent 和命令；非交互运行时需要询问的操作会被自动拒绝。本文的配置写法都对照提交 `108b988` 的源码核对过，其中权限、agent、命令、MCP 的例子在课程的实验包里运行过。

## 安装与登录

```sh
npm i -g opencode-ai@latest      # 或者 brew install anomalyco/tap/opencode
opencode providers login         # 选择服务商并登录，别名 opencode auth login
opencode models                  # 列出可用的模型
```

在项目目录下运行 `opencode` 进入终端界面。常用的斜杠命令：`/models` 切换模型，`/new` 开新会话，`/compact` 压缩上下文，`/undo` 和 `/redo` 撤销和重做，`/sessions` 切换会话，`/init` 让 agent 为项目生成 `AGENTS.md`。Tab 在 build 和 plan 两个 agent 之间切换。

## 配置文件放在哪里

配置按下面的顺序合并，后面的覆盖前面的：

1. 全局：`~/.config/opencode/opencode.json`
2. 环境变量 `OPENCODE_CONFIG` 指定的文件
3. 项目根目录的 `opencode.json`
4. 项目里的 `.opencode/` 目录（以及其中的 agent、command、tool、plugin 等子目录）
5. 环境变量 `OPENCODE_CONFIG_CONTENT` 里的 JSON

一个常用的项目配置：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
  "instructions": ["docs/coding-style.md"],
  "permission": {
    "edit": "ask",
    "bash": {
      "*": "ask",
      "git status*": "allow",
      "git diff*": "allow",
      "mvn -q test*": "allow",
      "rm *": "deny",
      "git push*": "deny"
    }
  }
}
```

`$schema` 让编辑器能补全和校验字段。`instructions` 把额外的文件加进系统提示，支持 glob。

## 权限：顺序很重要

opencode 的权限规则是**最后一条匹配的生效**，这和 Claude Code 的“deny 优先”不同。上面的 bash 规则把 `"*": "ask"` 放在最前面，后面的具体规则才能覆盖它。如果写反了：

```json
"bash": { "rm *": "deny", "*": "allow" }
```

`rm hello.txt` 先匹配 `rm *`，再匹配 `*`，最后一条是 allow，于是被允许执行。这个例子在课程 [第 25 课](/courses/ai-dev/25/) 的实验里真的删掉了文件。

另外几点：

- **默认几乎全部允许。** 不写 `permission` 时，编辑和命令都不询问；只有读 `.env` 类文件、访问项目外的目录、同一回复里连续三次相同的工具调用会询问。
- **复合命令逐段检查。** `ls && rm a.txt` 会被拆开，任何一段被拒绝，整条都不执行。
- **整体禁止的工具对模型隐藏。** 某个工具的最后一条匹配规则是 `"*": "deny"` 时，模型看不到这个工具。
- **规则拒绝和用户拒绝不一样。** 规则拒绝时模型收到错误，可以换个做法继续；用户在询问时拒绝，整个循环停止。

## 项目说明：AGENTS.md

opencode 读项目根目录（以及向上到仓库根目录的每一级）的 `AGENTS.md`；只要找到了 AGENTS.md，就不再读 CLAUDE.md。全局说明放在 `~/.config/opencode/AGENTS.md`，没有的话会读 `~/.claude/CLAUDE.md`。

同时使用 opencode 和 Claude Code 的项目，可以只维护 `AGENTS.md`，在 `CLAUDE.md` 里写一行 `@AGENTS.md` 导入它。

子目录里的 `AGENTS.md` 不会一开始就加载，而是在 agent 读到那个目录下的文件时，附加到工具结果里。它会随上下文压缩一起被总结掉，所以必须长期遵守的约定要写在根目录。

不想让 opencode 读 Claude Code 的 `~/.claude/CLAUDE.md` 和 `~/.claude/skills/`，设置环境变量 `OPENCODE_DISABLE_CLAUDE_CODE=1`。

## 自定义 agent

`.opencode/agent/reviewer.md`：

```markdown
---
description: 审查代码改动，只读，不修改任何文件。用户要求审查时使用。
mode: subagent
permission:
  edit: deny
  bash: { "*": "deny", "git diff*": "allow" }
  webfetch: deny
---
你是一个代码审查员。只指出问题，不要修改文件。每个问题给出文件和行号。
```

- `mode: subagent` 表示只能被主 agent 通过 task 工具调用；`primary` 可以用 Tab 切换到；`all` 两者都可以。
- `description` 会出现在 task 工具的描述里，主 agent 靠它决定什么时候用。
- 工具由权限决定：被整体禁止的工具不出现。上面 bash 的两条规则顺序如果反过来，最后一条是 `"*": "deny"`，bash 会整个消失。
- 还可以写 `model`、`temperature`、`steps`（步数上限）等字段。`opencode agent create` 可以交互式地生成这样的文件。

## 自定义命令

`.opencode/command/review.md`：

```markdown
---
description: 审查一个文件
agent: reviewer
subtask: true
---
请审查 $ARGUMENTS。

最近一次提交：!`git log --oneline -1`
```

在终端界面输入 `/review src/Main.java` 运行。发给模型之前，`$ARGUMENTS` 换成参数，`` !`…` `` 换成命令的输出。`subtask: true`（或者 `agent` 指定的是一个 subagent）时，命令在子会话里执行，不占用主会话的上下文。

## MCP

```json
{
  "mcp": {
    "time": { "type": "local", "command": ["python3", "/path/to/mcp-time.py"] },
    "docs": { "type": "remote", "url": "https://example.com/mcp" }
  },
  "permission": { "docs_*": "ask" }
}
```

MCP 工具的名字是“服务端名_工具名”，权限名也是它，所以可以用 `docs_*` 控制一整个服务端。服务端在初始化时返回的说明会放进系统提示。需要 OAuth 的远程服务端用 `opencode mcp auth <名字>` 登录。

## 上下文与会话

- 压缩是自动的：上一步的 token 用量超过“上下文窗口减去最大输出长度”时触发。压缩后保留最近几轮的原文，预算是可用空间的四分之一，最多 15000 token；用 `compaction.preserve_recent_tokens` 和 `compaction.tail_turns` 调整。
- `"compaction": { "prune": true }` 打开修剪：较早的工具输出被替换成一行占位文字，比压缩便宜。
- 会话存在 `~/.local/share/opencode/opencode.db`。`opencode session list` 列出会话，`opencode export <id>` 导出成 JSON，`opencode import <文件>` 导入。

## 非交互运行

```sh
opencode run "给 OrderService 补上单元测试"
opencode run --continue "再补一个边界情况"
opencode run --command review src/Main.java
```

`opencode run` 适合脚本和 CI。要注意：**非交互模式下，所有需要询问的权限都会被自动拒绝**，而用户拒绝会让循环停止。所以在 CI 里使用时，要事先把需要的命令写成 allow 规则，否则 agent 第一次碰到 ask 就会停下来。

## 常见坑

- **规则顺序写反。** 最常见的错误，见上文。写完后用一个无害的命令试一下。
- **以为有沙箱。** 没有。bash 命令以你的用户身份直接执行。
- **`/undo` 需要 git。** 快照基于 git，项目不是 git 仓库时无法撤销；`.gitignore` 里的文件也不在快照范围内。
- **插件拿到的数据和类型声明不完全一致。** 例如 MCP 工具的 `tool.execute.after` 钩子拿到的是 MCP 原始的 `content`，没有 `output` 字段。插件里的异常会让工具调用失败，要写得防御一些。
- **文档和代码不一致。** 例如文档说 `.env` 默认拒绝，代码里是询问。有疑问时以源码为准。
