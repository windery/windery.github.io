TL;DR：这个仓库把“流程入口”和“复用方法”分开，用文件引用传递上下文，把追问做成共享原语，再把规格拆成有阻塞边的任务图。执行来自宿主 Agent，仓库负责提供可检查的步骤与完成条件。

## 从技能文件到可调用能力

每个技能以 SKILL.md 为入口，前置元数据描述名称与用途，正文定义步骤、判断标准和需要读取的参考材料。`agents/openai.yaml` 可以进一步声明界面信息和调用策略。

用户入口设置 `disable-model-invocation: true`，例如 ask-matt、to-spec、implement；模型可调用的技能则保留触发描述，比如 tdd 的描述写明“用户提到 red-green-refactor 或想要集成测试时使用”。这条描述就是 Agent 自动匹配的依据。

仓库还规定了一条组合规则：用户入口可以调用模型可调用的技能，但不调用另一个用户入口。所以 implement 内部会驱动 tdd 和 code-review，而 to-spec 不会替你启动 to-tickets。

插件分发由 `.claude-plugin/plugin.json` 显式列出技能目录。“源码目录”“插件清单”和“本次可调用的技能”是三个层次，不能只靠目录总数判断安装结果。

## 上下文引用如何控制阅读范围

writing-for-agents 把引用看成行为路由：一句话不仅说明材料在哪，还要说明什么情况下读它。共同约束留在入口，某个分支才需要的格式或细则放在参考文件。

例如 setup-matt-pocock-skills 的入口保持简短，GitHub、GitLab、本地文件三种 tracker 各有一份模板，选定哪种才读哪份；tdd 的 `mocking.md` 和 `tests.md` 也只在对应判断时被引用。

关键不只是减少文字。若引用没有说明触发条件，Agent 可能在真正需要时没读到它；若所有细节都塞进入口，执行步骤又容易被淹没。

## 追问如何成为共享原语

grilling 是一个模型可调用的技能，只做一件事：一轮一轮地追问，维护一个尚未解决的问题“前沿”，直到设计树的每个分支都有答案。它规定事实是 Agent 的责任，决策是用户的责任。

grill-me 和 grill-with-docs 是它的两个具名入口，区别只在有没有把结论写进 `GLOSSARY.md` 和 ADR。triage、wayfinder、improve-codebase-architecture 也在内部运行它。把访谈抽成原语，意味着改一次提问方式，所有流程同时受益。

## 任务图如何推动实现

to-tickets 要求每张票描述一条完整、可验证的行为，并声明它被哪些票阻塞。本地 tracker 上阻塞关系是票文件里的文字，真实 tracker 上则是原生的 blocking 链接。没有未完成阻塞项的票构成当前可执行的“前沿”。

implement-spec 按这个前沿安排实现。源码规定每个实现者子代理在自己的 worktree 和分支上工作，开始前确认 worktree 基于集成分支，完成后合回集成分支；一张票完成，新的票可能解除阻塞，于是可以并行推进。最后对整条集成分支跑一次 code-review。

这种方式表达的是实际依赖，而不是把编号误当成严格线性顺序。

## 测试、诊断与审查负责不同反馈

tdd 围绕已约定的公开接口验证行为：先让测试失败，再实现足够让它通过的代码，每次只推进一个切片。源码明确写着“重构不属于这个循环”，它属于审查阶段。

diagnosing-bugs 在动手前先要求一条能在这个 bug 上变红的命令。没有这条反馈回路就不允许提出假设。之后才是最小化、假设、埋点、修复、回归测试；如果复盘发现根本没有合适的接缝来锁住 bug，它会把问题移交给 improve-codebase-architecture。

code-review 从固定 Git 基点开始，用两个并行子代理分别检查工程规范与需求符合度，互不污染。规范正确并不保证做对需求；需求满足也不保证遵守项目约定。分开给出结论，可以保留两种独立信号。

这解释了为什么仓库强调具体接口、真实 diff、规格与可观察结果：它们为 Agent 提供外部反馈，降低对文字自评的依赖。

## 两套词汇为什么是共享依赖

domain-modeling 维护领域词汇：挑战模糊的术语，拆开一词多义，把难以回退的决定记成 ADR。拆票、测试、变量命名都用同一套词，一个准确的领域词能把一长串描述压缩成共同理解。

codebase-design 维护另一套词汇，关于模块的形状：模块、接口、深度、接缝、适配器、局部性。tdd 和 improve-codebase-architecture 都用它来讨论“一个小接口后面放多少行为”。

这两套词汇的收益依赖持续维护。术语文件过时，或者技能读到了错误项目的规则，效果都会打折；所以配置必须从当前仓库发现，更新也要保留项目已有约定。
