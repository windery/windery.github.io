TL;DR：先选择一种安装方式，再对目标项目运行 setup-matt-pocock-skills。后续按“需要澄清、需要形成规格、需要实现还是需要检查”选择技能，不必每次走完整条流程。

## 最小安装与调用

README 为 Codex 等 Agent 提供的安装方式是：

```sh
npx skills@latest add mattpocock/skills
```

安装器会让你选择技能和目标 Agent。准备使用工程流程时，应包含 `setup-matt-pocock-skills`。本次阅读核对了这条文档命令，没有重新安装本机已有技能。

在目标项目里发起：

```text
使用 setup-matt-pocock-skills 配置这个项目。
```

预期产出是项目指令中的 Agent skills 入口，以及 `docs/agents/` 下关于问题跟踪、领域文档和适用时的分诊标签说明。配置会先查看现状，再展示拟写入内容，保留已有项目规则。

## 初始化究竟配置什么

| 配置 | 为什么需要 |
| --- | --- |
| 问题跟踪位置 | 后续技能要知道往 GitHub、GitLab 还是本地 Markdown 写票 |
| 分诊标签 | triage 要把不同状态映射成该项目真实使用的标签 |
| 领域文档位置 | 使用统一术语，并找到已有 ADR 决策记录 |

最新源码以 `GLOSSARY.md` 保存领域词汇。较早安装版本可能采用 `CONTEXT.md`，因此阅读旧项目时应先看它自己的配置，不能仅因文件名不同就重建一套。

## 按当前问题选择入口

```text
需求还不清楚 → grill-with-docs
不知道哪个技能合适 → ask-matt
讨论已足够清楚 → to-spec
规格需要变成可执行任务 → to-tickets
实现一组工作 → implement
按依赖图完成整份规格 → implement-spec
```

这是一张选择表，不是强制流水线。小修改不必先创建完整项目规划；大的实现则需要真实的规格、阻塞关系与测试边界。

测试先行可以直接表达为“使用 tdd 为这个行为建立测试和实现”。本版本的 tdd 要求先约定测试的公开接口，再逐个行为做失败测试与最小实现，不先批量写全部测试。

## 学习与交接

想跨多次会话学习一个主题时使用 teach，并给出具体学习目的。它会在工作区保存学习状态和独立 HTML 课程。想把当前工作交给下一次会话时使用 handoff，目标是保存继续工作需要的上下文。

技能文件中的调用写法因宿主而异：Claude Code 文档常用斜杠命令；在其他支持技能的 Agent 中，可以点名对应技能。能否自动匹配则取决于当前安装与宿主支持。

## 插件与可编辑安装的区别

README 将 Claude Code 插件作为受管理的整包安装，将 skills 安装作为可以自行修改文件的方式，并提醒不要两种方式同时装出重复技能。仓库的 `scripts/link-skills.sh` 标为维护者开发工具，不能当成普通安装指南使用。

本次在源码目录运行版本核验，得到 `plugin.json version is 1.2.3 (already in sync)`。这个结果只证明插件与包版本一致，不代表所有技能流程都已端到端执行。
