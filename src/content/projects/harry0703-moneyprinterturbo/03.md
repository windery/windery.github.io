TL;DR：WebUI、API、CLI 三个入口都把参数整理成同一个 `VideoParams`，交给 `app/services/task.py` 的 `start()`。这条流水线按“预检 → 文案 → 关键词 → 配音 → 字幕 → 素材 → 合成”的顺序执行，每一步调用 `llm`、`voice`、`subtitle`、`material`、`video` 中的一个服务模块，并把进度写入可替换的状态后端（内存或 Redis）。Provider 差异封装在各服务模块内部，流水线只关心每个阶段的输入和产物。

本文按一次任务的执行顺序说明各阶段做什么、模块之间如何调用、状态和文件存在哪里，以及想扩展时应该改哪里。

## 入口与模块分层

| 层次 | 职责 | 主要文件 |
| --- | --- | --- |
| 入口 | 收集参数，构造 `VideoParams` | `webui/Main.py`、`cli.py`、`main.py` → `app/asgi.py` → `app/router.py` |
| 接口层 | HTTP 路由、鉴权、参数校验、任务入队 | `app/controllers/v1/video.py`、`app/controllers/v1/llm.py`、`app/controllers/base.py` |
| 调度层 | 并发上限与排队 | `app/controllers/manager/`（API）、`app/services/webui_task.py`（WebUI） |
| 编排层 | 按阶段推进、写进度、统一转换失败 | `app/services/task.py` |
| 服务层 | 各阶段的具体实现与 Provider 适配 | `llm.py`、`voice.py`、`subtitle.py`、`material.py`、`video.py`，以及 `ofox.py`、`muapi.py` 等付费素材客户端 |
| 状态与配置 | 任务状态、配置读写 | `app/services/state.py`、`app/config/config.py`、`app/models/schema.py` |

三个入口调用 `task.start()` 的方式不同：

- API：`POST /api/v1/videos` 先写入一条“处理中”状态，再通过 `task_manager.add_task(tm.start, ...)` 交给后台线程，立即返回 `task_id`。`/subtitle` 和 `/audio` 两个接口走同一个函数，只是传入的 `stop_at` 不同。
- WebUI：使用独立的 `InMemoryTaskManager`，并发数固定为 1，任务在后台线程执行。日志按 `task_id` 缓存，页面每 0.5 秒轮询一次。
- CLI：在当前进程中同步调用 `tm.start(..., allow_server_file_input=True)`。只有 CLI 允许读取任务目录以外的本地音频；API 和 WebUI 默认把自备音频限制在任务目录内。

依据：[app/controllers/v1/video.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/controllers/v1/video.py)、[app/services/webui_task.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/webui_task.py)、[cli.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/cli.py)、[app/services/task.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/task.py)。

## 一次任务的完整流水线

`_run_pipeline()` 按下表顺序执行。`stop_at` 指定的阶段完成后，任务直接标记为完成并返回该阶段的产物；任何一步失败，都由 `_mark_task_failed()` 记录失败阶段和错误信息。

| 序号 | 阶段（`failed_stage`） | 调用 | 产物 | 完成后进度 |
| --- | --- | --- | --- | --- |
| 0 | `preflight` | 字幕颜色校验、素材源是否受支持、付费素材源和配乐服务的 Key、`utils.check_ffmpeg_ready()` | 无 | 5 |
| 1 | `script` | `llm.generate_script()`；用户已提供文案时跳过 | 文案文本 | 10 |
| 2 | `terms` | `llm.generate_terms()`，可选 TwelveLabs 重排；本地素材跳过 | 英文检索词列表，写入 `script.json` | 20 |
| 3 | `audio` | `voice.tts()`，或使用自备音频，或复用 WebUI 的完整试听音频 | `audio.mp3`、时长、字幕时间轴对象 `sub_maker` | 30 |
| 4 | `subtitle` | `voice.create_subtitle()`（edge）或 `subtitle.create()` + `subtitle.correct()`（whisper） | `subtitle.srt` | 40 |
| 5 | `materials` | `material.download_videos()`；`local` 时为 `video.preprocess_video()` | 本地素材文件列表 | 40→50 |
| 6 | `video` | 对每条成片调用 `video.combine_videos()` 和 `video.generate_video()` | `combined-N.mp4`、`final-N.mp4` | 50→100 |
| 7 | 跨平台发布（可选） | Upload-Post，放进独立线程池执行 | 发布状态字段 | 不影响成片状态 |

预检放在最前面，是为了在调用任何收费服务之前，先拦下缺 Key、缺 FFmpeg 之类注定会失败的任务。源码注释说明了这样排序的原因：完整任务如果缺少配乐 Key，就不应该先消耗 LLM、TTS 和素材服务的额度。只生成文案或关键词的任务不需要 FFmpeg，因此跳过这项探测。

依据：[app/services/task.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/task.py)、[app/utils/utils.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/utils/utils.py)。

## 各阶段的关键实现

### 文案与关键词（`llm.py`）

- 选择 Provider：`_generate_response()` 读取 `llm_provider`，从注册表取出 `LLMProviderSpec`，解析 API Key、模型和 Base URL（留空时使用注册表默认值），再按 `adapter` 字段分派到 OpenAI 兼容、Gemini、通义千问、Azure、Cloudflare、ModelScope、LiteLLM、Claude Code 等实现。Provider 的失败以 `"Error: "` 开头的字符串返回，编排层据此判断失败。
- 文案：`build_script_prompt()` 把系统提示（可用 `custom_system_prompt` 整体替换）和主题、段落数、语言、附加要求拼在一起。返回结果会去掉 `*`、`#`、方括号和圆括号等 Markdown 痕迹，最多重试 5 次。
- 关键词：prompt 要求只返回由英文词组成的 JSON 字符串数组。解析时先去掉 Markdown 代码块，失败后再用正则从文本中提取 `[...]`。默认取 5 个；开启 `match_materials_to_script` 时取 8 个，并要求按文案叙事顺序排列。

### 配音（`voice.py`）

- `tts()` 先检查文案中是否有停顿标签。只有 Edge TTS 会按停顿分段合成再拼接；其他 Provider 去掉标签后一次合成。
- `_single_tts()` 根据音色名选择 Provider：`no-voice` 生成静音音频；以 `-V2` 结尾的是 Azure Speech；`siliconflow:`、`gemini:`、`mimo:`、`minimax:`、`elevenlabs:`、`chatterbox:`、`kokoro:`、`fish_audio:`、`voxcpm:` 前缀分别对应各自的 Provider；其余全部交给 `azure_tts_v1`，也就是 Edge TTS。
- 音频时长以实际写出的文件为准，不用最后一个词的时间戳。源码注释说明，Edge TTS 在最后一个词之后还有固定的尾音，用时间戳会低估时长，进而少下载素材。

### 字幕（`voice.py`、`subtitle.py`）

- `edge` 模式：用 TTS 返回的 `sub_maker` 时间轴，把文案逐句匹配进去，写成 SRT。支持按句显示或逐词显示（`subtitle_display_mode`）。
- `whisper` 模式：`faster-whisper` 模型在首次使用时加载一次，优先读取 `models/whisper-<model_size>` 目录，没有则按模型名下载。转写完成后，`subtitle.correct()` 按编辑距离相似度用原文案校正字幕文字。
- 自备音频没有 `sub_maker`，只能用 whisper。edge 模式失败时会输出无字幕的视频，不会自动切换到 whisper。

### 素材（`material.py`）

- 库存素材（Pexels、Pixabay、Coverr）：对每个检索词调用平台搜索 API。结果按画幅过滤，并做 24 小时搜索缓存；去重后，随机模式会打乱顺序；然后逐个下载，直到累计时长超过“配音时长 × 成片数量”为止。下载并发数由 `material_concurrency` 控制，多个 API Key 会轮换使用。
- 按文案顺序匹配：开启 `match_materials_to_script` 后，改用 `_download_videos_by_script_order()`，按检索词顺序轮流取素材。
- AI 生成源（WaveSpeed、Seedance、OFox、MuAPI、秘塔 MiniMax、OpenAI 文生图）：逐段按需生成，凑够时长立即停止，也不使用搜索缓存，避免为用不到的片段付费。远端任务 ID 写入失败状态（如 `ofox_task_id`），方便到平台控制台找回已计费的产物。
- 实际下载的素材来源（平台、素材 ID、页面、作者）写入 `script.json` 的 `material_sources`。

### 剪辑合成（`video.py`）

1. `combine_videos()` 读取旁白时长，目标画面时长为旁白时长加 0.1 秒余量。每个素材按 `max_clip_duration × 播放速度` 切成若干段（顺序模式下每个素材只取第一段），再用 `cover`（裁切填满）或 `contain`（加黑边）适配目标画布，并应用转场效果。
2. 每段在线程池中单独编码成临时 MP4，并发数由 `video_clip_concurrency` 控制。素材总时长不够时，循环复用已有片段；最后用 FFmpeg concat 拼接，超时时间由 `ffmpeg_concat_timeout_seconds` 控制。
3. `generate_video()` 叠加旁白（按 `voice_volume` 调整音量）、用 `TextClip` 渲染的字幕，以及循环到成片时长的背景音乐（按 `bgm_volume` 调整音量）。编码器优先使用 `video_codec`，不可用时回退到 `libx264`。背景音乐处理失败时仍然输出只有旁白的成片，并在 `warnings` 中记录。

依据：[app/services/llm.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/llm.py)、[app/models/llm_provider.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/models/llm_provider.py)、[app/services/voice.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/voice.py)、[app/services/subtitle.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/subtitle.py)、[app/services/material.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/material.py)、[app/services/material_cache.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/material_cache.py)、[app/services/video.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/video.py)。

## 任务状态与存储

### 状态记录

`app/models/const.py` 定义了三种状态：`TASK_STATE_PROCESSING = 4`、`TASK_STATE_COMPLETE = 1`、`TASK_STATE_FAILED = -1`。每条状态记录包含 `task_id`、`state`、`progress`，以及各阶段写入的结果字段，如 `script`、`terms`、`audio_file`、`videos`、`failed_stage`、`error`、`warnings`。

| 后端 | 启用条件 | 特点 |
| --- | --- | --- |
| `MemoryState` | 默认 | 进程内字典，加锁读写；数据随进程结束而消失，不同进程之间不共享 |
| `RedisState` | `enable_redis = true` | 每个任务存为一个 Redis hash，读取时把字符串还原成原类型。源码注释要求 Redis 只对本应用可写，因为反序列化依赖这一信任边界 |

### 调度

API 的 `TaskManager` 先预占并发名额再启动线程。名额用完的任务进入队列，队列也满时返回 HTTP 429。启用 Redis 时，队列同样放在 Redis 中，API 重启后由 `resume_queued_tasks()` 继续派发。跨平台发布使用单独的线程池（2 个 worker），不占用视频生成的并发名额；它不会在重启后恢复，启动时会把中断的发布状态标记为失败。

### 文件

| 位置 | 内容 |
| --- | --- |
| `storage/tasks/<task_id>/` | `script.json`、`audio.mp3`、`subtitle.srt`、`combined-N.mp4`、`final-N.mp4` |
| `storage/cache_videos/` | 默认的素材下载目录，可用 `material_directory` 改为任务目录或绝对路径 |
| `storage/local_videos/`、`storage/bgm/` | 通过 API 上传的本地素材和背景音乐 |
| `resource/songs/`、`resource/fonts/` | 内置背景音乐和字幕字体 |

API 服务把 `storage/tasks` 挂载为静态路由 `/tasks`。查询任务时，返回的文件路径会根据 `endpoint` 配置转换成可下载的 URL；配置了 `api_key` 时，这条静态路由同样需要鉴权。

依据：[app/models/const.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/models/const.py)、[app/services/state.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/services/state.py)、[app/controllers/manager/base_manager.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/controllers/manager/base_manager.py)、[app/controllers/manager/redis_manager.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/controllers/manager/redis_manager.py)、[app/asgi.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/asgi.py)、[app/utils/utils.py](https://github.com/harry0703/MoneyPrinterTurbo/blob/9887b459e754ee073c056d988499b91136af9662/app/utils/utils.py)。

## 可扩展点

| 想做的事 | 改动位置 | 说明 |
| --- | --- | --- |
| 接入新的 LLM | 在 `app/models/llm_provider.py` 的 `LLM_PROVIDER_REGISTRY` 中增加一个 `LLMProviderSpec` | 协议兼容 OpenAI 时，只需声明默认模型和 Base URL；协议不同时，还要在 `llm._generate_response()` 中增加对应的 `adapter` 分支 |
| 接入新的 TTS | `voice.py`：新增 `is_xxx_voice()` 前缀判断和合成函数，并接入 `_single_tts()` | 合成函数需要写出音频文件，并返回 `SubMaker`，字幕阶段才能使用它的时间轴 |
| 接入新的素材源 | `material.download_videos()` 中增加分支，并加入 `task._SUPPORTED_VIDEO_SOURCES`；需要 CLI 支持时，再加入 `cli._CLI_VIDEO_SOURCES` | 付费源应参照现有实现：逐段按需生成，并在失败状态中保留远端任务 ID |
| 接入新的 AI 配乐 | 在 `task._VIDEO_MUSIC_PROVIDERS` 中登记 | 源码注释说明，服务只需实现 `is_enabled` 和 `generate_bgm`，预检、0 音量跳过、失败降级都复用同一路径 |
| 调整文案风格 | `custom_system_prompt`、`video_script_prompt` 参数 | 不需要改代码；系统提示最长 8000 字符，附加要求最长 2000 字符 |
| 只使用部分流水线 | `stop_at` | 可以只取文案、关键词、配音、字幕或素材，交给其他工具继续处理 |
| 换状态后端 | 实现 `state.BaseState` 和 `TaskManager` 的队列方法 | 现有实现为内存和 Redis 两种 |

另外，`app/services/video_project.py` 和 `docs/video-projects.md` 提供了一个可选的本地“视频工程”CLI，用于替换单个场景后增量重新渲染。它独立于主流水线，本文没有展开。
