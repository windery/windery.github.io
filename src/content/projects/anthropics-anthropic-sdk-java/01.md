TL;DR：Anthropic 官方的 Java SDK，用类型化的 builder 封装 Claude API。核心模块加 OkHttp 传输层即可调用，Bedrock、Vertex、Foundry 等云平台通过可插拔的 backend 接入。本文基于 2.68.0 版本（2026-09-30 发布）。

## 它解决什么问题

Claude API 本质上是几个 HTTP 接口，用任何 HTTP 客户端都能调用。但直接拼 JSON 有几个麻烦：请求体字段多且经常新增；响应里的 `content` 是多种类型混合的数组；流式输出要自己解析 SSE；重试、超时、限流也要自己写。

这个 SDK 把这些都封装好了，让 Java 代码以强类型的方式调用 API：

- 请求参数用 builder 构造，编译期就能发现字段名写错；
- 响应解析成类型化对象，多态的内容块用 `Optional` 访问；
- 内置重试、超时、流式解析和错误映射；
- 同一套代码可以切换到 Anthropic 官方 API 或云厂商托管的 Claude。

它在“AI 开发基础”课程的 [第 4 课](/courses/ai-dev/04/) 中首次使用，之后的结构化输出、工具调用等课程也会基于它。

## 模块组成

仓库是一个 Gradle 多模块项目，主要模块如下：

| 模块 | 作用 |
| --- | --- |
| `anthropic-java` | 对外发布的主依赖，聚合下面的 core 和 OkHttp 客户端 |
| `anthropic-java-core` | 请求/响应模型、服务接口、重试、流式解析、错误类型等全部核心逻辑 |
| `anthropic-java-client-okhttp` | 基于 OkHttp 的 HTTP 传输实现，提供 `AnthropicOkHttpClient` |
| `anthropic-java-bedrock` / `-vertex` / `-foundry` / `-google-cloud` / `-aws` | 各云平台的认证与路由 backend |
| `anthropic-java-mcp` | 把 MCP（Model Context Protocol）SDK 的类型转换成 Claude API 类型的辅助工具 |
| `anthropic-java-example` | 可直接运行的示例，覆盖消息、流式、工具、结构化输出等 |

日常使用只需要引入 `com.anthropic:anthropic-java`。core 与传输层分开，意味着理论上可以换用别的 HTTP 实现，而业务代码只依赖 core 中的 `AnthropicClient` 接口。

SDK 用 Kotlin 编写，但对 Java 调用方做了专门设计（`@JvmStatic`、`Optional`、builder），在 Java 8 及以上版本可用。和很多官方 SDK 一样，大部分代码由 OpenAPI 规格自动生成，所以 API 新增字段后 SDK 跟进很快，版本号也更新频繁。

## 核心设计

**不可变参数 + builder。** 每个请求对应一个参数类，比如 `MessageCreateParams`，通过 builder 构造，`build()` 之后不可变。builder 本身可以继续追加内容并再次 `build()`，示例中常用这个特性维护多轮对话。

**服务分组与客户端入口。** `AnthropicClient` 按 API 资源分组：`client.messages()`、`client.models()`、`client.beta()` 等。正式功能在 `com.anthropic.models.messages` 包，测试中的功能在 `client.beta()` 下，对应 `com.anthropic.models.beta.*` 包。两个包里有同名的 `MessageCreateParams`，导入时要注意选对。

**同步与异步。** `AnthropicOkHttpClient` 返回同步结果；`AnthropicOkHttpClientAsync` 返回 `CompletableFuture`，适合已经使用异步框架的服务。

**联合类型用 Optional 表达。** 响应中的 `ContentBlock` 可能是文本、思考、工具调用等多种类型。SDK 为每种可能提供一个返回 `Optional` 的访问方法，比如 `block.text()`、`block.toolUse()`，也提供 `isText()` / `asText()` 这样的判断与转换方法。这让“按类型筛选内容块”在 Java 中写起来很自然。

**向前兼容。** 字段内部用 `JsonField` 包装，能表示“缺失”“null”“已知值”和“未知结构”几种状态。API 新增了 SDK 还不认识的字段或枚举值时，旧版本 SDK 不会因此反序列化失败。模型名也是如此：`.model()` 既接受 `Model.CLAUDE_OPUS_5_5` 这样的常量，也接受任意字符串。

## 内置的可靠性能力

| 能力 | 默认行为 |
| --- | --- |
| 重试 | 最多 2 次；对 408、409、429、5xx 和网络错误重试；优先遵守 `Retry-After`，否则使用带抖动的指数退避 |
| 超时 | 连接超时 1 分钟，请求超时默认 10 分钟 |
| 错误映射 | HTTP 错误映射为 `BadRequestException`、`RateLimitException` 等，均继承 `AnthropicServiceException` |
| 认证 | `fromEnv()` 依次读取 `ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、本地配置文件和工作负载身份联合等来源 |

这些都可以在 builder 上调整，也可以通过 `withOptions(...)` 对单次调用覆盖。

## 适用范围与边界

- 它是**协议层 SDK**：封装的是 Claude API 本身，不提供 prompt 模板、RAG、向量库等应用层抽象。需要这些时，可以在它之上自己封装，或使用 Spring AI、LangChain4j 等框架（课程第六部分会介绍）。
- 它只面向 Claude。如果需要在多家模型之间切换，通常由框架层做统一抽象。
- beta 功能的接口可能随 API 变化而调整，生产代码使用 `client.beta()` 时应关注版本更新说明。
