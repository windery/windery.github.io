TL;DR：客户端做成单例并按需调整重试与超时；用 Java 类声明结构化输出；流式输出配合 `MessageAccumulator` 拿到完整消息；工具调用可以交给 beta 的 tool runner；排查问题时取原始响应和 request-id。本文代码均已在 2.68.0 版本上编译通过。

## 引入依赖

```xml
<dependency>
  <groupId>com.anthropic</groupId>
  <artifactId>anthropic-java</artifactId>
  <version>2.68.0</version>
</dependency>
```

最基础的调用方式见课程 [第 4 课](/courses/ai-dev/04/)。下面整理的是第 4 课之外、实际项目中常用的几种写法。

## 客户端配置

客户端内部持有连接池和线程池，应该全局复用。在 Spring Boot 中可以注册为 Bean：

```java
@Bean(destroyMethod = "close")
public AnthropicClient anthropicClient() {
    return AnthropicOkHttpClient.builder()
            .fromEnv()                          // 读取 ANTHROPIC_API_KEY 等环境变量
            .maxRetries(3)                      // 默认 2
            .timeout(Duration.ofSeconds(60))    // 默认请求超时 10 分钟
            .build();
}
```

某一次调用需要不同配置时，不必新建客户端，用 `withOptions` 派生一个即可：

```java
client.withOptions(options -> options.timeout(Duration.ofSeconds(10)))
        .messages()
        .create(params);
```

## 控制 effort

effort 嵌套在 `OutputConfig` 中，builder 上没有直接的 `.effort()` 方法：

```java
MessageCreateParams params = MessageCreateParams.builder()
        .model(Model.CLAUDE_OPUS_5_5)
        .maxTokens(1024L)
        .outputConfig(OutputConfig.builder().effort(OutputConfig.Effort.LOW).build())
        .addUserMessage("你好")
        .build();
```

## 结构化输出：直接得到 Java 对象

把一个普通 Java 类传给 `outputConfig(Class)`，SDK 会从类结构生成 JSON Schema 发给 API，并把返回的 JSON 反序列化成这个类。字段说明用 Jackson 的 `@JsonPropertyDescription` 写，它会进入 schema，相当于给模型的字段文档。

```java
public static class TicketLabel {
    @JsonPropertyDescription("工单类别：billing、shipping、after_sales 或 other")
    public String category;
    @JsonPropertyDescription("一句话说明判断依据")
    public String reason;
}

StructuredMessageCreateParams<TicketLabel> params = MessageCreateParams.builder()
        .model(Model.CLAUDE_OPUS_5_5)
        .maxTokens(2048L)
        .outputConfig(TicketLabel.class)
        .addUserMessage("给这条工单分类：快递三天没动了。")
        .build();

client.messages().create(params).content().stream()
        .flatMap(block -> block.text().stream())
        .forEach(text -> {
            TicketLabel label = text.text();   // 已经是 TicketLabel，不需要手动解析 JSON
            System.out.println(label.category + "：" + label.reason);
        });
```

这是正式（非 beta）功能，不需要额外的请求头。课程第 6 课会详细讲 schema 设计和失败处理。

## 流式输出并拿到完整消息

流式输出时，文本是一段段到达的。如果既要实时显示，又要在结束后拿到完整的 `Message`（比如记录 `usage`、存入对话历史），可以用 `MessageAccumulator` 把事件累积起来：

```java
MessageAccumulator accumulator = MessageAccumulator.create();
try (StreamResponse<RawMessageStreamEvent> stream = client.messages().createStreaming(params)) {
    stream.stream()
            .peek(accumulator::accumulate)
            .flatMap(event -> event.contentBlockDelta().stream())
            .flatMap(delta -> delta.delta().text().stream())
            .forEach(text -> System.out.print(text.text()));
}
Message full = accumulator.message();
System.out.println("\noutput_tokens=" + full.usage().outputTokens());
```

## 工具调用：tool runner

工具调用需要一个循环：模型返回 `tool_use`，你执行方法，把结果发回，直到模型给出最终回答。SDK 在 beta 中提供了 `BetaToolRunner`，替你执行这个循环。工具用一个实现 `Supplier<String>` 的类声明，字段就是参数：

```java
@JsonClassDescription("根据订单号查询物流状态")
static class GetShipment implements Supplier<String> {
    @JsonPropertyDescription("订单号，例如 A10086")
    public String orderId;

    @Override
    public String get() {
        return "订单 " + orderId + " 已于昨天到达上海转运中心";   // 实际项目中调用物流服务
    }
}

BetaToolRunner runner = client.beta().messages().toolRunner(
        com.anthropic.models.beta.messages.MessageCreateParams.builder()
                .model(Model.CLAUDE_OPUS_5_5)
                .maxTokens(4096L)
                .putAdditionalHeader("anthropic-beta", "structured-outputs-2025-11-13")
                .addTool(GetShipment.class)
                .addUserMessage("帮我查一下订单 A10086 到哪了")
                .build());

for (BetaMessage message : runner) {    // 每轮模型响应都会迭代出来
    message.content().stream()
            .flatMap(block -> block.text().stream())
            .forEach(text -> System.out.println(text.text()));
}
```

注意这里用的是 beta 包下的 `MessageCreateParams`。tool runner 很方便，但隐藏了循环细节；课程第 9、10 课会先手写这个循环，再回来看它省掉了什么。

## 排查问题：原始响应与 request-id

遇到奇怪的返回时，需要看 HTTP 状态码、响应头，以及每个请求唯一的 request-id（向 Anthropic 支持反馈问题时需要提供）。`withRawResponse()` 可以拿到这些信息，同时仍能解析出正常的对象：

```java
HttpResponseFor<Message> raw = client.messages().withRawResponse().create(params);
System.out.println("request-id=" + raw.requestId().orElse("-") + " status=" + raw.statusCode());
Message message = raw.parse();
```

建议在日志中记录 request-id，和你自己的 trace-id 关联起来。

## 常见坑

- **两个 `MessageCreateParams`。** 正式接口用 `com.anthropic.models.messages.MessageCreateParams`，beta 接口用 `com.anthropic.models.beta.messages.MessageCreateParams`，混用会编译失败。
- **不检查 `stop_reason`。** 输出被 `max_tokens` 截断时请求依然成功，只能通过 `stopReason()` 发现。
- **忘记关闭流。** `StreamResponse` 持有 HTTP 连接，必须用 try-with-resources。
- **硬编码模型常量。** `Model.CLAUDE_OPUS_5_5` 这样的常量需要升级 SDK 才会出现新值；把模型名放进配置，用 `.model(String)` 传入，换模型就不用改代码。
- **新模型拒绝旧参数。** 新一代模型不再接受 `temperature` 等采样参数，旧代码迁移时会收到 400 错误。
