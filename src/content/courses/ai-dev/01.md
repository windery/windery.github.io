这门课写给已经能独立交付后端服务的 Java 工程师。目标有两个：一是学会用编程 agent 高效、可靠地写代码，也就是常说的 vibe coding；二是理解这些 agent 是怎么实现的、底下的大模型是怎么工作的。第二个目标服务于第一个：只有知道 agent 为什么这样表现，最佳实践才不会变成一串需要死记的口诀。

## 三个概念，三层结构

先把三个经常混在一起的词分开：

| 层次 | 是什么 | 例子 |
| --- | --- | --- |
| 大模型 | 根据上下文预测下一个 token 的模型，通过 API 提供 | Claude、GPT、Gemini 等 |
| 编程 agent | 包在模型外面的程序：给模型提供工具，循环调用模型，直到任务完成 | Claude Code、Cursor 的 agent 模式、Codex |
| Vibe coding | 一种工作方式：用自然语言描述目标，让 agent 写代码，人负责引导和把关 | 你在终端里说“给订单接口加上幂等校验” |

它们是一层套一层的关系：你和 agent 对话，agent 和模型对话。你看到的每一个 agent 行为，最终都可以追溯到两个来源：**agent 程序做了什么**（发了什么上下文、提供了哪些工具、怎么处理结果），以及**模型怎么响应这些输入**。

## Vibe coding 这个词

“vibe coding”是 Andrej Karpathy 在 2025 年初提出的说法，原意是一种很随意的编程方式：完全跟着感觉走，接受 AI 生成的代码，不怎么看 diff，出错了就把报错贴回去，直到程序能跑。这种方式适合周末的小玩具，但不适合要长期维护的生产系统。

后来这个词的含义变宽了，常被用来泛指“主要靠 AI 写代码”的工作方式。这门课说的“vibe coding 最佳实践”，指的是后一种含义中**工程化的那一端**：人仍然对结果负责，只是把大部分键盘工作交给 agent。两者的差别主要在这几点：

| | 随意的 vibe coding | 工程化的 agent 编程 |
| --- | --- | --- |
| 需求 | 一句话，边做边改 | 写清目标、约束和验收标准 |
| 过程 | agent 想怎么改就怎么改 | 先探索、再计划、再实现 |
| 验证 | 能跑就行 | 测试、类型检查、人工 review |
| 上下文 | 一个会话聊到底 | 主动管理会话和项目记忆 |
| 适用 | 原型、一次性脚本 | 需要维护的代码库 |

## 为什么最佳实践离不开原理

网上的 vibe coding 技巧很多，比如“长会话要及时清空”“先让它写测试”“在项目里放一份 CLAUDE.md”。这些建议大多有效，但如果只记结论，遇到新情况就不知道该不该用。下面几条，都能在后面的课程里找到原理上的解释：

| 常见建议 | 背后的原理 | 对应课程 |
| --- | --- | --- |
| 会话太长就清空重来 | 模型无状态，每轮都重读全部历史；上下文越长，注意力越分散 | 第 2、4 课 |
| 同样的指令，结果每次不同 | 输出来自概率采样，本来就不是确定性的 | 第 3 课 |
| 让 agent 先跑测试再说完成 | agent 只能通过工具结果感知真实世界，测试是最可靠的反馈 | 第 6、16 课 |
| 把项目约定写进 CLAUDE.md | 这个文件会被 agent 自动放进每次请求的上下文 | 第 9、18 课 |
| 大任务先让它出计划 | 模型在一步步生成，先写下计划能约束后面的生成 | 第 10、15 课 |
| 不要把密钥贴进对话 | 对话内容会作为上下文发给模型服务，也可能被工具读取或写出 | 第 12 课 |

所以课程的顺序是：先讲模型，再讲 agent，最后讲实践。

## 课程结构

1. **大模型原理**：token、上下文窗口、采样和停止条件，以及长上下文为什么会让效果变差。
2. **Agent 实现原理**：从一次 API 调用开始，用 Java 手写一个能读写文件、执行命令的最小编程 agent，再看成熟工具在上下文管理、规划、扩展和权限上的设计。
3. **Vibe coding 最佳实践**：需求怎么写、任务怎么推进、如何建立反馈回路、怎么管理会话和项目配置、怎么审查 AI 写的代码、怎么并行。
4. **实战**：在一个 Spring Boot 项目里用 agent 完整交付一个功能，并复盘成本和失败。

第二部分会写不少代码。并不是要你以后自己做一个 agent，而是亲手写一遍之后，你会清楚地知道 agent 每一步给模型发了什么、模型返回了什么。之后再用 Claude Code 这类工具时，你对它的行为就有了可靠的判断依据。

## 后端经验在这里同样有用

转型时容易以为要从头学起，其实很多后端经验可以直接用上：

| 你已经会的 | 在这门课中的对应 |
| --- | --- |
| 调用第三方 HTTP 服务 | 模型就是一个按 token 计费的远程服务 |
| 接口契约、参数校验 | 工具的参数 schema，agent 产出的校验 |
| 单元测试、CI | agent 最重要的反馈回路 |
| Code review | 审查 AI 写的代码，只是频率更高、规模更大 |
| 权限控制、最小权限原则 | agent 的权限模式和沙箱 |
| 写设计文档、拆需求 | 写给 agent 的 spec 和计划 |

真正需要新建立的直觉只有几条：模型的输出是概率性的；上下文就是它知道的全部；自然语言的措辞会改变系统行为；每个 token 都要花钱和时间。

## 课程用到的工具

- **Java 17 或更高版本**，Maven 或 Gradle。第二部分的示例用 Java 编写。
- **Claude API 和官方 Java SDK**：第 5 课开始直接调用 API。需要在 [Claude Console](https://platform.claude.com/) 创建 API key，放进环境变量 `ANTHROPIC_API_KEY`，不要写进代码或提交到仓库。
- **一个编程 agent**：第三部分以 Claude Code 为主要例子，同时说明其他工具中的对应做法。

课程涉及的开源项目会在本站“项目解读”中单独介绍。目前有两个和本课相关：[Anthropic Java SDK](/projects/anthropics-anthropic-sdk-java/01/)（第 5 课起使用），以及 [mattpocock/skills](/projects/mattpocock-skills/01/)（一套编程 agent 技能，第三部分会多次引用）。

## 怎样学这门课

- **原理部分边读边验证。** 遇到“模型会这样”的说法，尽量用 API 或 agent 实际试一次。
- **实践部分在真实项目里做。** 拿自己维护的代码库练习，效果和问题都会真实得多。
- **记录成本。** 看每次请求的 token 用量，建立“这类任务大概花多少”的直觉。
- **保持怀疑。** agent 说“已完成、测试通过”时，要像对待外部系统的返回值一样去核实。

## 练习

1. 回忆你最近一次用 AI 写代码的经历：哪一步最顺利，哪一步最费劲？把费劲的那一步记下来，学完第二部分后回来看，试着找出原因。
2. 在 Claude Console 创建一个 API key，设置到环境变量中，确认程序能读到（不要把 key 的值输出到任何公开的地方）。
3. 对照“为什么最佳实践离不开原理”那张表，挑一条你平时不太认同或没听过的建议，在后面学到对应课程时重点关注。
