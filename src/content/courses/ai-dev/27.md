## agent 是什么

在 opencode 里，agent 是一份配置：用什么提示词、什么模型、什么权限、最多几步。主循环只有一个，不同的 agent 只是给它不同的参数。`agent/agent.ts` 里的定义：

```typescript
export const Info = Schema.Struct({
  name: Schema.String,
  description: Schema.optional(Schema.String),
  mode: Schema.Literals(["subagent", "primary", "all"]),
  native: Schema.optional(Schema.Boolean),
  hidden: Schema.optional(Schema.Boolean),
  temperature: Schema.optional(Schema.Finite),
  permission: PermissionV1.Ruleset,
  model: Schema.optional(/* providerID + modelID */),
  prompt: Schema.optional(Schema.String),
  steps: Schema.optional(Schema.Finite),
  // ……
})
```

这和第 11 课的 `AgentConfig(indent, tools, maxSteps, compaction)` 是同一个思路：把“主 agent”和“子 agent”的区别提取成数据，循环代码只写一份。opencode 多了提示词、模型和权限，工具集合也不是直接列出来的，而是由权限规则筛出来的（第 25 课讲过，被 `"*": "deny"` 整体禁止的工具，模型根本看不到）。

内置的 agent 有七个：

| agent | mode | 用途 | 权限的特点 |
| --- | --- | --- | --- |
| build | primary | 默认 agent | 默认规则，几乎全部允许 |
| plan | primary | 计划模式，Tab 切换 | 编辑只允许写 `.opencode/plans/*.md` |
| general | subagent | 通用子 agent，可以并行做多件事 | 禁止 todowrite |
| explore | subagent | 只读的代码探索 | `"*": "deny"`，只放开 grep、glob、list、bash、webfetch、websearch、read |
| compaction | primary，隐藏 | 压缩上下文（第 26 课） | 不带工具 |
| title | primary，隐藏 | 生成会话标题 | 不带工具 |
| summary | primary，隐藏 | 生成会话摘要 | 不带工具 |

`mode` 决定 agent 出现在哪里：`primary` 是用户可以切换到的主 agent，`subagent` 只能被 task 工具调用，`all` 两边都可以。`hidden` 的 agent 不出现在任何列表里，只在内部使用。第 24 课每次运行都能看到的“生成标题”请求，用的就是 title agent。

```text
  user      text        [cache] "读 hello.txt，告诉我里面写了什么。"

  user      text        "看看这个项目有什么"
  assistant tool_use    [cache] {"description": "查看 hello.txt", "prompt": "读 hello.txt，告诉我里面写了什么。", "subagent_type": "explore"}
  user      tool_result [cache] "<task id=\"ses_…\" state=\"completed\">\n<task_result>\nhello.txt 里是一句英文问候。\n</task_result>\n</task>"
```

请求 3 和 4 是子 agent 的。和第 11 课的 MiniAgent 一样，子 agent 有自己的系统提示和工具集合，只看得到 `prompt` 里的那句话，看不到主对话。有两点值得注意：

- **explore 的系统提示很短，只有一千多个字符。** 它用的是 agent 自己的 `prompt`（`agent/prompt/explore.txt`），不是 provider 提示词，后面也没有 skills 列表，因为它的权限禁止了 skill 工具。
- **工具列表里没有 websearch 和 list。** 权限放开了，但这两个工具本身没有注册：websearch 要用环境变量打开，list 在这个版本里已经不是独立工具了。权限规则只是“允许”，有没有这个工具是另一回事。

`tool/task.ts` 做的事情可以概括成这几步：

```typescript
// 1. 子 agent 的嵌套深度有上限，默认 1：子 agent 不能再开子 agent
if (depth >= (cfg.subagent_depth ?? 1)) {
  return yield* Effect.fail(new Error(`Subagent depth limit reached ……`))
}
// 2. 调用 task 本身也要过权限检查，pattern 是子 agent 的名字
yield* ctx.ask({ permission: id, patterns: [params.subagent_type], always: ["*"], metadata: { /* … */ } })
// 3. 新建一个子会话，parentID 指向当前会话；传了 task_id 就接着用原来的子会话
const nextSession = session ?? (yield* sessions.create({
  parentID: ctx.sessionID,
  title: params.description + ` (@${next.name} subagent)`,
  agent: next.name,
  permission: [...childPermission, /* 默认禁止 todowrite 和 task */],
}))
// 4. 在子会话里调用同一个 prompt 函数，跑完整的主循环
const result = yield* ops.prompt({ sessionID: nextSession.id, agent: next.name, parts, /* … */ })
// 5. 子会话最后一段文字就是返回值
return result.parts.findLast((item) => item.type === "text")?.text ?? ""
```

返回值被包装成 `<task id="…" state="completed"><task_result>…</task_result></task>`。`id` 是子会话的 ID，工具描述里告诉模型：下次传 `task_id` 就能接着这个子会话继续，它会记得之前读过的东西。这是 MiniAgent 没有的能力：MiniAgent 的子 agent 用完就丢。

子会话就是一个普通的会话，只是多了一个 `parent_id`：

```sh
./db.sh "select id, parent_id, title from session"
```

```text
id                              parent_id                       title
ses_effdb3ca9ffeJkklKwdBQEkfFH                                  演示会话
ses_effdb35f6ffeW2QognWQUc3ul4  ses_effdb3ca9ffeJkklKwdBQEkfFH  查看 hello.txt (@explore subagent)
```

TUI 里可以切换到子会话，看它每一步做了什么。

权限的传递在 `agent/subagent-permissions.ts`：父会话的 deny 规则和 `external_directory` 规则会带到子会话里，其他规则不带。源码注释说得很清楚：父 agent 的限制只管父 agent 自己，子 agent 能做什么由它自己的权限决定；但用户在会话上明确禁止的事，子 agent 也不能做。

另外两个特性：

- **并行。** task 工具和其他工具一样在 AI SDK 里执行，一次回复里的多个 task 调用会同时运行。工具描述里第一条用法就是“尽量在一条消息里同时启动多个 agent”。
- **后台运行（实验性）。** 设置 `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true` 后，task 可以传 `background: true`，立即返回“已在后台运行”。子会话完成后，结果作为一条新的用户消息插入父会话。

## 自定义 agent 和命令

自定义 agent 写成 Markdown 文件，放在 `.opencode/agent/`（或 `agents/`）下，frontmatter 是配置，正文是提示词。命令也是 Markdown，放在 `.opencode/command/` 下，正文是提示词模板。全局的放在 `~/.config/opencode/` 下的同名目录，也可以写在 `opencode.json` 的 `"agent"` 和 `"command"` 里。

实验包的 `extras/dot-opencode/` 里准备了一个 agent、一个命令、一个插件和一个自定义工具。先运行一次任意剧本创建 `demo/`，再复制进去：

```sh
./run.sh 01-read "读一下 hello.txt"
cp -r extras/dot-opencode demo/.opencode
```

`agent/reviewer.md`：

```markdown
---
description: 审查代码改动，只读，不修改任何文件。用户要求审查时使用。
mode: subagent
permission:
  edit: deny
  bash: deny
  webfetch: deny
---
你是一个代码审查员。只指出问题，不要修改文件。每个问题给出文件和行号。
```

`command/review.md`：

```markdown
---
description: 审查一个文件
agent: build
---
请审查 $ARGUMENTS。

最近一次提交：!`git log --oneline -1`
```

用 `--command` 运行这个命令，剧本让模型把审查交给 reviewer：

```sh
./run.sh 09-agent --command review hello.txt
python3 show.py logs/09-agent.jsonl
```

```text
===== 请求 2：1 条消息，工具 ['bash', 'edit', 'glob', 'grep', 'line_count', 'read', 'skill', 'task', 'todowrite', 'webfetch', 'write']
  user      text        [cache] "请审查 hello.txt。\n\n最近一次提交：b396c1a init"

===== 请求 3：1 条消息，工具 ['glob', 'grep', 'read', 'skill']
system（……字符）：你是一个代码审查员。只指出问题，不要修改文件。每个问题给出文件和行号。 You are powered by the model named claude-so ...
  user      text        [cache] "审查 hello.txt，列出问题。"
```

（你的提交哈希会不一样。`line_count` 是一起复制进去的自定义工具，下一节讲。）

先看命令。用户消息里看不到 `$ARGUMENTS` 和 `` !`…` ``：发给模型之前，`$ARGUMENTS` 被换成了参数，`` !`git log --oneline -1` `` 被换成了命令的输出。`session/prompt.ts` 的 `command` 函数做这件事，还支持 `$1`、`$2` 这样的位置参数，以及 `@文件路径` 把文件作为附件。命令就是一个**在客户端展开的提示词模板**，模型看到的只是展开后的结果。命令的 frontmatter 还可以指定 `model`，以及 `subtask: true`：这时整个命令会在一个子会话里执行，不污染主会话的上下文。

再看 reviewer。它的系统提示以 Markdown 正文开头，后面依次是环境信息、AGENTS.md、skills 列表，和第 26 课讲的拼法一致：agent 有自己的 `prompt`，就用它代替 provider 提示词。工具只剩 glob、grep、read、skill 四个：edit 和 write 被 `edit: deny` 去掉了，bash、webfetch 被各自的 deny 去掉了，task 和 todowrite 是子会话默认禁止的。

Markdown 文件变成 agent 配置的代码在 `config/agent.ts`，只有二十几行：

```typescript
for (const item of await Glob.scan("{agent,agents}/**/*.md", { cwd: dir, absolute: true, dot: true, symlink: true })) {
  const md = await ConfigMarkdown.parse(item).catch(() => undefined)
  if (!md) continue
  const name = configEntryNameFromPath(path.relative(dir, item), ["agent/", "agents/"])
  const config = { name, ...md.data, prompt: md.content.trim() }
  result[config.name] = ConfigParse.schema(ConfigAgentV1.Info, config, item)
}
```

文件名就是 agent 的名字；frontmatter 展开成配置字段；正文成为 `prompt`。和第 18 课 Claude Code 的子 agent 文件几乎是同一种格式，区别在字段：Claude Code 用 `tools` 列出可用的工具，opencode 用 `permission` 规则。

task 工具的描述里会列出所有可用的子 agent，内容来自每个 agent 的 `description`（`tool/registry.ts` 的 `describeTask`）。主 agent 决定用哪个子 agent，依据只有这一句描述。所以 description 要写清楚“什么时候用我”，这和第 18 课讲 skill 描述的道理一样。

## 插件和自定义工具

插件是一个 TypeScript 函数，返回一组钩子。复制进去的 `plugin/guard.ts`：

```typescript
import type { Plugin } from "@opencode-ai/plugin"

export const Guard: Plugin = async () => ({
  "tool.execute.before": async (input, output) => {
    if (input.tool === "read" && String(output.args.filePath).endsWith(".env")) {
      throw new Error("guard 插件：不允许读取 .env")
    }
  },
  "tool.execute.after": async (input, output) => {
    console.error(`[guard] ${input.tool} 执行完毕，output 的字段：${Object.keys(output).join(", ")}`)
  },
})
```

自定义工具 `tool/line_count.ts`：

```typescript
import { tool } from "@opencode-ai/plugin"

export default tool({
  description: "统计一个文本文件有多少行",
  args: {
    path: tool.schema.string().describe("文件的绝对路径"),
  },
  async execute(args) {
    const text = await Bun.file(args.path).text()
    return `${args.path} 共 ${text.split("\n").length - 1} 行`
  },
})
```

运行插件剧本，模型先读 `.env`，再调用 `line_count`：

```sh
./run.sh 10-plugin "试试插件"
```

```text
✗ Read .env failed
Error: guard 插件：不允许读取 .env
[guard] line_count 执行完毕，output 的字段：title, output, attachments, metadata
⚙ line_count {"path":"…/demo/hello.txt"}
.env 被插件挡住了；hello.txt 有 1 行。
```

几个观察：

- **钩子在工具外面执行。** 第 25 课讲过，读 `.env` 默认要询问用户；这里根本没走到询问那一步，`tool.execute.before` 先抛了异常。包装代码在 `session/tools.ts`：先触发 before，再调用工具的 `execute`，再触发 after。权限检查在 `execute` 里面，所以插件比权限规则更早。
- **抛异常就是拒绝。** 异常信息作为工具错误返回给模型，循环继续。效果相当于第 18 课 Claude Code 的 PreToolUse hook 返回“拒绝”，区别是 Claude Code 的 hook 是一个外部命令，opencode 的插件是同一个进程里的函数。
- **失败的调用不触发 after。** `[guard]` 只为 line_count 打印了一行。
- **自定义工具就是普通工具。** 文件名成为工具名，出现在每一个请求的工具列表里，参数 schema 由 `tool.schema`（也就是 zod）生成。

`.opencode` 下的 TypeScript 文件为什么能 `import "@opencode-ai/plugin"`？看一下 `demo/.opencode/`，会发现多了 `node_modules/` 和 `.gitignore`。`config/config.ts` 在启动时检查每个配置目录，在后台给它安装 `@opencode-ai/plugin`。所以第一次运行会慢一点，而且需要网络。

插件能用的钩子定义在 `packages/plugin/src/index.ts` 的 `Hooks` 接口里：

| 钩子 | 时机 | 能做什么 |
| --- | --- | --- |
| `event` | 任何事件 | 观察会话、消息、权限等所有事件 |
| `config` | 加载配置后 | 读取配置 |
| `tool` | 注册工具时 | 提供自定义工具 |
| `auth`、`provider` | 登录、列出模型时 | 接入新的模型服务商 |
| `chat.message` | 收到用户消息 | 修改消息和附件 |
| `chat.params`、`chat.headers` | 调用模型前 | 改温度、最大输出长度、请求头 |
| `command.execute.before` | 执行命令前 | 修改展开后的内容 |
| `tool.execute.before`、`tool.execute.after` | 工具执行前后 | 改参数、拦截调用、改输出 |
| `tool.definition` | 发送工具定义前 | 改工具描述和参数 |
| `shell.env` | 执行 shell 命令前 | 注入环境变量 |
| `permission.ask` | 询问权限时 | 自动允许或拒绝 |
| `experimental.chat.system.transform` | 拼系统提示时 | 增加或修改系统提示（第 26 课） |
| `experimental.chat.messages.transform` | 发送历史前 | 修改发给模型的历史 |
| `experimental.session.compacting` | 压缩前 | 往压缩提示里加内容，或整个替换（第 26 课） |
| `experimental.compaction.autocontinue` | 压缩后 | 决定是否自动继续 |

表里的 `permission.ask` 有一个问题：在这个版本的 `packages/opencode/src` 里搜索 `"permission.ask"`，找不到任何触发它的代码。接口声明了，但没有接上。想用插件自动批准权限，目前只能通过 `event` 钩子观察 `permission.asked` 事件，再调用服务端的接口回复。这又是一个“类型和文档不等于行为”的例子。

插件的来源有两种：本地文件（`.opencode/plugin/` 或全局配置目录下的 `plugin/`），以及 npm 包（`opencode.json` 里的 `"plugin": ["包名"]`）。

## MCP

第 18 课讲过，MCP 是把外部系统接入 agent 的标准协议。实验包的 `extras/mcp-time.py` 是一个不依赖任何库的 MCP 服务端，只有一个 `now` 工具。打开它看一下：stdio 传输就是一行一个 JSON-RPC 消息，服务端只需要回答 `initialize`、`tools/list` 和 `tools/call` 三种请求。

在实验包根目录的 `opencode.json` 里加上（`__LAB__` 会被 `run.sh` 换成实验目录的路径）：

```json
"mcp": {
  "time": { "type": "local", "command": ["python3", "__LAB__/extras/mcp-time.py"] }
}
```

然后运行：

```sh
./run.sh 11-mcp "现在几点"
python3 show.py logs/11-mcp.jsonl
python3 show.py logs/11-mcp.jsonl --system | grep -A2 '<server'
```

```text
===== 请求 3：3 条消息，工具 ['bash', 'edit', 'glob', 'grep', 'line_count', 'read', 'skill', 'task', 'time_now', 'todowrite', 'webfetch', 'write']
  user      text        "现在几点"
  assistant tool_use    [cache] {}
  user      tool_result [cache] "2026-10-03 13:06:09"
```

```text
  <server name="time">
    需要知道当前时间时，调用 now 工具。
  </server>
```

- **工具名是“服务端名_工具名”。** 服务端叫 `time`，工具叫 `now`，模型看到的是 `time_now`。两部分都会把不合法的字符替换掉。不同服务端的同名工具因此不会冲突。
- **服务端的 `instructions` 进入系统提示。** `initialize` 返回的说明被放在 `<server name="time">` 里，这就是第 26 课系统提示表格里的“MCP 服务端的说明”那一段。
- **权限检查用工具名。** MCP 工具调用前会以工具名（这里是 `time_now`）为权限名询问，所以可以写 `"permission": { "time_*": "ask" }` 控制一整个服务端。

插件剧本复制进去的 guard 还在，看一下终端输出：

```text
[guard] time_now 执行完毕，output 的字段：content
```

内置工具和自定义工具的 after 钩子拿到的是 `title, output, attachments, metadata`，MCP 工具拿到的却是 MCP 协议原始的 `content`。插件的类型声明说 `output` 一定有 `output` 字段，但 MCP 工具的包装代码（`session/tools.ts` 里处理 MCP 的部分）把原始结果直接传给了钩子。如果插件按类型声明写 `output.output.length`，遇到 MCP 工具就会抛异常，而 after 钩子里的异常会让这次工具调用失败。写插件时要防御这种情况。

远程 MCP 服务端用 `"type": "remote"` 加 `"url"`，先尝试 Streamable HTTP，失败再退回 SSE；需要 OAuth 的，用 `opencode mcp auth <名字>` 登录。

## Skills

第 26 课实验里，系统提示末尾的 `<available_skills>` 列出了一些 skill。如果你装过 Claude Code 的 skills，会发现它们也在里面。原因在 `skill/index.ts`：

```typescript
const CLAUDE_EXTERNAL_DIR = ".claude"
const AGENTS_EXTERNAL_DIR = ".agents"
const EXTERNAL_SKILL_PATTERN = "skills/**/SKILL.md"
const OPENCODE_SKILL_PATTERN = "{skill,skills}/**/SKILL.md"
```

opencode 依次扫描：

1. `~/.claude/skills/` 和 `~/.agents/skills/`（全局）；
2. 从当前目录向上到仓库根目录，每一级的 `.claude/skills/` 和 `.agents/skills/`（项目）；
3. 各个配置目录（`~/.config/opencode/`、`.opencode/`）下的 `skill/` 或 `skills/`；
4. 配置里 `skills.paths` 列出的目录和 `skills.urls` 列出的地址。

也就是说，opencode **直接读取 Claude Code 的 skills 目录**，和它读取 `~/.claude/CLAUDE.md` 一样（第 26 课）。设置环境变量 `OPENCODE_DISABLE_CLAUDE_CODE=1` 可以同时关掉这两项。

skill 的工作方式和第 18 课讲的 Claude Code 一样，分两步：系统提示里只有名字、描述和路径；模型觉得需要时调用 `skill` 工具，完整的 SKILL.md 才作为工具结果进入上下文。第 26 课讲 prune 时提到“skill 工具的输出不会被清理”，原因就在这里：skill 的内容是指令，清掉了模型就不知道该怎么做了。

## 其他扩展点

- **LSP。** opencode 内置了许多语言服务器的启动配置（`lsp/server.ts`）。第 25 课讲过，编辑后的诊断默认关闭；还有一个实验性的 `lsp` 工具，让模型直接查定义、引用，要用 `OPENCODE_EXPERIMENTAL_LSP_TOOL` 打开。
- **服务端和 SDK。** 第 24 课讲过，TUI 只是一个客户端。`opencode serve` 单独启动服务端，`http://localhost:4096/doc` 是它的 OpenAPI 文档；`@opencode-ai/sdk` 提供 `createOpencodeClient`，可以用代码创建会话、发送消息、订阅事件。IDE 插件、桌面版和 GitHub 集成都是这样做的。

## 三方对照

| | MiniAgent（第 11、12 课） | opencode | Claude Code（第 18 课） |
| --- | --- | --- | --- |
| 子 agent 的定义 | Java 里的 `AgentConfig` | Markdown 文件或配置，权限规则决定工具 | Markdown 文件，`tools` 列出工具 |
| 子 agent 的上下文 | 一次性的对话 | 一个子会话，可以用 `task_id` 继续 | 独立上下文 |
| 嵌套 | 不支持 | 默认 1 层，可配置 | 子 agent 不能再开子 agent |
| 并行 | 不支持 | 一次回复里的多个 task 同时运行 | 支持 |
| 自定义命令 | 无 | Markdown 模板，支持参数和 shell 展开 | skills 和自定义命令 |
| 工具调用前后的拦截 | 代码里写死 | 插件钩子，同一进程里的函数 | hooks，外部命令 |
| 自定义工具 | 改源码 | `.opencode/tool/*.ts` | 通过 MCP |
| MCP | 无 | 本地和远程，工具名加服务端前缀 | 本地和远程，工具名加服务端前缀 |
| skills | 无 | 读自己的目录，也读 `.claude/skills` | `.claude/skills` |

## 全课总结

这门课从一个问题开始：怎样把编程 agent 用好？走了五段路：

1. **原理（第 1–5 课）。** 模型是一个按 token 预测的函数；它只知道上下文里有的东西；上下文越长，效果越容易变差。
2. **手写（第 6–12 课）。** 一个能用的编程 agent 只需要几百行 Java：一个循环、几个工具、一份系统提示、一个压缩函数、一套权限规则。
3. **实践（第 13–20 课）。** Claude Code 的每一个最佳实践，背后都是前两部分的某个原理：写清楚需求是在给模型足够的上下文，先计划后编码是在降低一次做错的代价，测试和编译器是在给它一个可靠的反馈回路，`/clear` 和 `/compact` 是在管理有限的上下文。
4. **实战（第 21–22 课）。** 在真实的 Spring Boot 项目里走完一个功能的全过程，然后算清楚收益和成本。
5. **通读（第 23–27 课）。** opencode 是一个生产级的 agent，但它的骨架就是第 8 课的那个循环。多出来的部分，大多是在处理真实世界的麻烦：几十家模型服务商、断网和限流、几小时的长会话、多个客户端、用户自己的扩展。

最后把三者放在一起看：

| | MiniAgent | opencode | Claude Code |
| --- | --- | --- | --- |
| 定位 | 教学用的最小实现 | 开源的通用 agent，支持多家模型 | 闭源的产品，为 Claude 模型优化 |
| 主循环 | 一个 `while` | 一个 `while`，外面包着流式处理、重试、中断和压缩 | 不公开，行为和前两者一致 |
| 状态 | 内存里的消息列表 | SQLite 里的会话、消息和 part | 本地 JSONL 文件 |
| 安全 | 询问加规则，可选 Docker | 默认几乎全部允许，规则可以收紧，没有沙箱 | 默认由分类器审查，可选沙箱 |
| 你能改什么 | 所有代码 | 配置、agent、命令、插件、工具，必要时改源码 | 配置、CLAUDE.md、skills、hooks、MCP |

读完 opencode，再用 Claude Code 时，你应该能对它的大多数行为给出一个具体的解释：为什么它在这里停下来问你，为什么压缩之后忘了某个约定，为什么同一个任务第二次做更便宜，为什么子 agent 回来的报告缺了细节。能解释，就能调整：改提示词、改配置、改工作方式，而不是只能重试。

## 动手

1. **改子 agent 的权限。** 把 `demo/.opencode/agent/reviewer.md` 里的 `bash: deny` 改成 `bash: { "*": "deny", "git diff*": "allow" }`，重新运行 `09-agent`，reviewer 的工具列表里有 bash 吗？把两条规则的顺序反过来再试一次。用第 25 课讲的“最后匹配的规则生效”和“整体禁止的工具对模型隐藏”解释结果。
2. **加深嵌套。** 在 `opencode.json` 里设 `"subagent_depth": 2`，再给 reviewer 的权限加上 `task: allow`。写一个剧本让 reviewer 再调用 explore，用 `db.sh` 查出三层会话的 `parent_id`。
3. **把命令改成子任务。** 给 `review.md` 的 frontmatter 加上 `subtask: true`，重新运行 `09-agent`。剧本的回复会对不上（命令现在在一个子会话里执行，那里没有 task 工具，你会看到一次无效的工具调用），这不要紧，重点看两处：用 `db.sh` 查会话表，多了一个什么样的子会话？`show.py` 输出的最后一个请求里，主会话收到的是什么？
4. **写一个插件。** 用 `tool.execute.after` 给所有 bash 输出加一行“（命令在 xx 毫秒内完成）”。提示：在 before 里按 `callID` 记下开始时间。注意处理 MCP 工具那种没有 `output` 字段的情况。
5. **扩展 MCP 服务端。** 给 `mcp-time.py` 加一个 `add` 工具，接收两个数字返回和。不用改 opencode 的任何配置，重新运行后模型能看到什么新工具？
6. **对照 Claude Code。** 在你自己的项目里，把第 18 课写的一个 Claude Code 子 agent 文件复制到 `.opencode/agent/`，把 `tools` 改写成 `permission` 规则，用 opencode 跑一次同样的任务。

## 小结

- agent 是一份配置：提示词、模型、权限、步数上限。主循环只有一个。
- task 工具开一个带 `parent_id` 的子会话，在里面跑同一个主循环，最后一段文字作为结果返回；可以用 `task_id` 继续，默认只能嵌套一层，父会话的 deny 规则会传给子会话。
- 自定义 agent 和命令都是 Markdown：frontmatter 是配置，正文是提示词或模板。命令在发给模型之前展开。
- 插件是同一进程里的钩子函数，比权限检查更早执行；自定义工具放在 `.opencode/tool/` 下。声明的钩子不一定都接上了，传进来的数据也不一定和类型一致。
- MCP 工具名带服务端前缀，服务端说明进入系统提示；skills 和 CLAUDE.md 一样，opencode 会直接读取 Claude Code 的目录。
