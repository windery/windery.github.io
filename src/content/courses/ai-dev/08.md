第 7 课的 `ToolUseDemo` 只处理一轮工具调用。可真实的编程任务从来不是一步完成的：先读代码，再改代码，然后跑测试，看到报错再改，再跑测试。每一步做什么，都取决于上一步的结果。

把第 7 课的往返放进一个循环，就得到了 agent。这一课用不到 200 行 Java 写一个能读文件、写文件、执行命令的编程 agent，再让它修一个真实的 bug。写完你会发现，Claude Code 的核心机制和它是一样的。

## agent 就是一个循环

去掉所有细节，编程 agent 的核心只有几行：

```text
历史 = [用户的任务]
循环：
    回复 = 调用模型(系统提示, 工具列表, 历史)
    历史.追加(回复)
    如果 回复里没有工具调用：
        把回复展示给用户，结束
    结果 = 逐个执行 回复里的工具调用
    历史.追加(user 消息: 结果)
```

模型决定**下一步做什么**，循环负责**执行并把结果喂回去**。“先读代码再改”“测试失败就继续修”这些行为，没有一行是写在循环里的，它们来自模型对上下文的判断，而系统提示和工具结果是这个判断的依据。

这也是为什么第一部分要花五课讲模型：循环本身很简单，agent 表现得好不好，几乎全看每一轮送进去的上下文。

## 要做的几个设计决定

循环虽然简单，真正跑起来还要回答几个问题。每一个都对应 Claude Code 里你见过的某个行为。

**1. 什么时候停。** 第 4 课的 `stop_reason` 在这里派上用场：

| stop_reason | 循环怎么处理 |
| --- | --- |
| `tool_use` | 执行工具，结果发回，继续循环 |
| `end_turn` | 任务告一段落，把控制权交还用户 |
| `max_tokens` | 回复被截断。如果截断处有工具调用，参数可能不完整，不执行，告诉模型原因并继续 |
| `pause_turn` | 服务端暂停了长任务，把历史原样再发一次即可继续 |
| `refusal` | 模型拒绝，提示用户后停止 |

此外还要有一个**步数上限**。模型可能陷入“改了又改”的死循环，每一步都在花钱。这和给重试加上限、给熔断器设阈值是一个道理。

**2. 出错了怎么办。** 分两种情况：

- **工具执行失败**（文件不存在、路径非法、用户拒绝）：作为 `is_error: true` 的 `tool_result` 回传，让模型自己调整。
- **命令执行了但结果不好**（编译失败、测试不通过）：这不是工具的错误，是正常的结果。原样返回退出码和输出，模型会读报错、改代码。**测试失败的输出，就是 agent 修 bug 的依据。**

**3. 工具结果太长怎么办。** 一次 `mvn test` 可能输出几千行。每个工具结果都会留在历史里，此后每一轮都要重新发送、重新计费（第 2 课）。这一课先用最简单的办法：超过 2 万字符就截断。第 9 课会讲更好的做法，比如只返回失败的测试和关键报错。

**4. 安全。** 模型可能请求执行任何命令。这一版先做两件事：写文件和执行命令之前，在终端里问你 `y/N`；路径不允许跳出项目目录。第 12 课会专门讲权限模式和沙箱。

## 完整代码

在第 7 课的 `mini-agent` 项目里新建 `src/main/java/demo/MiniAgent.java`：

```java
package demo;

import com.anthropic.client.AnthropicClient;
import com.anthropic.client.okhttp.AnthropicOkHttpClient;
import com.anthropic.core.JsonValue;
import com.anthropic.models.messages.ContentBlock;
import com.anthropic.models.messages.ContentBlockParam;
import com.anthropic.models.messages.Message;
import com.anthropic.models.messages.MessageCreateParams;
import com.anthropic.models.messages.StopReason;
import com.anthropic.models.messages.Tool;
import com.anthropic.models.messages.ToolResultBlockParam;
import com.anthropic.models.messages.ToolUseBlock;
import java.io.File;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.Scanner;
import java.util.concurrent.TimeUnit;

public class MiniAgent {

    static final Path ROOT = Path.of("").toAbsolutePath().normalize();
    static final int MAX_STEPS = 30;            // 一次任务最多调用模型的次数
    static final int MAX_RESULT_CHARS = 20_000; // 单个工具结果的长度上限
    static final Scanner IN = new Scanner(System.in, StandardCharsets.UTF_8);

    static final String SYSTEM = """
            你是一个编程助手，在用户的项目目录中工作。项目根目录：%s
            - 修改代码之前，先用工具阅读相关文件，不要猜测文件内容。
            - 修改之后，运行构建或测试来验证，并根据输出继续修正。
            - 完成后，用中文简要说明改了哪些文件、怎么验证的。
            """.formatted(ROOT);

    // ---------- 工具定义 ----------

    static Tool tool(String name, String description, Map<String, Object> properties, String... required) {
        Tool.InputSchema.Builder schema = Tool.InputSchema.builder().properties(JsonValue.from(properties));
        for (String r : required) schema.addRequired(r);
        return Tool.builder().name(name).description(description).inputSchema(schema.build()).build();
    }

    static final List<Tool> TOOLS = List.of(
            tool("read_file", "读取一个文本文件的完整内容。路径相对于项目根目录。",
                    Map.of("path", Map.of("type", "string")), "path"),
            tool("write_file", "用给定内容覆盖写入一个文件，文件不存在时创建。路径相对于项目根目录。",
                    Map.of("path", Map.of("type", "string"),
                           "content", Map.of("type", "string", "description", "文件的完整新内容")),
                    "path", "content"),
            tool("run_command", "在项目根目录用 bash 执行一条命令，返回退出码和输出。适合 ls、grep、mvn test 等。",
                    Map.of("command", Map.of("type", "string")), "command"));

    // ---------- 主程序：读取用户输入，每条输入跑一轮 agent 循环 ----------

    public static void main(String[] args) {
        AnthropicClient client = AnthropicOkHttpClient.fromEnv();
        MessageCreateParams.Builder conversation = MessageCreateParams.builder()
                .model("claude-opus-5-5")
                .maxTokens(16_000L)
                .system(SYSTEM);
        TOOLS.forEach(conversation::addTool);

        System.out.println("项目目录：" + ROOT + "\n输入任务，输入 exit 退出。");
        while (true) {
            System.out.print("\n> ");
            if (!IN.hasNextLine()) break;
            String task = IN.nextLine().trim();
            if (task.equals("exit")) break;
            if (task.isEmpty()) continue;
            conversation.addUserMessage(task);
            runAgentLoop(client, conversation);
        }
    }

    // ---------- agent 循环 ----------

    static void runAgentLoop(AnthropicClient client, MessageCreateParams.Builder conversation) {
        for (int step = 1; step <= MAX_STEPS; step++) {
            Message response = client.messages().create(conversation.build());
            conversation.addMessage(response); // 模型的回复原样进入历史
            StopReason reason = response.stopReason().orElse(StopReason.END_TURN);
            System.out.printf("[第 %d 步] stop_reason=%s input_tokens=%d output_tokens=%d%n",
                    step, reason, response.usage().inputTokens(), response.usage().outputTokens());

            List<ContentBlockParam> results = new ArrayList<>();
            for (ContentBlock block : response.content()) {
                block.text().ifPresent(t -> System.out.println(t.text()));
                block.toolUse().ifPresent(toolUse -> {
                    ToolResultBlockParam result = reason.equals(StopReason.MAX_TOKENS)
                            // 输出被截断时，工具参数可能不完整，不执行，告诉模型原因
                            ? error(toolUse, "未执行：回复在 max_tokens 处被截断，请把操作拆小后重试。")
                            : execute(toolUse);
                    results.add(ContentBlockParam.ofToolResult(result));
                });
            }

            if (!results.isEmpty()) {
                // 每个 tool_use 都必须有对应的 tool_result，放在下一条 user 消息里
                conversation.addUserMessageOfBlockParams(results);
                continue;
            }
            if (reason.equals(StopReason.PAUSE_TURN)) continue; // 服务端暂停：原样再发一次即可继续
            if (reason.equals(StopReason.MAX_TOKENS)) System.out.println("（回复被截断）");
            if (reason.equals(StopReason.REFUSAL)) System.out.println("（模型拒绝了这个请求）");
            return; // end_turn 等：这一轮任务结束，把控制权交还用户
        }
        System.out.println("（达到 " + MAX_STEPS + " 步上限，停止。可以输入“继续”让它接着做。）");
    }

    // ---------- 工具执行 ----------

    static ToolResultBlockParam execute(ToolUseBlock toolUse) {
        System.out.println("  → " + toolUse.name() + " " + summary(toolUse));
        try {
            String output = switch (toolUse.name()) {
                case "read_file" -> Files.readString(resolve(arg(toolUse, "path")));
                case "write_file" -> writeFile(arg(toolUse, "path"), arg(toolUse, "content"));
                case "run_command" -> runCommand(arg(toolUse, "command"));
                default -> throw new IllegalArgumentException("未知工具：" + toolUse.name());
            };
            return ToolResultBlockParam.builder().toolUseId(toolUse.id()).content(truncate(output)).build();
        } catch (Exception e) {
            // 失败不抛给调用方，而是作为 is_error 的结果回传，模型会据此调整
            return error(toolUse, e.toString());
        }
    }

    static String writeFile(String path, String content) throws Exception {
        if (!confirm("写入 " + path + "（" + content.length() + " 个字符）")) {
            throw new IllegalStateException("用户拒绝了这次写入");
        }
        Path file = resolve(path);
        if (file.getParent() != null) Files.createDirectories(file.getParent());
        Files.writeString(file, content);
        return "已写入 " + path;
    }

    static String runCommand(String command) throws Exception {
        if (!confirm("执行 " + command)) {
            throw new IllegalStateException("用户拒绝执行这条命令");
        }
        File log = File.createTempFile("agent", ".log");
        Process process = new ProcessBuilder("bash", "-c", command)
                .directory(ROOT.toFile())
                .redirectErrorStream(true)
                .redirectOutput(log)
                .start();
        boolean finished = process.waitFor(120, TimeUnit.SECONDS);
        if (!finished) process.destroyForcibly();
        String output = Files.readString(log.toPath());
        log.delete();
        return (finished ? "exit code: " + process.exitValue() : "超时（120 秒），已终止") + "\n" + output;
    }

    // ---------- 辅助方法 ----------

    static Path resolve(String path) {
        Path p = ROOT.resolve(path).normalize();
        if (!p.startsWith(ROOT)) throw new IllegalArgumentException("不允许访问项目目录之外的路径：" + path);
        return p;
    }

    static String arg(ToolUseBlock toolUse, String name) {
        Map<?, ?> input = toolUse._input().convert(Map.class);
        Object value = input.get(name);
        if (value == null) throw new IllegalArgumentException("缺少参数：" + name);
        return value.toString();
    }

    static String summary(ToolUseBlock toolUse) {
        return toolUse.name().equals("write_file") ? arg(toolUse, "path") : toolUse._input().toString();
    }

    static boolean confirm(String action) {
        System.out.print("  允许" + action + "？[y/N] ");
        return IN.hasNextLine() && IN.nextLine().trim().equalsIgnoreCase("y");
    }

    static String truncate(String s) {
        if (s.length() <= MAX_RESULT_CHARS) return s;
        return s.substring(0, MAX_RESULT_CHARS) + "\n……（输出过长，已截断，共 " + s.length() + " 个字符）";
    }

    static ToolResultBlockParam error(ToolUseBlock toolUse, String message) {
        return ToolResultBlockParam.builder().toolUseId(toolUse.id()).content(message).isError(true).build();
    }
}
```

对照前面的伪代码读 `runAgentLoop`，几处细节：

- **`conversation` 是一个一直在增长的 builder。** 用户的每条输入、模型的每次回复、每批工具结果都追加进去，每次 `build()` 得到一份完整的请求。这就是“历史”。
- **对话跨任务保留。** 一个任务结束后，你在 `>` 后面继续输入，模型能看到之前做过的所有事。所以可以说“再加一个测试用例”，它知道指的是哪里。代价是历史越来越长，第 10、17 课会讲怎么管理。
- **`run_command` 返回退出码。** 模型要靠它判断命令是否成功，所以退出码和输出放在一起返回。
- **每一步打印 `input_tokens`。** 运行时注意这个数字：它几乎每一步都在增长，因为每一轮都要重新发送全部历史。

`run_command` 用 `bash -c` 执行命令，macOS 和 Linux 可以直接运行；Windows 上请在 WSL 或 Git Bash 里使用。

## 动手：让它修一个 bug

准备一个练习目录，里面放一个有 bug 的类。它的 `main` 方法会检查三个用例，全部通过时打印 `ALL PASSED`：

```sh
mkdir -p ~/agent-lab && cd ~/agent-lab

cat > PriceCalculator.java <<'JAVA'
public class PriceCalculator {

    // 规则：订单满 100 元（含 100）减 20；会员在此基础上打九折；结果四舍五入保留两位小数
    static double finalPrice(double total, boolean member) {
        double price = total;
        if (total > 100) price -= 20;
        if (member) price = price * 0.9;
        return Math.round(price * 100) / 100;
    }

    public static void main(String[] args) {
        check(finalPrice(100, false), 80.0);
        check(finalPrice(150, true), 117.0);
        check(finalPrice(59.9, true), 53.91);
        System.out.println("ALL PASSED");
    }

    static void check(double actual, double expected) {
        if (Math.abs(actual - expected) > 1e-9) {
            throw new AssertionError("expected " + expected + " but was " + actual);
        }
    }
}
JAVA

java PriceCalculator.java    # Java 11+ 可以直接运行单个源文件
```

你会看到 `expected 80.0 but was 100.0`。这里有两个 bug，修好第一个之后，第二个才会暴露出来。

在练习目录里启动 agent。`-f` 指向 `mini-agent` 的 pom，而当前目录仍是 `~/agent-lab`，agent 会把它当作项目根目录：

```sh
cd ~/agent-lab
mvn -q -f ~/mini-agent/pom.xml compile exec:java -Dexec.mainClass=demo.MiniAgent
```

（`~/mini-agent` 换成你在第 7 课创建项目的路径。）然后输入任务：

```text
> 运行 java PriceCalculator.java，修复代码里的 bug，直到输出 ALL PASSED。不要修改 main 和 check 方法。
```

每次它要执行命令或写文件时，看清楚再按 `y`。一次典型的运行大致是这样（下面的 token 数只是示意，每次的具体步骤也会不同）：

```text
[第 1 步] stop_reason=tool_use input_tokens=1630 output_tokens=210
  → run_command {command=java PriceCalculator.java}
  允许执行 java PriceCalculator.java？[y/N] y
[第 2 步] stop_reason=tool_use input_tokens=1950 output_tokens=180
  → read_file {path=PriceCalculator.java}
[第 3 步] stop_reason=tool_use input_tokens=2420 output_tokens=900
  → write_file PriceCalculator.java
  允许写入 PriceCalculator.java（712 个字符）？[y/N] y
[第 4 步] stop_reason=tool_use input_tokens=3480 output_tokens=120
  → run_command {command=java PriceCalculator.java}
  ……
[第 6 步] stop_reason=end_turn input_tokens=4800 output_tokens=260
修复了两处问题：……
```

运行结束后，自己再跑一次 `java PriceCalculator.java` 确认结果，再用 `git diff` 或直接打开文件看它改了什么。这就是第 3 课说的：不要只听 agent 说“已完成”。

## 观察与实验

跑通之后，做几个实验，每个都对应后面课程的一个主题：

1. **拒绝一次。** 第一次要求执行命令时按 `n`。模型收到“用户拒绝执行这条命令”的错误结果后会怎么做？它可能换一种方式，也可能停下来问你。这就是 Claude Code 里你拒绝权限请求后看到的行为。
2. **看 token 增长。** 记下每一步的 `input_tokens`，算一算整个任务总共发送了多少输入 token。对照第 2 课的价格表，估算这次修 bug 花了多少钱。
3. **改掉系统提示里的一句话。** 删掉“修改之后，运行构建或测试来验证”，换一个新的 bug 再试。模型是否还会主动验证？多试几次，你会对“系统提示决定 agent 的工作习惯”有直观的感受。
4. **给一个模糊的任务。** 输入“优化一下这个类”。看它改了什么、改了多少、你是否同意。第 14 课讲需求怎么写时，会回到这个例子。

## 小结

- agent 的核心是一个循环：调用模型，执行它请求的工具，把结果发回，直到它不再请求工具。
- 模型决定下一步，循环只负责执行。agent 的“工作习惯”来自系统提示和上下文。
- 根据 `stop_reason` 决定继续还是停止，并设置步数上限防止失控。
- 工具失败用 `is_error` 回传；命令执行失败（比如测试不通过）是正常结果，原样返回退出码和输出。
- 历史每一步都在增长，工具结果越长，后续每一轮越贵。

## 动手练习

1. 完成“让它修一个 bug”，保存终端输出。数一数它用了几步、调用了哪些工具，以及总的输入 token。
2. 完成“观察与实验”中的四个实验，各记一句你的观察。
3. 给 `MiniAgent` 增加一个命令：输入 `/tokens` 时，打印到目前为止所有请求的输入和输出 token 总数（提示：在 `runAgentLoop` 里累加 `usage()`）。
4. 把步数上限改成 3，再让它修同一个 bug，观察它停在了哪里。然后输入“继续”，看它能否接着完成。想一想：它为什么知道从哪里接着做？
