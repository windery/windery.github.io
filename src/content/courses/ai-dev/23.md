第五部分要通读 opencode 的源码。opencode 是一个开源的编程 agent，功能和 Claude Code 很接近，用 TypeScript 写成，运行在 Bun 上。读它的源码，能把第二部分手写的 MiniAgent、Claude Code 和一个真实的开源实现放在一起对照。

这一课的目标很明确：**读懂**，而不是**会写**。TypeScript 的很多特性你都不会在这里学到，只讲 opencode 源码里反复出现、Java 程序员第一次看会卡住的那些写法。其中最需要专门讲的是 Effect，opencode 的核心代码几乎都用它写成，不了解它的基本写法，读起来会很吃力。

需要三样东西：Bun、opencode 的源码，以及这一课的示例。


## Java 和 TypeScript 的对照

先看一张对照表，后面逐项展开：

| Java | TypeScript | 说明 |
| --- | --- | --- |
| `class`、`record` | `interface`、`type` | TypeScript 的类型只在编译期存在，运行时就是普通的 JavaScript 对象 |
| `enum Status { A, B }` | `type Status = "a" \| "b"` | 字符串字面量联合，opencode 几乎不用 enum |
| `sealed interface` + `record` | 可辨识联合 | 用一个 `type` 字段区分成员，`switch` 之后自动收窄类型 |
| `Optional<T>` | `T \| undefined`、`?.`、`??` | 可能为空的值直接写在类型里 |
| `Map<String, Object>` | `Record<string, unknown>` | `unknown` 是“不知道什么类型，用之前必须检查” |
| `CompletableFuture<T>` | `Promise<T>` | 配合 `async` / `await` 使用 |
| `Flux<T>`（Reactor） | `AsyncIterable<T>`、Effect 的 `Stream` | 一个一个地产生值 |
| `@Service` + 构造器注入 | Effect 的 `Context.Service` + `Layer` | 本课后半部分专门讲 |
| `package` | 文件即模块，`import` / `export` | 没有包的概念，每个文件就是一个模块 |

## 类型：interface、联合类型与收窄

运行 `bun 01-types.ts`，对照代码看输出。下面是其中最重要的几段。

**interface 和字面量联合。** interface 描述一个对象有哪些字段，`?` 表示字段可能不存在。`"pending" | "in_progress" | "completed"` 是一个类型，它只允许这三个字符串，作用和 Java 的 enum 一样：

```typescript
interface Todo {
  content: string
  status: "pending" | "in_progress" | "completed"
  priority?: number
}
```

**可辨识联合。** 这是 opencode 里最常见的模式。一条消息由多个“部分”（part）组成：文本、工具调用、一步结束……每种部分都有一个 `type` 字段，值各不相同：

```typescript
type Part =
  | { type: "text"; text: string }
  | { type: "tool"; tool: string; input: Record<string, unknown> }
  | { type: "step-finish"; reason: string; tokens: number }

function describe(part: Part): string {
  switch (part.type) {
    case "text":
      return `文本：${part.text}`
    case "tool":
      return `调用工具 ${part.tool}，参数 ${JSON.stringify(part.input)}`
    case "step-finish":
      return `一步结束，原因 ${part.reason}，用了 ${part.tokens} token`
  }
}
```

在 `case "text"` 里，编译器知道 `part` 一定是第一种，所以可以访问 `part.text`；在 `case "tool"` 里则可以访问 `part.tool`。这叫**类型收窄**，效果相当于 Java 21 对 sealed interface 做模式匹配的 switch。

第 24 课会看到，opencode 处理模型的流式输出，就是一个对事件类型的大 `switch`：`text-delta`、`tool-call`、`tool-result`、`finish-step`……

**类型守卫。** filter 之后数组的类型不会自动收窄，所以会看到这样的写法，返回类型 `p is X` 告诉编译器“返回 true 时 p 就是 X”：

```typescript
const tools = parts.filter((p): p is Extract<Part, { type: "tool" }> => p.type === "tool")
```

**几个常见运算符。**

```typescript
todo.priority ?? "未设置"            // ??：左边是 null 或 undefined 时取右边
last?.text                           // ?.：last 为空时整个表达式是 undefined，不会抛异常
const done = { ...todo, status: "completed" as const }  // 展开：复制对象并覆盖字段
const limits = { read: 2000 } satisfies Record<string, number>  // 检查类型，但不改变推断结果
```

`as const` 让 `"completed"` 保持字面量类型，而不是被放宽成 `string`。`satisfies` 在 opencode 里经常出现在返回值后面，比如 `return { ... } satisfies Tool.DefWithoutID<...>`，意思是“检查这个对象符合工具定义的类型”。

## 异步：Promise、async/await 与异步迭代

运行 `bun 02-async.ts`。

`async` 函数返回 `Promise`，`await` 等待它完成，读法和 Java 的同步代码几乎一样：

```typescript
async function readFile(path: string): Promise<string> {
  await Bun.sleep(50)
  return `${path} 的内容`
}

const [a, b] = await Promise.all([readFile("a.txt"), readFile("b.txt")])
```

**异步迭代**是理解流式输出的关键。`async function*` 定义一个可以边产生边消费的生成器，`for await` 一个一个地取：

```typescript
async function* fakeModelStream(signal: AbortSignal): AsyncGenerator<ModelEvent> {
  for (const word of ["我", "先", "读", "一下", "文件"]) {
    if (signal.aborted) return
    await Bun.sleep(30)
    yield { type: "text-delta", text: word }
  }
  yield { type: "finish", reason: "stop" }
}

for await (const event of fakeModelStream(controller.signal)) {
  if (event.type === "text-delta") text += event.text
}
```

`AbortController` 和 `AbortSignal` 是 JavaScript 标准的取消机制。用户在 opencode 里按下 Esc，就是通过它同时取消正在进行的模型请求和工具执行。例子里 100 毫秒后取消，所以只收到了前几个词。

## 模块：import、export 与命名空间

每个 `.ts` 文件都是一个模块，`export` 的东西才能被别的文件 `import`。opencode 有一个特别的约定，运行 `bun 03-modules/main.ts` 看一下：

```typescript
// todo.ts
export interface Info { content: string; status: string }
export const create = (content: string): Info => ({ content, status: "pending" })

export * as Todo from "./todo"   // 最后一行：把整个文件作为命名空间 Todo 再导出一次
```

```typescript
// main.ts
import { Todo } from "./todo"
const item: Todo.Info = Todo.create("补测试")
```

这样使用方写出来的是 `Todo.create(...)`、`Todo.Info`，读起来像 Java 的静态方法和嵌套类型。你在 opencode 里看到的 `SessionPrompt.Service`、`MessageV2.parts(...)`、`Permission.evaluate(...)` 都是这种写法。看到 `Xxx.yyy` 时，去找文件末尾有 `export * as Xxx` 的那个文件。

另外两种 import 路径：

- `import { Todo } from "@/session/todo"`：`@/` 是 `packages/opencode/tsconfig.json` 里配置的别名，指向 `packages/opencode/src/`。
- `import { Database } from "@opencode-ai/core/database/database"`：`@opencode-ai/xxx` 是仓库里的另一个包，对应 `packages/xxx/`。opencode 是一个 monorepo，有几十个包。

## Effect：opencode 的骨架

[Effect](https://effect.website) 是一个 TypeScript 库，提供依赖注入、错误处理、重试、并发、资源管理和流处理。opencode 用的是 Effect 4 的 beta 版本（`4.0.0-beta.83`）。它的写法和普通 TypeScript 差别很大，但核心概念只有几个。运行 `bun 04-effect.ts`，对照下面的讲解。

### Effect 是一个“还没执行的计算”

```typescript
const hello = Effect.gen(function* () {
  const name = yield* Effect.succeed("opencode")
  return `hello, ${name}`
})
console.log(await Effect.runPromise(hello))
```

`Effect.gen(function* () { ... })` 里的代码不会马上执行，它只是**描述**了一段计算，`Effect.runPromise` 时才真正运行。在函数体里，**把 `yield*` 读成 `await`**：等待另一个 Effect 完成，拿到它的结果。

这是读 opencode 最重要的一条规则。你会看到大量这样的代码：

```typescript
const parts = yield* MessageV2.parts(ctx.assistantMessage.id)
const agent = yield* agents.get(ctx.assistantMessage.agent)
yield* permission.ask({ ... })
```

按 `await` 去读，就是普通的顺序代码。

`Effect.fn("名字")(function* (参数) { ... })` 定义一个函数，调用它返回一个 Effect。名字用于日志和追踪，比如 `Effect.fn("SessionPrompt.cancel")`。

### 服务与依赖注入

Java 后端熟悉的依赖注入，在 Effect 里由三部分组成：

```typescript
// 1. 接口：服务提供哪些方法
interface TodoShape {
  readonly add: (content: string) => Effect.Effect<string>
}

// 2. 标识：一个类，作为“要注入什么”的键，相当于 Spring 里 bean 的类型
class Todo extends Context.Service<Todo, TodoShape>()("@demo/Todo") {}

// 3. 实现：Layer.effect 描述怎么构造这个服务，以及它依赖什么
const todoLayer = Layer.effect(
  Todo,
  Effect.gen(function* () {
    const clock = yield* Clock          // 拿到依赖，相当于构造器注入
    const add = Effect.fn("Todo.add")(function* (content: string) {
      const now = yield* clock.now()
      return `[${now.toISOString()}] ${content}`
    })
    return Todo.of({ add })
  }),
)
```

使用时，`yield* Todo` 就能拿到服务。运行前要用 `Effect.provide(...)` 提供所有依赖，少提供一个，**编译就不通过**。这比 Spring 在启动时才报错更早发现问题。

opencode 的 `packages/opencode/src/session/todo.ts` 就是这个结构，只有 70 多行，建议现在就打开读一遍：

```typescript
export interface Interface {
  readonly update: (input: { sessionID: SessionID; todos: ReadonlyArray<Info> }) => Effect.Effect<void>
  readonly get: (sessionID: SessionID) => Effect.Effect<Info[]>
}

export class Service extends Context.Service<Service, Interface>()("@opencode/SessionTodo") {}

const layer = Layer.effect(
  Service,
  Effect.gen(function* () {
    const events = yield* EventV2Bridge.Service
    const { db } = yield* Database.Service
    const update = Effect.fn("Todo.update")(function* (input) { /* 删掉旧的，插入新的，发布事件 */ })
    const get = Effect.fn("Todo.get")(function* (sessionID) { /* 按 position 查询 */ })
    return Service.of({ update, get })
  }),
)
```

接口、标识、实现，外加文件末尾的 `export * as Todo from "./todo"`。opencode 的每个服务几乎都是这个模板。

### pipe：重试、捕获、清理

Java 里用 try/catch/finally 和装饰器做的事，Effect 用 `.pipe(...)` 把一个个“包装”串起来：

```typescript
const withRetry = flaky.pipe(
  Effect.retry(Schedule.recurs(5)),                          // 失败后最多再试 5 次
  Effect.catch((e) => Effect.succeed(`放弃：${e.message}`)), // 相当于 catch
  Effect.ensuring(Effect.sync(() => console.log("清理资源"))), // 相当于 finally
)
```

`pipe` 从上往下读：先加重试，再加错误处理，最后加清理。第 24 课的主循环里，调用模型的那段代码就是这样包装的：中断时怎么处理、按什么策略重试、出错后怎么收尾。

### Schema：类型和校验一次写完

```typescript
const ReadParams = Schema.Struct({
  filePath: Schema.String,
  offset: Schema.optional(Schema.Number),
})
type ReadParams = Schema.Schema.Type<typeof ReadParams>
```

`Schema.Struct` 定义的结构，既能推出 TypeScript 类型，又能在运行时校验数据，还能转换成 JSON Schema。opencode 的工具参数就是这样定义的：同一份定义，既用来校验模型传来的参数，又转成 JSON Schema 发给模型（第 7 课讲过工具定义里的 `input_schema`）。

### Stream：处理流式事件

```typescript
Stream.fromIterable(events).pipe(
  Stream.tap((e) => Effect.sync(() => { /* 处理每个事件 */ })),
  Stream.runDrain,
)
```

和 Java 的 Stream 或 Reactor 类似。opencode 把模型返回的流式事件转成 Effect 的 Stream，然后对每个事件调用处理函数。

### 还会遇到的几个

- `Deferred`：只能完成一次的值，相当于 `CompletableFuture`。权限请求就是创建一个 Deferred，等用户点了“允许”再完成它。
- `Effect.runPromise(...)`、`run.promise(...)`：从 Effect 世界回到 Promise 世界的边界。opencode 用的 Vercel AI SDK 是基于 Promise 的，两边交界处会看到这些调用。
- zod：另一个校验库，opencode 只在插件接口上用它，内置代码用 Effect Schema。

## 动手：读一个真实的工具

用学到的东西读 `packages/opencode/src/tool/todo.ts`，它定义了 `todowrite` 工具（第 11 课 MiniAgent 的 `todo_write` 的对应物）：

```typescript
export const Parameters = Schema.Struct({
  todos: Schema.mutable(Schema.Array(Todo.Info)).annotate({ description: "The updated todo list" }),
})

export const TodoWriteTool = Tool.define<typeof Parameters, Metadata, Todo.Service>(
  "todowrite",
  Effect.gen(function* () {
    const todo = yield* Todo.Service

    return {
      description: DESCRIPTION_WRITE,
      parameters: Parameters,
      execute: (params: Schema.Schema.Type<typeof Parameters>, ctx: Tool.Context<Metadata>) =>
        Effect.gen(function* () {
          yield* ctx.ask({ permission: "todowrite", patterns: ["*"], always: ["*"], metadata: {} })
          yield* todo.update({ sessionID: ctx.sessionID, todos: params.todos })
          return {
            title: `${params.todos.filter((x) => x.status !== "completed").length} todos`,
            output: JSON.stringify(params.todos, null, 2),
            metadata: { todos: params.todos },
          }
        }),
    } satisfies Tool.DefWithoutID<typeof Parameters, Metadata>
  }),
)
```

试着回答：

1. 工具的参数是什么？对应的 JSON Schema 大概长什么样？
2. `description` 来自哪里？（看文件开头的 `import DESCRIPTION_WRITE from "./todowrite.txt"`，工具的长描述是单独的文本文件。）
3. 执行时先做了什么，再做了什么，最后返回给模型的 `output` 是什么？
4. `yield* Todo.Service` 拿到的是什么？它的实现在哪个文件？

答案：参数是一个待办数组；执行时先通过 `ctx.ask` 检查权限，再调用上面读过的 `Todo` 服务写入数据库，返回给模型的是整个列表的 JSON；`Todo.Service` 的实现就是 `session/todo.ts` 里的 `layer`。和 MiniAgent 的 `todo_write` 相比，结构几乎一样，多出来的是权限检查和持久化。

## 小结

- 读 opencode 只需要一小部分 TypeScript：interface、字面量联合、可辨识联合和类型收窄、`?.` 和 `??`、async/await 和 `for await`、模块和 `export * as`。
- 可辨识联合加 `switch` 是 opencode 处理消息和事件的基本模式。
- Effect 的关键：把 `yield*` 读成 `await`；服务由接口、`Context.Service` 标识和 `Layer` 实现组成；`pipe` 串起重试、捕获和清理；Schema 同时提供类型、校验和 JSON Schema。
- 看到 `Xxx.yyy`，去找末尾写着 `export * as Xxx` 的文件；`@/` 指向 `packages/opencode/src/`。
